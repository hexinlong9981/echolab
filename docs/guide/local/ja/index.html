はじめにローカル(local)実(じっ)行(こう)3 つのルート(route)

トップ(top)・動(うご)かし方(かた)を選(えら)ぶ

EchoLab を自(じ)分(ぶん)のパソコン(PC)で動(うご)かします。コード(code)を取(しゅ)得(とく)して Python の環(かん)境(きょう)を用(よう)意(い)したら、手(て)元(もと)の条(じょう)件(けん)（JDK 21 があるか、Anthropic の API キー(key)があるか）に応(おう)じてルート(route)を 1 つ選(えら)びます。いちばん短(みじか)いルート(route)なら Python だけで済(す)み、数(すう)分(ふん)で出(しゅっ)典(てん)つきの最(さい)初(しょ)の回(かい)答(とう)を確(たし)かめられます。

「ローカル(local)で動(うご)かす」とは

EchoLab には、デプロイ(deploy)が必(ひつ)要(よう)なサーバー(server)はありません。「ローカル(local)で動(うご)かす」とは、リポジトリ(repository)のルート(root)でコマンド(command) python -m core.agent "質問" を実(じっ)行(こう)することです。このプロセス(process)があなたのパソコン(PC)の上(うえ)で「LLM が呼(よ)ぶツール(tool)を決(き)める → ツール(tool)が計(けい)算(さん)する → 検(けん)証(しょう)器(き)が下(した)書(が)きを照(しょう)合(ごう)する → レンダラ(renderer)が数(すう)字(じ)を埋(う)める → 回(かい)答(とう)と出(しゅっ)典(てん)の表(ひょう)を表(ひょう)示(じ)する」までを順(じゅん)に行(おこな)い、実(じっ)行(こう)トレース(trace)を手(て)元(もと)の .echolab/traces/ に書(か)き出(だ)します。

このうち 2 つの部(ぶ)分(ぶん)を差(さ)し替(か)えられ、その組(く)み合(あ)わせが 3 つのルート(route)になります。

  • LLM の部(ぶ)分(ぶん)：あらかじめ用(よう)意(い)した台(だい)本(ほん)（--llm scripted --script 台本.yaml。ネット(net)接(せつ)続(ぞく)も費(ひ)用(よう)も不(ふ)要(よう)）か、実(じつ)物(ぶつ)の Claude（既(き)定(てい)の --llm anthropic）。
  • 計(けい)算(さん)の部(ぶ)分(ぶん)：テスト(test)用(よう)の Python の参(さん)照(しょう)実(じっ)装(そう)（--fake-backend。同(おな)じプロセス(process)の中(なか)で計(けい)算(さん)）か、実(じつ)物(ぶつ)の Java の計(けい)算(さん)サービス(service) calc-engine（CLI が config/services.yaml に従(したが)って子(こ)プロセス(process)として起(き)動(どう)し、MCP の stdio で通(つう)信(しん)）。

どのルート(route)を選(えら)んでも、ゲートウェイ(gateway)（ツール(tool)の許(きょ)可(か)リスト(list)、呼(よ)び出(だ)し ID と出(しゅっ)典(てん) ID の採(さい)番(ばん)）、比(ひ)較(かく)ツール(tool)、数(すう)値(ち)の検(けん)証(しょう)器(き)、レンダラ(renderer)、実(じっ)行(こう)トレース(trace)はすべて同(おな)じ本(ほん)物(もの)のコード(code)です。
