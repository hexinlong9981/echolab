OS

  • Linux：比(ひ)較(かく)的(てき)新(あたら)しいディストリビューション(distribution)であれば、どれでもかまいません。
  • macOS：コマンド(command)は Linux と同(おな)じです（「ターミナル(terminal)」で実(じっ)行(こう)します）。
  • Windows：WSL2（Windows Subsystem for Linux）を使(つか)い、このガイド(guide)の操(そう)作(さ)はすべて WSL の Linux の中(なか)で行(い)ってください。
WSL を使(つか)ったことがない方(ほう)へまず Windows で WSL を準(じゅん)備(び)する をご覧(らん)ください。WSL 2 と Ubuntu のインストール(install)から、このページ(page)に挙(あ)げた Python、Git、JDK 21 を Ubuntu の中(なか)に入(い)れるところまでを説(せつ)明(めい)しています。
Windows をお使(つか)いの方(ほう)へ：コマンド(command)はすべて WSL の中(なか)で実(じっ)行(こう)し、Windows 側(がわ)のツール(tool)と混(ま)ぜないでください WSL のターミナル(terminal)では、既(き)定(てい)で PATH に Windows のディレクトリ(directory)（/mnt/c/…）も含(ふく)まれるため、Windows 版(ばん)の python.exe や git.exe も見(み)つかってしまいます。これらは Windows のファイルシステム(file system)と改(かい)行(ぎょう)の規(き)則(そく)で動(うご)くため、このガイド(guide)のコマンド(command)とは相(あい)性(しょう)がよくありません。次(つぎ)の 3 点(てん)を守(まも)ってください。
  • Python、Git、JDK は WSL の Linux の中(なか)にインストール(install)し、コマンド(command)に .exe を付(つ)けない。
  • リポジトリ(repository)は /mnt/c/… の下(もと)ではなく、WSL のホームディレクトリ(home directory)（例(れい)：~/echolab）にクローン(clone)する。動(どう)作(さ)が速(はや)く、権(けん)限(げん)や改(かい)行(ぎょう)コード(code)の問(もん)題(だい)も起(お)きません。
  • このガイド(guide)のコマンド(command)を Windows の PowerShell や「コマンド(command) プロンプト(prompt)」で実(じっ)行(こう)しない。

Windows 側(がわ)ではなく WSL の中(なか)にいることを確(たし)かめます。

uname -sr の結(けっ)果(か)に microsoft-standard-WSL2 があれば、WSL2 の中(なか)にいます。2 つ目(め)のコマンド(command)は、Windows のプログラム(program)も PATH に載(の)っていることを示(しめ)すためのものです（ユーザー(user)名(な)は <ユーザー名> に置(お)き換(か)えています）。このガイド(guide)では .exe の付(つ)かない Linux 版(ばん)のコマンド(command)だけを使(つか)います。

Python 3.12 以(い)上(じょう)

このプロジェクト(project)は Python 3.12 を前(ぜん)提(てい)にしています（pyproject.toml の ruff の設(せっ)定(てい)が target-version = "py312"）。このガイド(guide)の出(しゅつ)力(りょく)はすべて Python 3.12.11 で実(じっ)際(さい)に実(じっ)行(こう)したものです。仮(か)想(そう)環(かん)境(きょう)を作(つく)るための標(ひょう)準(じゅん)ライブラリ(library) venv も必(ひつ)要(よう)です。

  • 2 つ目(め)の出(しゅつ)力(りょく)が False の場(ば)合(あい)：システム(system)の python3 が古(ふる)すぎます。まず別(べっ)途(と)インストール(install)された python3.12 がないか確(たし)かめ（python3.12 --version）、あれば以(い)降(こう)のコマンド(command)の python3 を python3.12 に置(お)き換(か)えてください。なければ、ディストリビューション(distribution)のパッケージマネージャー(package manager)か python.org のインストーラー(installer)で 3.12 以(い)上(じょう)を入(い)れてください。
  • 3 つ目(め)で ModuleNotFoundError が出(で)る場(ば)合(あい)：Linux のディストリビューション(distribution)によっては venv / ensurepip が別(べつ)パッケージ(package)（名(な)前(まえ)はたいてい python3.12-venv のようなもの）に分(わ)かれています。それをインストール(install)してください。

JDK 21（ルート(route) B と、ルート(route) C で Java サービス(service)を使(つか)う場(ば)合(あい)）

計(けい)算(さん)サービス(service) calc-engine は Java 21 で書(か)かれています。jar のビルド(build)には（JRE だけでなく）JDK が必(ひつ)要(よう)で、実(じっ)行(こう)時(じ)にも Java 21 が必(ひつ)要(よう)です。ディストリビューション(distribution)は何(なん)でもかまいません。ここでは Eclipse Temurin を例(れい)にします。

CLI が java を探(さが)す順(じゅん)序(じょ)は、まず PATH 上(うえ)の java、見(み)つからなければ $JAVA_HOME/bin/java です。したがって、Java を PATH に通(とお)さなくても、JAVA_HOME を設(せっ)定(てい)するだけで足(た)ります。ビルド(build)に使(つか)う ./gradlew も JAVA_HOME を読(よ)みます。

例(れい)として、Adoptium から Temurin 21 の Linux x64 用(よう)アーカイブ(archive)をダウンロード(download)して ~/.local/jdk に展(てん)開(かい)し、バージョン(version)番(ばん)号(ごう)の付(つ)かないリンク(link) ~/.local/jdk/21 を作(つく)ります（以(い)下(か)は空(そら)のホームディレクトリ(home directory)で実(じっ)際(さい)に実(じっ)行(こう)した記(き)録(ろく)です）。

確(かく)認(にん)のポイント(point)：1 行(ぎょう)目(め)が version "21.…" であること、javac も動(うご)くこと（JDK が入(はい)っている証(しょう)拠(こ)です）。export JAVA_HOME=… はいま開(ひら)いているターミナル(terminal)でしか有(ゆう)効(こう)でないので、ずっと有(ゆう)効(こう)にしたい場(ば)合(あい)はこの行(ぎょう)を ~/.bashrc（またはお使(つか)いのシェル(shell)の設(せっ)定(てい)ファイル(file)）に追(つい)加(か)してください。ディストリビューション(distribution)のパッケージマネージャー(package manager)や macOS のインストーラー(installer)で入(い)れてもかまいません。java -version が 21 と表(ひょう)示(じ)されれば大(だい)丈(じょう)夫(ぶ)です。

PATH に java がなくてもかまいませんこのガイド(guide)の環(かん)境(きょう)では、command -v java || echo "PATH に java がありません" の出(しゅつ)力(りょく)は PATH に java がありません で、JAVA_HOME だけで動(うご)かしています。逆(ぎゃく)に、PATH に古(ふる)いバージョン(version)の java（たとえば Java 8）があると CLI はそちらを優(ゆう)先(せん)し、Java 21 でビルド(build)した jar は古(ふる)い Java では動(うご)きません。その場(ば)合(あい)は JDK 21 を PATH の先(せん)頭(とう)に置(お)いてください。詳(くわ)しくは ローカル(local)実(じっ)行(こう)のトラブルシューティング(troubleshooting) をご覧(らん)ください。

Docker（任(にん)意(い)）

JDK を入(い)れたくない場(ば)合(あい)のために、README には gradle:8-jdk21 のコンテナ(container)で Java をビルド(build)・テスト(test)するコマンド(command)（services/calc-engine で ./gradlew check を実(じっ)行(こう)）が載(の)っています。具(ぐ)体(たい)的(てき)な使(つか)い方(かた)は Java の計(けい)算(さん)サービス(service)で動(うご)かす をご覧(らん)ください。

docker --version で確(たし)かめられるのはクライアント(client)だけですDocker エンジン(engine)に接(せつ)続(ぞく)できることも必(ひつ)要(よう)です。このガイド(guide)の環(かん)境(きょう)では、現(げん)在(ざい)のユーザー(user)にアクセス(access)権(けん)がないとき、docker version が permission denied while trying to connect to the docker API at unix:///var/run/docker.sock と出(しゅつ)力(りょく)しました。その場(ば)合(あい)は、ユーザー(user)を docker グループ(group)に追(つい)加(か)する（またはお使(つか)いの Docker のインストール(install)方(ほう)法(ほう)の説(せつ)明(めい)に従(したが)う）必(ひつ)要(よう)があります。Windows で Docker Desktop を使(つか)う場(ば)合(あい)は、設(せっ)定(てい)でお使(つか)いの WSL ディストリビューション(distribution)の WSL 統(とう)合(ごう)を有(ゆう)効(こう)にしてください。

注(ちゅう)意(い)：コンテナ(container)はビルド(build)とテスト(test)にしか使(つか)いません。ルート(route) B では CLI が手(て)元(もと)のマシン(machine)で java -jar … として計(けい)算(さん)サービス(service)を起(き)動(どう)するため、Java サービス(service)を実(じっ)際(さい)に動(うご)かすときは、手(て)元(もと)にも Java 21 が必(ひつ)要(よう)です。
