使用真实 Claude 运行

不加 --llm 时，CLI 默认调用 Claude API（模型 claude-opus-5-5），由 Claude 理解你的问题、选择计算工具并组织回答。本页说明如何准备 API 密钥、费用上限如何保护你，以及哪些数据会离开你的电脑。

关于本页的输出本页的实测环境没有设置 API 密钥，所以下面只展示两种真实输出：没有凭据时，和达到费用上限时。本页不展示真实 Claude 的回答；回答的格式与台本模式相同，读法见 回答怎么读。路径缩写为 ~/echolab。

1. 获取 API 密钥

  1. 登录 Anthropic 的 Claude Console（https://platform.claude.com/，旧地址 console.anthropic.com 会跳转过来）。
  2. 在 Settings → API keys 创建一个密钥，复制以 sk-ant- 开头的字符串。密钥只显示一次。
  3. API 按用量计费，需要在 Console 的计费设置中准备额度。EchoLab 自身另有费用上限（见下文），两者独立。

2. 让 CLI 找到凭据

CLI 使用 Anthropic 官方 Python SDK，按 SDK 的默认顺序查找凭据。常用两种方式：

# 方式 A：环境变量（只对当前终端有效）
export ANTHROPIC_API_KEY=sk-ant-...（你的密钥）

# 方式 B：用 Anthropic 的 CLI 登录，SDK 会读取它保存的配置
ant auth login
不要把密钥写进仓库本仓库是公开的。.gitignore 已经忽略了 .env 和 .env.*，但 CLI 不会自动读取 .env。如果你想把密钥放在 .env 里，需要自己加载：set -a; . ./.env; set +a。提交前可以用 git status 和 git check-ignore -v .env 确认它没有被跟踪。

3. 先确认费用上限

每次调用 Claude 之前都会检查费用台账。默认值在 config/budget.yaml：

设置默认值用环境变量覆盖
每日上限 caps_usd.daily1.00 美元（UTC 换日，北京时间 8:00）ECHOLAB_DAILY_USD
每月上限 caps_usd.monthly10.00 美元（UTC 换月）ECHOLAB_MONTHLY_USD
台账 ledger.echolab/costs.jsonl（已被 Git 忽略）ECHOLAB_LEDGER
价格表 pricing_usd_per_mtokclaude-opus-5-5：输入 4.00、输出 20.00 美元／百万 token—

第一次试用时，可以先把上限调低：

export ECHOLAB_DAILY_USD=0.20
export ECHOLAB_MONTHLY_USD=2.00

只有 --llm anthropic 会写入真实台账；台本模式只使用每次运行专用的临时台账。费用的计算方式和台账的每行格式见 成本上限与数据可信度。

4. 提问

在仓库根目录、激活虚拟环境后运行（不写 --llm 即为 anthropic）。默认会启动 Java 计算服务，需要先完成 第 4 页；暂时没有 Java 时可加 --fake-backend，但那样无法回答需要引用示例数据的问题。

export JAVA_HOME=$HOME/.local/jdk/21
python -m core.agent "攻撃力 2000、スキル倍率 2.5、ダメージバフ 0.3、会心率 0.6、会心ダメージ 2.2、防御定数 1600、敵の防御 1000、防御無視 0、敵の耐性 0.1、耐性ダウン 0 のときの期待ダメージは？"

以下是没有设置凭据时运行这条命令的真实输出：

  • 回答的意思是：找不到 Claude API 的认证信息，无法回答；请设置 ANTHROPIC_API_KEY（或 ant auth login），或使用不需要密钥的台本模式。
  • 状态 llm_error，退出码 1，费用 0。没有发生 API 调用，所以台账 costs.jsonl 也没有被创建（.echolab/ 下只有 traces）。
  • 8 秒左右的耗时主要是 Java 服务的启动：网关先打开，然后才轮到 Claude 调用。
  • 凭据无效、限流、网络错误等其他 llm_error 的区分方法见 故障排除与 FAQ 的 ③。

设置好凭据后，同一条命令会输出 Claude 的回答、出典表和状态行 状態: answered … 費用: $…，费用同时追加到 .echolab/costs.jsonl。

5. 达到上限时会怎样

费用检查发生在调用 Claude 之前，也在使用凭据之前（core/agent/loop.py 的 _call_llm 先执行 budget.check()）。所以可以在不花钱、也不需要密钥的情况下复现：把每日上限设为 0，并把台账指向一个临时文件，以免碰到真实台账。

  • 即使没有凭据，结果也是 budget_exceeded 而不是 llm_error：上限检查在前，Claude 根本没有被调用。轨迹里没有 llm_call 或 llm_error 事件。
  • 回答说明了是哪一个上限（今日＝日次）、已用额／上限、何时恢复，以及修改方法。把 ECHOLAB_MONTHLY_USD=0 时，回答换成「今月（UTC）のコストが月次の上限に達したため…」。
  • 临时台账文件没有被创建：没有发生调用，就没有要记的账。
  • 如果在一次提问的中途达到上限（例如工具调用之后的第二次 Claude 调用前），同样以 budget_exceeded 结束，已经产生的费用会如实记入台账。

问题原文会原样发送，也会原样写入本机轨迹。不要在问题里写与计算无关的个人信息。数据流向图见 成本上限与数据可信度。

安全使用的小建议

密钥只放在环境里

用 export 或 ant auth login，不要写进代码、配置文件或命令历史会被分享的脚本里。

先用台本模式

环境、Java 服务都确认无误后，再切换到真实 Claude，避免为排查环境问题付费。

上限先调低

首次试用把 ECHOLAB_DAILY_USD 设成较小的值，熟悉后再恢复默认。

分享轨迹前先检查

轨迹包含问题原文和每一版草稿。.echolab/ 已被 Git 忽略，不会被意外提交。

密钥泄露时

立即在 Console 中删除该密钥并创建新的；仅仅从文件里删掉是不够的。
