运行JDK 21calc-engine

使用 Java 计算服务运行

去掉 --fake-backend，让 CLI 启动真正的计算服务 calc-engine（Java 21 + Spring Boot 的 MCP 服务器）。本页依次介绍：安装 JDK 21、构建 jar、CLI 如何启动服务、运行示例，以及只有 Java 服务才支持的「数据引用」。

关于本页的输出本页所有命令和输出都是在一份全新克隆的仓库上实际运行得到的（Linux／WSL2，Python 3.12，Temurin 21）。为便于阅读，仓库所在的长路径统一缩写为 ~/echolab，用户名替换为 user，较长的输出用「…」省略了中间部分。耗时因机器和网络而异，仅供参考。

台本模式的两种计算后端

在 用脚本模式运行 中，我们加了 --fake-backend：计算由 Python 的参照实现（tests/core/fakes.py）完成，不需要 Java。去掉它之后，CLI 会按 config/services.yaml 启动 Java 计算服务。两者对同一问题给出的数值相同，区别如下：

--fake-backend（Python 参照实现）不加（Java 计算服务）
需要什么只要 Python 环境JDK 21 + 构建好的 jar
自带示例的耗时（实测）约 3.2 秒约 8.5 秒（多出的时间主要是 JVM 和 Spring 的启动）
数据引用（banner／profile）不支持，工具报错支持，并自动加「未確認」注记
用途演示、单元测试、台本模式的评估真实使用、端到端测试（pytest -m e2e）

1. 安装 JDK 21

任何 JDK 21 发行版都可以。下面以 Eclipse Temurin 为例，用压缩包安装到用户目录，不需要 root 权限（x64 Linux／WSL2；其他平台请在 Adoptium 网站选择对应的包，macOS 也可以用 Homebrew 安装 temurin@21）。

mkdir -p ~/.local/jdk
curl -L -o /tmp/temurin21.tar.gz \
  https://api.adoptium.net/v3/binary/latest/21/ga/linux/x64/jdk/hotspot/normal/eclipse
tar -xzf /tmp/temurin21.tar.gz -C ~/.local/jdk        # 解压出 jdk-21.0.12.1+1 这样的目录（版本号会变）
ln -sfn ~/.local/jdk/jdk-21.0.12.1+1 ~/.local/jdk/21  # 固定一个不带版本号的路径，方便升级
echo 'export JAVA_HOME=$HOME/.local/jdk/21' >> ~/.bashrc
export JAVA_HOME=$HOME/.local/jdk/21

下载的压缩包约 198 MB。写进 ~/.bashrc 后，新开的终端会自动设置 JAVA_HOME。

不必把 java 放进 PATHCLI 启动服务前会查找 java：PATH 上有就用 PATH 上的；PATH 上没有、但设置了 JAVA_HOME，就改用 $JAVA_HOME/bin/java（见 core/gateway/mcp_backend.py 的 resolve_executable）。Gradle Wrapper 同样读取 JAVA_HOME。所以只设置 JAVA_HOME 就够了。
注意顺序只有当 PATH 上找不到 java 时，CLI 才会使用 JAVA_HOME。如果 PATH 上已经有一个旧版本的 java（例如 Java 8 或 17），CLI 会用它，服务启动失败。这时把 JDK 21 放到 PATH 最前面：export PATH="$JAVA_HOME/bin:$PATH"。实际的报错见 本地运行的故障排除。

2. 构建 jar

在仓库根目录下进入 services/calc-engine，用自带的 Gradle Wrapper 构建可执行 jar。第一次运行会下载 Gradle 本体（8.14.3）和所有依赖库，需要联网，实测约 2 分钟；之后只需几秒。

  • 产物是 services/calc-engine/build/libs/calc-engine-mcp.jar（约 24 MB，包含 Spring Boot 和所有依赖）。config/services.yaml 引用的正是这个路径。
  • Gradle 本体和依赖缓存在 ~/.gradle/（可用 GRADLE_USER_HOME 改位置），不会写进仓库。build/ 已被 Git 忽略。
  • 编译时会运行 Error Prone，并启用 -Xlint:all -Werror：任何编译警告都会让构建失败。
  • 修改 Java 代码后需要重新运行 ./gradlew bootJar，CLI 不会自动重新构建。domains/wuwa/data 下的数据在运行时读取，修改数据不必重新构建。

3. CLI 如何启动计算服务

启动方式写在 config/services.yaml 里，路径都相对于仓库根目录：

schema_version: 1
services:
  calc-engine:
    transport: stdio
    command: ["java", "-jar", "services/calc-engine/build/libs/calc-engine-mcp.jar"]
    env:
      ECHOLAB_DATA_ROOT: domains

每次运行 python -m core.agent（不加 --fake-backend）时，网关会把 jar 作为子进程启动，通过标准输入／输出用 MCP 协议通信；提问结束后进程随之退出。不监听任何网络端口。

sequenceDiagram
  participant U as 你（终端）
  participant C as CLI 与网关<br/>Python
  participant J as calc-engine<br/>java -jar 子进程
  U->>C: python -m core.agent "问题" --llm scripted …
  C->>C: 读取 config/services.yaml
  C->>C: 检查 java 与 jar 是否存在<br/>缺少则以退出码 2 结束
  C->>J: 启动子进程（工作目录：仓库根目录）
  C->>J: MCP initialize（stdin／stdout）
  J-->>C: 初始化完成
  C->>J: tools/list
  J-->>C: damage_expected、echo_score、gacha_…
  loop AI 请求调用工具时
    C->>J: tools/call（每次最多等 30 秒）
    J-->>C: 结果 JSON（数值、未确认数据 ID）
  end
  C->>J: 关闭会话，进程退出
  C-->>U: 回答、出典表、状态行
图 1：一次提问中 CLI 与 Java 计算服务的交互（MCP over stdio）
  • 先检查再启动：PATH 和 JAVA_HOME 都找不到 java，或 jar 不存在时，CLI 不会启动进程，而是打印一行 エラー: …（含修复方法）并以退出码 2 结束。
  • 标准输出只用于 MCP：服务不打印启动横幅，日志只写到标准错误，因此不会混进回答。
  • 环境变量：env 里的值是默认值；如果你的 shell 里已经设置了同名环境变量，以 shell 为准。

Agent、网关、校验器之间的整体关系见 工作原理。

5. 只有 Java 服务支持的数据引用

部分工具可以不直接给出参数，而是用 ID 引用仓库自带的示例数据（domains/wuwa/data/v2.x/）。两种写法只能二选一：

工具（MCP 名）直接给出引用数据示例 ID
gacha_probability_within、gacha_simulaterulesbannerfeatured-character
echo_scoreweightsprofilesample-crit-attacker

仓库里只有一个示例台本，所以这里另写一个只有两步的小台本 my-banner.yaml（放在仓库根目录，不提交）：第 1 步用 banner 调用抽卡概率工具，第 2 步用占位符引用结果。

# 卡池数据引用的演示台本：用 banner 的 ID 代替直接给出规则
turns:
  - tool_uses:
      - name: gacha_probability_within
        input: {banner: featured-character, start_pity: 0, guaranteed: false, pulls: 80}
  - text: 80 回以内に限定キャラクターを獲得できる確率は [[c1.probability|%1]] です。
  • 示例数据标为 verified: false（未与游戏官方数据核对）。Java 服务把用到的未确认数据 ID（gacha_rules:featured-character）随结果一起返回，回答末尾自动加上注记「※ この回答の数値の一部は、未確認のサンプルデータに基づいています。」（部分数值基于未经确认的示例数据）。AI 不能省略这条注记。
  • 出典表的「未確認データ」列写明具体是哪条数据。注记的含义见 回答怎么读。

同一个台本加上 --fake-backend 会失败：Python 参照实现只接受直接给出的 rules，工具返回错误后，台本的步骤就对不上了。

工具的输入说明（JSON Schema）里列有 banner 和 profile，所以使用真实 Claude 时，它也可能选择引用示例数据；要让这类问题得到回答，需要使用 Java 服务。

6. 数据目录：ECHOLAB_DATA_ROOT

Java 服务从 $ECHOLAB_DATA_ROOT/wuwa/ 读取 domain.yaml，再按其中的 data_dir 找到数据文件。默认值是 config/services.yaml 中的 domains，相对于仓库根目录（子进程的工作目录）。想换一份数据（比如你核对过的版本）时，在 shell 里设置同名环境变量即可覆盖：

ECHOLAB_DATA_ROOT=$PWD/domains python -m core.agent "…" --llm scripted --script my-banner.yaml   # 与默认相同
ECHOLAB_DATA_ROOT=/path/to/my-data python -m core.agent "…"                                       # 目录下需要有 wuwa/domain.yaml

目录不对时服务不会停止，而是把错误作为工具结果返回（真实 Claude 会看到这条错误并据此调整）。实测用 ECHOLAB_DATA_ROOT=/tmp/echolab-nodata（不存在的目录）运行上面的台本，台本的后续步骤对不上而以 エラー: 台本どおりに進みませんでした… 结束，轨迹里记录的工具错误是：

"error": "gacha_probability_within: データファイルがありません: /tmp/echolab-nodata/wuwa/domain.yaml"

只有引用数据（banner／profile，或省略 echo_score 的 max_roll）时才会读这个目录；直接给出全部参数的计算不受影响。

另一种方式：用 Docker 构建（可选）

如果不想在本机安装 JDK，可以在官方 Gradle 镜像（内含 JDK 21）里构建和测试。以下命令取自 README，在 services/calc-engine 目录下运行：

cd services/calc-engine
docker run --rm -u "$(id -u):$(id -g)" -e GRADLE_USER_HOME=/cache \
  -v "$HOME/.gradle-echolab:/cache" -v "$(cd ../.. && pwd):/w" -w /w/services/calc-engine \
  gradle:8-jdk21 ./gradlew check
部分作用
--rm运行结束后删除容器
-u "$(id -u):$(id -g)"以你自己的用户身份运行，生成的 build/ 不会属于 root
-e GRADLE_USER_HOME=/cache 与 -v "$HOME/.gradle-echolab:/cache"把 Gradle 的下载缓存放在宿主机的 ~/.gradle-echolab，第二次起不必重新下载
-v "$(cd ../.. && pwd):/w" 与 -w /w/services/calc-engine挂载整个仓库（测试要读取 domains/wuwa 的黄金用例和数据）并在 calc-engine 目录下执行
gradle:8-jdk21 ./gradlew check运行测试和静态检查；把 check 换成 bootJar 就只构建 jar
注意Docker 只负责构建。CLI 运行时仍然在本机执行 java -jar …，所以要用 Java 服务回答问题，本机仍需要 JDK 21（构建出的 jar 可以直接使用）。本页的实测环境没有运行这条 Docker 命令；遇到 permission denied … docker.sock 时见 本地运行的故障排除。
