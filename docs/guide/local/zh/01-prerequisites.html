操作系统

  • Linux：任何较新的发行版都可以。
  • macOS：命令与 Linux 相同（在「终端」中执行）。
  • Windows：请使用 WSL2（Windows Subsystem for Linux），在 WSL 的 Linux 里完成本指南的全部操作。
从未用过 WSL？先看 在 Windows 上安装设置 WSL：从安装 WSL 2 和 Ubuntu，到在 Ubuntu 里装好本页列出的 Python、Git、JDK 21。
Windows 用户：所有命令都在 WSL 里执行，不要混用 Windows 一侧的工具 在 WSL 的终端里，PATH 默认也包含 Windows 的目录（/mnt/c/…），所以 Windows 版的 python.exe、git.exe 也能被找到。它们看到的是 Windows 的文件系统和换行规则，和本指南的命令不兼容。请做到三点：
  • Python、Git、JDK 都安装在 WSL 的 Linux 里，命令里不带 .exe。
  • 把仓库克隆到 WSL 的家目录（如 ~/echolab），而不是 /mnt/c/… 下：速度更快，也不会出现权限和换行符的问题。
  • 不要用 Windows 的 PowerShell 或「命令提示符」去执行本指南的命令。

Python 3.12 或更高

项目按 Python 3.12 设定（pyproject.toml 中 ruff 的 target-version = "py312"）。本指南的输出都是用 Python 3.12.11 实际运行得到的。还需要标准库的 venv（用来建虚拟环境）。

  • 第二条输出 False：系统的 python3 太旧。先看看有没有单独安装的 python3.12（python3.12 --version），有的话后面的命令把 python3 换成 python3.12 即可；没有就用发行版的包管理器或 python.org 的安装包装一个 3.12 以上的版本。
  • 第三条报 ModuleNotFoundError：有些 Linux 发行版把 venv / ensurepip 拆成了单独的包（名称通常类似 python3.12-venv），装上即可。

Git

只用来执行 git clone，版本没有特别要求。仓库是公开的，克隆不需要 GitHub 账号。

JDK 21（路线 B，以及路线 C 使用 Java 服务时）

计算服务 calc-engine 用 Java 21 编写，需要 JDK（不只是 JRE）来构建 jar，运行时也需要 Java 21。哪个发行版都可以，这里以 Eclipse Temurin 为例。

CLI 找 java 的顺序是：先找 PATH 上的 java，找不到就用 $JAVA_HOME/bin/java。所以不必把 Java 加入 PATH，只要设好 JAVA_HOME；构建用的 ./gradlew 也会读 JAVA_HOME。

例如：从 Adoptium 下载 Temurin 21 的 Linux x64 压缩包，解压到 ~/.local/jdk，再建一个不带版本号的链接 ~/.local/jdk/21（下面是在一个空的家目录里实际执行的记录）：

要点：第一行是 version "21.…"；javac 也能运行（说明装的是 JDK）。export JAVA_HOME=… 只对当前终端有效，想长期有效就把这一行加到 ~/.bashrc（或你所用 shell 的配置文件）里。用发行版的包管理器或 macOS 的安装包安装也可以，只要 java -version 显示 21。

PATH 上没有 java 也没关系本指南的环境里，command -v java || echo "PATH 上没有 java" 输出的就是 PATH 上没有 java，只靠 JAVA_HOME 运行。反过来，如果 PATH 上有一个旧版本的 java（例如 Java 8），CLI 会优先用它，而用 Java 21 构建的 jar 不能在旧版本的 Java 上运行；这种情况请把 JDK 21 放到 PATH 的前面。详见 本地运行的故障排除。

Docker（可选）

如果不想安装 JDK，README 提供了用 gradle:8-jdk21 容器构建和测试 Java 的命令（在 services/calc-engine 下执行 ./gradlew check）。具体用法见 使用 Java 计算服务运行。

docker --version 只检查了客户端还要能连上 Docker 引擎。本指南的环境里，当前用户没有访问权限时，docker version 会输出 permission denied while trying to connect to the docker API at unix:///var/run/docker.sock。这时需要把用户加入 docker 组（或按你的 Docker 安装方式的说明处理）。Windows 上用 Docker Desktop 时，还要在设置里为你的 WSL 发行版打开 WSL 集成。

注意：容器只用来构建和测试。路线 B 中 CLI 是在本机以 java -jar … 启动计算服务的，所以真正运行 Java 服务时，本机仍然需要 Java 21。
