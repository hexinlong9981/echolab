开始本地运行三种路线

首页・选择运行方式

在自己的电脑上把 EchoLab 跑起来：取得代码、建好 Python 环境，然后按手头的条件（有没有 JDK 21、有没有 Anthropic API 密钥）选一条路线。最短的路线只需要 Python，几分钟就能看到第一个带出典的回答。

「在本地运行」指的是什么

EchoLab 没有需要部署的服务器。所谓「本地运行」，就是在仓库根目录用命令行执行 python -m core.agent "问题"：这个进程在你的电脑上依次完成「LLM 决定调用哪些工具 → 工具计算 → 校验器核对草稿 → 渲染器填入数字 → 打印回答和出典表」，并把执行轨迹写到本机的 .echolab/traces/。

其中有两个部分可以替换，组合起来就是三条路线：

  • LLM 部分：可以是事先写好的脚本（--llm scripted --script 脚本.yaml，不联网、不花钱），也可以是真实的 Claude（默认的 --llm anthropic）。
  • 计算部分：可以是测试用的 Python 参考实现（--fake-backend，在同一个进程里计算），也可以是真实的 Java 计算服务 calc-engine（CLI 按 config/services.yaml 把它作为子进程启动，经 MCP 的 stdio 通信）。

无论选哪条路线，网关（工具许可列表、调用 ID 与出典 ID 的编号）、比较工具、数值校验器、渲染器和执行轨迹都是同一套真实代码。

建议：不管最终走哪条路线，都先跑一次路线 A路线 A 不依赖 Java 和网络（安装依赖时除外），能最快确认 Python 环境和代码本身没有问题。之后再换成 Java 或真实 Claude，出了问题也容易判断是哪一部分。

三条路线实际运行的是什么

路线LLM 部分计算部分需要适合做什么
A 脚本模式 + Python 替身脚本（YAML）按顺序返回写好的工具调用和草稿Python 参考实现（tests/core/fakes.py），同一进程内计算，不走 MCPPython 3.12+第一次体验完整流程；观察校验器「差し戻し」（退回重写）；自己写脚本做实验
B 脚本模式 + Java 服务同上calc-engine（Java 21 + Spring Boot + Spring AI）作为 MCP 服务器，CLI 以子进程启动、经 stdio 调用Python 3.12+、JDK 21（构建 jar）确认 Java 计算服务和 MCP 通信在你的机器上正常工作；对照 A 的结果
C 真实 ClaudeClaude API（模型 claude-opus-5-5），自己理解问题、决定调用哪些工具通常是 Java 服务；也可以加 --fake-backend 用 Python 替身以上 + API 密钥；会产生费用（默认上限每天 1 美元、每月 10 美元）用自己的话自由提问
脚本模式不「理解」问题路线 A、B 中，调用哪些工具、写什么草稿全都写在脚本里，与你输入的问题文字无关。换一个问题，用同一个脚本仍会得到同样的回答。能真正理解问题的只有路线 C。详见 用脚本模式运行。
