WSL 是什么，为什么要在 WSL 里运行 EchoLab

WSL（Windows Subsystem for Linux，适用于 Linux 的 Windows 子系统）让你在 Windows 上直接使用 Linux 发行版（例如 Ubuntu）及其命令行工具，不需要传统的虚拟机或双系统。WSL 2 在一个轻量级的工具虚拟机里运行真正的 Linux 内核。

EchoLab 在 Windows 上要放在 WSL 里运行，原因是：

  • 和 CI 一致：仓库的 GitHub Actions 在 ubuntu-latest 上用 Python 3.12 和 JDK 21 运行测试。在 WSL 的 Ubuntu 里运行，命令、路径和换行规则都和 CI 相同。
  • 本指南的命令都是 Linux 命令：.venv/bin/python、./gradlew、export JAVA_HOME=… 这些写法在 PowerShell 里不能直接用。
  • 只在一侧工作：工具（Git、Python、JDK）和代码都放在 Linux 里，不要和 Windows 一侧的工具混用。原因见 准备环境 中「所有命令都在 WSL 里执行」的说明。

1. 确认 Windows 的版本和虚拟化

wsl --install 要求 Windows 10 版本 2004 及以上（内部版本 19041 及以上），或 Windows 11。确认方法：按 Windows 徽标键 + R，输入 winver，点「确定」，弹出的窗口里会显示版本号和内部版本号（OS 内部版本）。也可以在「设置 → 系统 → 关于」里查看。

版本太旧时，先通过 Windows 更新升级。微软也为旧版本提供了 手动安装步骤，但本指南不做介绍。

WSL 2 还需要电脑的虚拟化功能处于开启状态。多数电脑默认已开启；如果安装或启动时出现错误 0x80370102，见下文的 常见问题。

2. 安装 WSL 和 Ubuntu

在开始菜单里找到 PowerShell（或 Windows Terminal），右键选择「以管理员身份运行」，输入：

wsl --install

PowerShell（管理员）。Windows 一侧的命令只给出命令本身，不附输出示例。

按照微软文档，这一条命令会：启用「适用于 Linux 的 Windows 子系统」和「虚拟机平台」两个可选组件；下载并安装最新的 Linux 内核；把 WSL 2 设为默认版本；下载并安装 Ubuntu 发行版。过程中需要重启电脑，请按提示重启。

想指定 Ubuntu 的版本（可选）

默认安装的发行版名为「Ubuntu」。想指定版本时，先列出可以在线安装的发行版，再用 -d 指定名称：

wsl -l -o
wsl --install -d Ubuntu-24.04

PowerShell。wsl -l -o 是 wsl --list --online 的简写；-d 后面的名称请以列表里 NAME 一栏实际显示的为准。

本页 Ubuntu 一侧的包名和输出都在 Ubuntu 24.04 上验证过。默认的「Ubuntu」对应哪个版本会随时间变化，安装后请用下文的 cat /etc/os-release 确认。

第一次启动：创建 Linux 用户

重启后，从开始菜单打开 Ubuntu（或在 Windows Terminal 中打开 Ubuntu 标签页）。第一次启动会先等待文件解压，之后要求输入新的用户名和密码。需要知道的几点（均来自微软文档）：

  • 这个用户名和密码只属于这个 Linux 发行版，与 Windows 的用户名、密码无关，可以另取。
  • 输入密码时屏幕上什么也不显示（连 * 也没有），这是正常的，输完按回车即可。
  • 这个账户会成为该发行版的默认用户，启动时自动登录；它是 Linux 的管理员，可以用 sudo 执行管理命令。之后 sudo 要求的密码就是这里设的密码。
  • 忘了密码：在 PowerShell 里执行 wsl -u root 以 root 身份进入，再用 passwd <用户名> 重设，完成后 exit。

3. 确认安装结果

在 PowerShell（不需要管理员）里执行：

wsl -l -v

PowerShell。wsl -l -v 是 wsl --list --verbose 的简写。

它会列出已安装的发行版，以及每个发行版的状态（运行中或已停止）和所用的 WSL 版本。确认 Ubuntu 那一行的 VERSION 为 2。用 wsl --install 新装的发行版默认就是 WSL 2。

如果 VERSION 显示为 1，或者想先把 WSL 本身更新到最新版本，可以使用下面的命令：

wsl --update
wsl --set-default-version 2
wsl --set-version Ubuntu 2

PowerShell。依次为：更新 WSL；把今后新装的发行版默认设为 WSL 2；把已安装的发行版（这里是名为 Ubuntu 的发行版，名称以 wsl -l -v 的显示为准）转换为 WSL 2。

微软文档提醒：在 WSL 1 和 WSL 2 之间转换可能耗时较长，也可能失败；发行版里已经有重要文件时，请先备份。刚装好的空发行版不必担心。

5. 仓库放在哪里

把仓库克隆到 Ubuntu 的家目录，例如 ~/echolab（即 /home/<用户名>/echolab），不要放在 /mnt/c/…（也就是 Windows 的 C 盘）下：

  • 速度：微软建议用 Linux 工具处理的文件就放在 WSL 的文件系统里。跨操作系统访问文件虽然可行，但可能明显变慢；安装依赖、运行测试会读写大量小文件，差别很明显。
  • 行为一致：在 /mnt/c 下，文件权限、大小写敏感性等都遵循 Windows 文件系统的规则，和 CI 的 Linux 环境不一样。

克隆的具体命令见 安装与设置。克隆前先 cd ~ 回到家目录即可。

从 Windows 一侧查看文件

  • 在 Ubuntu 终端里进入某个目录后执行 explorer.exe .（注意末尾的点），会用 Windows 的文件资源管理器打开当前目录。
  • 在文件资源管理器的地址栏输入 \\wsl$，可以看到所有已安装的发行版及其文件；家目录位于 \\wsl$\<发行版名>\home\<用户名>。
  • 想用 VS Code 编辑：安装 VS Code 的 WSL 扩展 后，在 Ubuntu 终端的仓库目录里执行 code .，VS Code 会连接到 WSL，在 Linux 一侧编辑和运行。详见微软的 在 WSL 中使用 VS Code。这一步是可选的。
查看可以，运行请留在 Ubuntu 里从 Windows 一侧打开、浏览文件没有问题；但 Python、Git、Java 这些命令请都在 Ubuntu 的终端里执行，不要对 \\wsl$ 下的仓库使用 Windows 版的 Git 或 Python。

6. 在 WSL 里设置 Git

只是 git clone 公开仓库、在本地运行 EchoLab 的话，不需要任何 Git 设置，也不需要 GitHub 账号。想在本地提交（commit）时，先在 Ubuntu 里设置姓名和邮箱：

git config --global user.name "你的名字"
git config --global user.email "you@example.com"

Ubuntu 终端。这些设置保存在 Ubuntu 的 ~/.gitconfig 中，与 Windows 一侧的 Git 设置互不相干。

想推送（push）到自己在 GitHub 上的仓库时，需要认证。GitHub 不接受账户密码用于 HTTPS 方式的 Git 操作，可以选择：

  • 在 Ubuntu 里安装 GitHub CLI（gh），执行 gh auth login 按提示登录；
  • 或使用 个人访问令牌（personal access token） 代替密码；
  • 或配置 SSH 密钥。

无论哪种方式，都在 Ubuntu 里完成设置，Git 命令也只在 Ubuntu 里执行。

7. 常见问题

现象原因处理方法
安装或启动时出现错误 0x80370102（「The virtual machine could not be started because a required feature is not installed.」）电脑的虚拟化功能未开启，或「虚拟机平台」功能未启用按电脑厂商的说明，在 BIOS（UEFI）设置中开启虚拟化（通常在 CPU 相关的选项里），并确认「虚拟机平台」已启用。参见微软的 在 Windows 上启用虚拟化。另外，WSL 2 要求 CPU 支持 SLAT，很旧的 CPU 无法运行 WSL 2
wsl --install 无法使用Windows 版本太旧（低于 Windows 10 版本 2004 / 内部版本 19041）用 winver 确认版本，通过 Windows 更新升级后再安装
执行 wsl --install 只显示了 WSL 的帮助文字WSL 已经装过了（这条命令只在完全没有安装 WSL 时可用）先 wsl --list --online 查看可用的发行版，再 wsl --install -d Ubuntu（或列表中的其他名称）只安装发行版
安装依赖、运行测试特别慢仓库放在 /mnt/c/… 下，每次读写文件都要跨越 Windows 和 Linux 的边界在 Ubuntu 的家目录里重新克隆（cd ~ 后 git clone），在新位置重建 .venv
运行脚本时报 cannot execute: required file not found，或出现 $'\r': command not found文件的换行符是 Windows 的 CRLF（例如用 Windows 版 Git 克隆，或用把换行改成 CRLF 的编辑器保存过）在 Ubuntu 里用 Linux 版的 Git 重新克隆。仓库的 .gitattributes 已指定 eol=lf；另外可以在 Ubuntu 里执行 git config --global core.autocrlf input，让提交时把 CRLF 转为 LF。参见微软的 在 WSL 上开始使用 Git 中关于换行符的说明
java: command not found，但 java.exe -version 能运行；或者习惯性地用了 python.exe工具只装在了 Windows 一侧。WSL 可以运行 Windows 程序（需带 .exe），但那是 Windows 版，看到的是 Windows 的环境按上文第 4 节在 Ubuntu 里 apt install。确认 which java python3 git 显示的都是 /usr/… 下的路径，而不是 /mnt/c/…；命令里不要带 .exe
sudo 要密码，但想不起来了Linux 用户的密码与 Windows 的密码无关在 PowerShell 里 wsl -u root，再 passwd <用户名> 重设

换行符那一行的两条错误信息，是在 Ubuntu 24.04 中执行 CRLF 换行的脚本时实际得到的（前者在第一行 #! 带有 CR 时出现，后者在脚本中有空行时出现）；不同的脚本内容和 shell 版本，报错的文字可能不同。EchoLab 本身运行时的问题见 本地运行的故障排除。
