运行测试与评估

在本机运行与 CI 相同的检查：Python 的代码规范与单元测试、使用 jar 的端到端测试、Java 的测试与静态检查，以及数值忠实度评估。全部不需要 API 密钥。

关于本页的输出以下输出和耗时都来自一份全新克隆的仓库上的实际运行（WSL2，Python 3.12，Temurin 21）。路径缩写为 ~/echolab，较长的输出用「…」省略。除特别说明外，命令都在仓库根目录、已激活虚拟环境（source .venv/bin/activate）的状态下执行。

一览：命令 → 检查什么 → 需要什么 → 大约耗时

命令检查什么需要什么实测耗时

耗时是同一台机器上的一次实测，会因机器和缓存状态而变化。

1. 代码规范：ruff

规则在 pyproject.toml 的 [tool.ruff]（行宽 100，目标 Python 3.12）。ruff format .（不带 --check）会直接改写文件；CI 只用 --check，有未格式化的文件就失败。

2. Python 测试（不含端到端）

  • 不启动 Java，也不调用 Claude：LLM 用台本或 SDK 客户端的替身，计算服务用 Python 参照实现（与 --fake-backend 相同）。
  • 5 deselected 是被 -m "not e2e" 排除的端到端测试。
  • 其中 tests/core/test_evals.py 会跑一遍台本模式的评估，并要求结果与已提交的 evals/reports/scripted-baseline.md 一致。
  • 各测试文件的内容见仓库的 tests/README.zh-CN.md。

4. Java：./gradlew check

在 services/calc-engine 目录下运行。与 bootJar 一样，第一次运行会下载 Gradle 和依赖。

包含的检查内容本次实测
测试（test）JUnit 5 单元测试、jqwik 性质测试、ArchUnit 架构测试；黄金用例与 Python 参照实现共用 domains/wuwa/golden12 个测试类、138 项，全部通过

5. 评估：数值忠实度

评估用 8 个固定用例（evals/faithfulness/cases.yaml）检查「回答里有没有来历不明的数字」。台本模式不需要密钥，运行几秒：

  • 报告同时输出到屏幕和 --out 指定的文件（Markdown）。每个用例的原始记录保存在 evals/reports/raw/（已被 Git 忽略）。
  • 指标：忠实度 1.000 表示没有任何回答包含无出处的数字；差し戻し率 0.462 是因为部分用例故意写出不合格的草稿，以确认校验器会退回。
  • 台本模式的「費用」是根据台本里写的虚构用量算出的，只用于检查计费逻辑，不是真实花费。
  • 实测输出除日期行外，与已提交的 evals/reports/scripted-baseline.md 完全一致。
用真实 Claude 运行评估（会产生费用）

需要 API 密钥和 Java 服务（见 第 5 页）。每个用例都会调用 Claude，并受同样的日／月上限约束。

6. 网页界面（可选）：在浏览器里看回放

需要 Node.js（建议 22 以上）。不需要 API 密钥、Java 或 Tesseract：

python -m servers.web_api.export                 # 剧本模式运行全部演示与评估 → web/public/data/
(cd web && npm ci && npm run build)              # 构建网页 → web/dist/（需要 Node.js）
python -m servers.web_api                        # 只监听 127.0.0.1 → http://127.0.0.1:8765/

浏览器打开 http://127.0.0.1:8765/，有「回放」「评估」「运行（本机）」三个标签页。开发时可以用 (cd web && npm run dev)；前端的检查是 (cd web && npm run typecheck && npm test)。

CI 如何运行同样的检查

GitHub Actions 的工作流在 .github/workflows/，CI 不持有 API 密钥，LLM 全部用台本替代：

工作流・作业触发执行的命令
test.yml ・ python推送到 main、每个 PRruff check . → ruff format --check . → pytest -m "not e2e"（Python 3.12）
test.yml ・ e2e同上Temurin 21 → ./gradlew bootJar --no-daemon → ECHOLAB_E2E_REQUIRED=1 pytest -m e2e
java.yml ・ check修改 services/calc-engine/、domains/wuwa/ 的黄金用例・数据・domain.yaml 时./gradlew check --no-daemon → bootJar → 确认 jar 存在 → 上传测试与覆盖率报告

本地按本页的顺序跑完一遍，基本等同于 CI 的全部检查。提交前至少运行 ruff check . && ruff format --check . && pytest -m "not e2e"。
