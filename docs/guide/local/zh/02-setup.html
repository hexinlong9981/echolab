开始git clonevenvpytest

安装与设置

取得代码、建 Python 虚拟环境、安装依赖，再用测试确认安装成功。这一页的步骤三条路线都要做，大约几分钟（主要是下载依赖的时间）。

本页的终端记录都是在一个全新的克隆里实际执行得到的；为便于阅读，克隆所在的路径已缩写为 ~/echolab。

整体步骤

克隆git clone
→
虚拟环境python3 -m venv
→
安装依赖pip install
→
验证pytest
→
就绪选路线

1. 克隆仓库

Windows 用户请在 WSL 的终端里执行，并克隆到 WSL 的家目录下（见 准备环境）。

2. 建虚拟环境、安装依赖

最后可能还会出现一条 [notice] A new release of pip is available，可以忽略。装了什么、为什么需要：

包来自用途
anthropicrequirements.txtAnthropic 官方 Python SDK，调用 Claude API（路线 C）。脚本模式下不会联网
mcprequirements.txtMCP 客户端：以子进程启动 Java 计算服务并经 stdio 通信（路线 B/C）
pyyamlrequirements.txt读取 domain.yaml、config/*.yaml、脚本、黄金用例
jsonschemarequirements.txt网关按 JSON Schema 校验工具的输入；测试中校验数据文件
pytest、pytest-asynciorequirements-dev.txt运行 tests/ 下的测试（很多是异步的）
ruffrequirements-dev.txt代码检查（lint）

requirements-dev.txt 的第一行是 -r requirements.txt，所以装它就包含了运行所需的全部依赖。只想运行 CLI、不跑测试时，装 requirements.txt 也可以。

各选项的含义见使用说明的 命令参考。本指南后面的命令统一写成 .venv/bin/python …，激活后写 python … 效果相同。

3. 用测试确认安装成功

运行不需要 Java 的全部测试。-m "not e2e" 排除了要启动 Java 计算服务（jar）的端到端测试，所以这一步只需要 Python。

  • 294 passed：全部通过。测试数量会随仓库的更新变化，重要的是没有 failed 或 error。
  • 5 deselected：被 -m "not e2e" 排除的端到端测试。它们需要构建好的 jar，运行方法见 运行测试与评估。
为什么不加 -qpyproject.toml 的 pytest 设置里已经有 addopts = "-q"。命令行再加 -q 就变成更安静的 -qq：实际运行 pytest -q -m "not e2e" 时，只打印进度点，不再打印最后的 294 passed, … 这一行。想看到汇总行，就像上面那样不加 -q。

4. 目录导览

只列出运行时会接触到的部分：

位置内容什么时候会用到
core/与领域无关的核心（Python）：agent/（CLI 和对话循环、LLM 的实现）、gateway/（工具许可列表、Schema 校验、编号、费用上限）、compare/（比较工具）、verifier/（校验器和渲染器）、trace/、evals/每次运行。core/agent/examples/compare_builds.yaml 是自带的示例脚本
services/calc-engine/Java 21 的计算库和 MCP 服务器（Gradle 项目，带 ./gradlew）路线 B/C：在这里构建 jar（build/libs/calc-engine-mcp.jar）
domains/wuwa/领域包：domain.yaml（声明可用的工具）、golden/（黄金用例）、data/v2.x/（示例数据）、prompts/（系统提示）每次运行都会读取。写脚本时可以参考 golden/ 的输入
config/services.yaml（怎样启动计算服务）、budget.yaml（费用上限和价格表）路线 B/C；路线 C 的费用上限
evals/faithfulness/cases.yaml（忠实度评估用例，也是很好的脚本范例）、reports/（汇总后的报告）运行评估时
tests/pytest 测试；tests/core/fakes.py 是 --fake-backend 使用的 Python 替身运行测试时；路线 A
docs/架构说明、ADR（设计决策记录）、使用说明和本指南的源文件想了解设计时

5. 运行时文件写在哪里

运行时产生的文件都写在仓库根目录下的 .echolab/，它和 .venv/ 一样被 .gitignore 排除，不会出现在 git status 里。

文件内容什么时候写
.echolab/traces/<运行 ID>.jsonl一次提问的执行轨迹：问题、LLM 调用、工具调用、校验判定、回答每次运行（所有路线）
.echolab/costs.jsonl费用台账：每次调用 Claude 的用量和金额，用来检查每日、每月上限只在路线 C（--llm anthropic）。脚本模式的用量是虚构的，记在每次运行用完即删的临时台账里，不写这个文件

轨迹的读法见使用说明的 执行轨迹与评估。想清空记录时，直接删除 .echolab/traces/ 下的文件即可。
