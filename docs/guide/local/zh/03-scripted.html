运行路线 A--llm scripted--fake-backend

用脚本模式运行（无需 API 密钥）

脚本模式用一个 YAML 文件代替 Claude：调用哪些工具、写什么草稿都事先写好。工具的计算、校验器、渲染器和执行轨迹都是真实的代码。本页运行自带示例、解释状态行，然后自己写一个脚本并实际运行。

本页的终端记录都是实际运行得到的；仓库所在的路径已缩写为 ~/echolab。

部分脚本模式 + --fake-backend（路线 A）
LLM模拟：core/agent/llm/scripted.py 按顺序返回脚本里的每一轮。不联网，不读你的问题
计算替身：tests/core/fakes.py 用 Python 参考实现计算，结果和 Java 一样按小数 6 位（HALF_EVEN）返回。只提供 damage.expected、echo.score、gacha.probability_within 三个工具（没有 gacha.simulate），也不按 JSON Schema 检查这三个工具的输入
网关真实：只开放 domain.yaml 声明的工具，按调用顺序编号 c1、c2…
比较工具真实：compare.diff、compare.ratio（核心代码，不经计算服务）
校验器・渲染器真实：检查草稿里的每个数字，不合格就「差し戻し」（退回重写）；通过后把占位符换成数字
执行轨迹真实：写到 .echolab/traces/<运行 ID>.jsonl
费用用脚本里写的虚构用量计算，记在用完即删的临时台账里；不写 .echolab/costs.jsonl

去掉 --fake-backend，计算就换成真实的 Java 服务（路线 B，见 使用 Java 计算服务运行），脚本不用改。

自己写脚本

脚本的格式

格式由 core/agent/llm/scripted.py 定义。文件的顶层是 turns:（也可以直接是一个列表），每个元素是 LLM 的一轮回应，按顺序使用：

键是否必需说明
tool_uses可省略这一轮要调用的工具列表，每项是 {name, input}（id 可省略，自动生成）。同一轮里的多个调用并行执行。有 tool_uses 时，这一轮的 stop_reason 默认为 tool_use
text可省略没有 tool_uses 时，这就是交给校验器的回答草稿（模板），数字用占位符引用
expect可省略上一条发给 LLM 的消息里必须包含的字符串。例如 expect: 差し戻し 确认上一版草稿确实被退回了；不符合时运行以错误结束
usage可省略虚构的 token 用量，如 {input_tokens: 1200, output_tokens: 80}，也可写 cache_creation_input_tokens、cache_read_input_tokens。默认全为 0，用于演示费用计算
stop_reason可省略默认按有无 tool_uses 决定；也可以写 refusal、max_tokens 来模拟这些情况

工具名写成「线上的名字」，即把点换成下划线：

脚本里写工具出典的字段（例）
damage_expecteddamage.expectedtotal、base、bonus_multiplier、crit_multiplier、defense_multiplier、resistance_multiplier
echo_scoreecho.scorescore、percent_of_ideal
gacha_probability_withingacha.probability_withinprobability
compare_diffcompare.diffdiff
compare_ratiocompare.ratioratio、change

出典 ID 是「调用编号.字段」：整个运行中第 1 次工具调用是 c1，第 2 次是 c2……（出错的调用也占一个号）。比较工具的输入写出典 ID，如 {a: c2.total, b: c1.total}。

占位符有三种写法（整数部分每 3 位加逗号，四舍六入五成双）：

写法效果例
[[c1.total]]最多 2 位小数，去掉末尾的 06192.000000 → 6,192
[[c1.total|1]]固定 N 位小数6192.000000 → 6,192.0
[[c4.change|%1]]乘 100，N 位小数，加 %0.151163 → 15.1%

草稿里占位符以外的数字，只允许三类：问题里出现过的数字、行首的列表编号（如 1.）、10 以下的整数后面紧跟量词（日语的「つ・点・種類・位・番目」、中文的「个・种・项・条・步」、英语的 ways・points・steps・options 等名词；数字与量词之间最多一个空格）。

参考范例evals/faithfulness/cases.yaml 里的每个评估用例都有一段同样格式的 turns（涵盖期待伤害、声骸评分、抽卡概率、比较工具），可以照着改。那里的 fake_unverified、expect.status 等键只给评估程序用，CLI 不读。工具的输入可以参考 domains/wuwa/golden/*.yaml 里各用例的 input。

示例：抽卡概率

下面写一个新脚本：用 domains/wuwa/golden/gacha.yaml 里的玩具规则（数值是说明用的，不是游戏官方数值），计算 10 抽和 20 抽以内抽到限定角色的概率。为了演示退回，第 2 轮故意写一个自己估算的数字。脚本放在仓库外的 ~/echolab-scripts/，不需要加进仓库。

# 自己写的脚本：用玩具规则计算抽卡概率（规则数值是说明用的，不是游戏官方数值）
turns:
  # 第 1 轮：并行调用两次工具（10 抽以内、20 抽以内）
  - tool_uses:
      - name: gacha_probability_within
        input:
          rules: {base_rate: 0.1, soft_pity_start: 5, soft_pity_increment: 0.1, hard_pity: 10, featured_rate: 0.5, guarantee_after_loss: true}
          start_pity: 0
          guaranteed: false
          pulls: 10
      - name: gacha_probability_within
        input:
          rules: {base_rate: 0.1, soft_pity_start: 5, soft_pity_increment: 0.1, hard_pity: 10, featured_rate: 0.5, guarantee_after_loss: true}
          start_pity: 0
          guaranteed: false
          pulls: 20
    usage: {input_tokens: 2000, output_tokens: 150}
  # 第 2 轮：故意写一个自己估算的数字（73%），会被校验器退回
  - text: 10 抽以内抽到限定角色的概率大约是 73%。
    usage: {input_tokens: 400, output_tokens: 40}
  # 第 3 轮：只用占位符引用工具结果，通过校验
  - expect: 差し戻し
    text: |-
      按你给的规则：
      - 10 抽以内抽到限定角色的概率：[[c1.probability|%1]]
      - 20 抽以内抽到限定角色的概率：[[c2.probability|%1]]
    usage: {input_tokens: 600, output_tokens: 80}

~/echolab-scripts/gacha_toy.yaml

运行时把规则也写进问题里（脚本不读问题，但校验器会把问题里的数字当作可引用的数字）：

  • c1.probability 的原始值 0.7344054712000005 与黄金用例 gacha-001 的期待值 0.7344054712 一致（概率是浮点数，按最短表示原样返回，不像期待伤害那样取 6 位小数）。[[c1.probability|%1]] 把它渲染成 73.4%。
  • 20 抽是硬保底的两倍，又有「歪了之后必是限定」，所以必定抽到：1.0 → 100.0%。
  • 草稿里的「10 抽」「20 抽」没有被退回，因为 10 和 20 都出现在问题里。
  • 費用: $0.0174 来自脚本里虚构的 usage：输入合计 3,000 tokens × 4 美元/百万 + 输出合计 270 tokens × 20 美元/百万（config/budget.yaml 中 claude-opus-5-5 的价格）。这只是演示费用的计算方式，没有任何实际费用，也不写入 .echolab/costs.jsonl。

看一看被退回的草稿

被退回的第 1 版草稿记录在执行轨迹的 verdict（判定）事件里：

第 1 版的问题：「数值『73%』没有出处。工具的结果请用 [[出典ID]] 引用，差和比请用比较工具计算（可以引用问题中的数值）」。这段话会作为退回通知发回给 LLM，所以第 3 轮的 expect: 差し戻し 能匹配上。

一直写数字会怎样

如果每版草稿都直接写数字，退回到上限后运行以 fallback 结束：不给出任何数字，退出码为 1。下面的脚本 ~/echolab-scripts/always_bad.yaml 在工具调用之后连续三轮都写「概率大约是 73%。」：

# 每一版草稿都直接写数字：校验永远不通过
turns:
  - tool_uses:
      - name: gacha_probability_within
        input:
          rules: {base_rate: 0.1, soft_pity_start: 5, soft_pity_increment: 0.1, hard_pity: 10, featured_rate: 0.5, guarantee_after_loss: true}
          start_pity: 0
          guaranteed: false
          pulls: 10
  - text: 概率大约是 73%。
  - text: 概率大约是 73%。
  - text: 概率大约是 73%。

命令中的「…（与上例相同）…」是为了版面而省略的，实际运行时输入的是完整的问题。固定回答的意思是：「抱歉，无法写出能确认计算结果出处的回答，因此不给出含数字的回答。请把条件写得更具体后再问一次。」——宁可不给数字，也不给没有出处的数字。
