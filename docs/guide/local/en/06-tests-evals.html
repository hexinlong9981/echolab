Run tests & evals

Run the same checks as CI on your own machine: Python linting and unit tests, end-to-end tests that use the jar, Java tests and static checks, and the numeric faithfulness evals. None of them need an API key.

About the output on this pageAll outputs and timings below come from real runs on a fresh clone of the repository (WSL2, Python 3.12, Temurin 21). The path has been shortened to ~/echolab, and long outputs are cut with "…". Unless stated otherwise, commands are run from the repository root with the virtual environment activated (source .venv/bin/activate).

1. Linting: ruff

The rules are in [tool.ruff] in pyproject.toml (line length 100, target Python 3.12). ruff format . (without --check) rewrites files in place; CI uses only --check and fails if any file is not formatted.

2. Python tests (excluding end-to-end)

  • Neither Java nor Claude is used: the LLM is replaced by scripts or a stand-in for the SDK client, and the calc service by the Python reference implementation (the same as --fake-backend).
  • 5 deselected are the end-to-end tests excluded by -m "not e2e".
  • tests/core/test_evals.py runs the scripted-mode evals once and requires the result to match the committed evals/reports/scripted-baseline.md.
  • For what each test file covers, see tests/README.en.md in the repository.

3. End-to-end tests: pytest -m e2e

The end-to-end tests start the real calc-engine jar as configured in config/services.yaml. First build the jar as described on page 4, and make sure the tests can find JDK 21 (setting JAVA_HOME is enough):

Without java or the jar, these tests are skipped by default (not counted as failures), and the skip message gives the reason:

The skip reasons read "java not found (set PATH or JAVA_HOME)" and "jar not found: …".

With ECHOLAB_E2E_REQUIRED=1, missing prerequisites fail the tests instead of skipping them. The CI e2e job runs this way, so that "everything skipped" is not mistaken for a pass. In an environment without java:

The error says that the executable java for service calc-engine was not found, and asks you to install JDK 21 and put java on PATH, or set JAVA_HOME so that $JAVA_HOME/bin/java exists. With everything in place, ECHOLAB_E2E_REQUIRED=1 pytest -m e2e gives the same result as above (5 passed, about 31 seconds in our run). Add this variable when you want to be sure your environment really ran the e2e tests rather than quietly skipping them.

5. Evals: numeric faithfulness

The evals use 8 fixed cases (evals/faithfulness/cases.yaml) to check whether answers contain numbers without a source. In scripted mode they need no key and take a few seconds:

The report is titled "Eval report: numeric faithfulness" and lists the date (UTC), the LLM, the cases file (8 cases) and these metrics: faithfulness (the share of answers that contain no numbers without a source) 1.000; rejection rate (rejected drafts / drafts) 0.462 (6 / 13); passed cases 8 / 8; total cost (USD) 0.028120. 「…（ケースごとの結果の表）…」 stands for the omitted per-case results table.

  • The report is printed to the screen and also written to the file given by --out (Markdown). The raw record of each case is saved in evals/reports/raw/ (ignored by Git).
  • Metrics: a faithfulness of 1.000 means no answer contained a number without a source; the rejection rate of 0.462 is because some cases deliberately write failing drafts to confirm that the verifier rejects them.
  • In scripted mode, the cost (費用) is calculated from the fictitious usage written in the scripts; it only exercises the cost logic and is not real spending.
  • Apart from the date line, the output of our run matched the committed evals/reports/scripted-baseline.md exactly.
Running the evals with real Claude (incurs cost)

Requires an API key and the Java service (see page 5). Every case calls Claude and is subject to the same daily and monthly caps.

python -m core.evals --llm anthropic --out evals/reports/<名前>.md
python -m core.evals --llm anthropic --case damage-basic --out /tmp/one-case.md   # run a single case

<名前> means "<name>": a file name of your choice.

These commands were not run for this page. For what the eval metrics mean in detail, see Traces and evals.

6. Web UI (optional): watch replays in a browser

Needs Node.js (22 or later recommended). No API key, Java or Tesseract needed:

python -m servers.web_api.export                 # run every demo and eval in scripted mode → web/public/data/
(cd web && npm ci && npm run build)              # build the site → web/dist/ (needs Node.js)
python -m servers.web_api                        # listens on 127.0.0.1 only → http://127.0.0.1:8765/

Open http://127.0.0.1:8765/ in a browser; there are three tabs: Replay, Evals and Run (local). During development use (cd web && npm run dev); the front-end checks are (cd web && npm run typecheck && npm test).

How CI runs the same checks

The GitHub Actions workflows are in .github/workflows/. CI has no API key, and the LLM is always replaced by scripts:

Workflow ・ jobTriggerCommands run
test.yml ・ pythonPushes to main, every PRruff check . → ruff format --check . → pytest -m "not e2e" (Python 3.12)
test.yml ・ e2eSame as aboveTemurin 21 → ./gradlew bootJar --no-daemon → ECHOLAB_E2E_REQUIRED=1 pytest -m e2e
java.yml ・ checkChanges to services/calc-engine/, or to the golden cases, data or domain.yaml in domains/wuwa/./gradlew check --no-daemon → bootJar → confirm the jar exists → upload the test and coverage reports

Running through this page locally, in order, covers essentially all of CI's checks. Before committing, run at least ruff check . && ruff format --check . && pytest -m "not e2e".
