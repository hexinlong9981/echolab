Run with real Claude

Without --llm, the CLI calls the Claude API by default (model claude-opus-5-5): Claude understands your question, chooses the calculation tools and writes the answer. This page explains how to set up an API key, how the cost caps protect you, and which data leaves your computer.

About the output on this pageThe environment used for this page did not have an API key set, so only two kinds of real output are shown below: with no credentials, and when a cost cap is reached. No real Claude answers are shown here; answers have the same format as in scripted mode, and how to read them is covered in Reading the answers. The path has been shortened to ~/echolab.

1. Get an API key

  1. Sign in to Anthropic's Claude Console (https://platform.claude.com/; the old address console.anthropic.com redirects there).
  2. Under Settings → API keys, create a key and copy the string starting with sk-ant-. The key is shown only once.
  3. The API is billed by usage, so set up credit in the Console's billing settings. EchoLab has its own cost caps (see below); the two are independent.

2. Let the CLI find your credentials

The CLI uses Anthropic's official Python SDK and looks for credentials in the SDK's default order. Two common ways:

# Option A: environment variable (only for the current terminal)
export ANTHROPIC_API_KEY=sk-ant-...   # your key

# Option B: sign in with Anthropic's CLI; the SDK reads the configuration it saves
ant auth login
Do not put your key in the repositoryThis repository is public. .gitignore already ignores .env and .env.*, but the CLI does not read .env automatically. If you want to keep your key in .env, load it yourself: set -a; . ./.env; set +a. Before committing, you can confirm it is not tracked with git status and git check-ignore -v .env.

3. Check the cost caps first

The cost ledger is checked before every call to Claude. The defaults are in config/budget.yaml:

Daily cap caps_usd.daily$1.00 (the day rolls over at 00:00 UTC (09:00 in Tokyo))ECHOLAB_DAILY_USD
Monthly cap caps_usd.monthly$10.00 (the month rolls over in UTC)ECHOLAB_MONTHLY_USD
Ledger ledger.echolab/costs.jsonl (ignored by Git)ECHOLAB_LEDGER

For your first tries, you may want to lower the caps:

export ECHOLAB_DAILY_USD=0.20
export ECHOLAB_MONTHLY_USD=2.00

Only --llm anthropic writes to the real ledger; scripted mode uses a temporary ledger for each run. For how cost is calculated and the format of each ledger line, see Cost caps and data trust.

4. Ask a question

Run from the repository root with the virtual environment activated (leaving out --llm means anthropic). By default the Java calc service is started, so complete page 4 first. If you do not have Java yet, add --fake-backend, but then questions that need the sample data references cannot be answered.

export JAVA_HOME=$HOME/.local/jdk/21
python -m core.agent "攻撃力 2000、スキル倍率 2.5、ダメージバフ 0.3、会心率 0.6、会心ダメージ 2.2、防御定数 1600、敵の防御 1000、防御無視 0、敵の耐性 0.1、耐性ダウン 0 のときの期待ダメージは？"

The question (in Japanese) asks for the expected damage with ATK 2000, skill multiplier 2.5, damage bonus 0.3, crit rate 0.6, crit damage 2.2, DEF constant 1600, enemy DEF 1000, DEF ignore 0, enemy RES 0.1 and RES shred 0. With real Claude you can ask in your own words.

  • The answer means: "No Claude API credentials were found, so I could not answer. Set the environment variable ANTHROPIC_API_KEY (or sign in with ant auth login), or use scripted mode (--llm scripted), which needs no API key." The source table says 「（引用した出典はありません）」 ("no sources cited"). The trace's llm_error event records kind: credentials and "Claude API credentials not found (set ANTHROPIC_API_KEY or similar)".

With credentials set, the same command prints Claude's answer, the source table and the status line 状態: answered … 費用: $…, and the cost is appended to .echolab/costs.jsonl.

5. What happens when a cap is reached

The cost check happens before Claude is called, and also before the credentials are used (_call_llm in core/agent/loop.py runs budget.check() first). So you can reproduce it without spending money and without a key: set the daily cap to 0 and point the ledger at a temporary file, so the real ledger is not touched.

「…（同上）…」 in the command means "… (same as above) …"; it is shortened here for layout, and the run used the full question. The answer means: "Today's (UTC) cost has reached the daily cap, so I cannot answer right now (used 0 USD / cap 0 USD). It becomes available again when the UTC date changes. The cap can be changed with the environment variable ECHOLAB_DAILY_USD or caps_usd.daily in config/budget.yaml."

  • Even without credentials, the result is budget_exceeded, not llm_error: the cap check comes first, and Claude was never called. The trace has no llm_call or llm_error event.
  • The answer says which cap was reached (today = daily), the amount used and the cap, when it becomes available again, and how to change it. With ECHOLAB_MONTHLY_USD=0, the answer instead begins 「今月（UTC）のコストが月次の上限に達したため…」 ("This month's (UTC) cost has reached the monthly cap…").
  • The temporary ledger file was not created: no call was made, so there was nothing to record.
  • If a cap is reached partway through a question (for example, before the second Claude call after a tool call), the run likewise ends with budget_exceeded, and the cost already incurred is recorded in the ledger as is.

6. Which data is sent

Scripted mode --llm scriptedReal Claude --llm anthropic
External network accessNoneOnly the Claude API
What is sentNothingThe system prompt, the tool definitions (input schemas), the full text of your question, Claude's earlier replies, tool results (source IDs and numbers), and the verifier's rejection notices
What stays on your machineThe calculations (Java subprocess or Python reference implementation), the sample data, the traces in .echolab/traces/, and the cost ledger .echolab/costs.jsonl

Your question is sent as is, and is also written as is to the trace on your machine. Do not put personal information unrelated to the calculation in your questions. For a diagram of the data flow, see Cost caps and data trust.

Tips for safe use

Keep the key in the environment only

Use export or ant auth login; do not write it in code, configuration files, or scripts whose command history you might share.

Start with scripted mode

Switch to real Claude only after your environment and the Java service work, so you do not pay while debugging setup problems.

Lower the caps at first

For your first tries, set ECHOLAB_DAILY_USD to a small value; restore the default once you are familiar.

Check traces before sharing

Traces contain the full question and every draft. .echolab/ is ignored by Git, so it is not committed by accident.

If your key leaks

Delete the key in the Console right away and create a new one; just removing it from a file is not enough.
