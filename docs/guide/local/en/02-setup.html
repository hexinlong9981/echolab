Setup

Fetch the code, create a Python virtual environment, install dependencies, and confirm the install with the tests. All three paths need the steps on this page, which take a few minutes (mostly spent downloading dependencies).

All terminal sessions on this page were recorded in a fresh clone; for readability, the path of the clone has been shortened to ~/echolab.

1. Clone the repository

Windows users: run this in a WSL terminal and clone into your WSL home directory (see Prerequisites).

2. Create a virtual environment and install dependencies

A final [notice] A new release of pip is available line may also appear; you can ignore it. What gets installed, and why:

PackageFromUsed for
anthropicrequirements.txtAnthropic's official Python SDK, for calling the Claude API (path C). It makes no network calls in scripted mode
mcprequirements.txtMCP client: starts the Java calc service as a subprocess and talks to it over stdio (paths B/C)
pyyamlrequirements.txtReads domain.yaml, config/*.yaml, scripts and golden cases
jsonschemarequirements.txtThe gateway validates tool inputs against JSON Schema; tests validate data files
pytest, pytest-asynciorequirements-dev.txtRun the tests under tests/ (many of them async)
ruffrequirements-dev.txtLinting

The first line of requirements-dev.txt is -r requirements.txt, so installing it includes every runtime dependency. If you only want to run the CLI and not the tests, installing requirements.txt is enough.

Activating the virtual environment (optional)

The commands above are written as .venv/bin/python and .venv/bin/pip, so they work without activation. If that is too much typing, activate the environment once in each new terminal; after that, python points to the Python inside the virtual environment:

The help text 「出典付きで質問に答える」 means "Answer questions with sources". For what each option means, see the CLI reference in the user guide. The rest of this guide writes commands as .venv/bin/python …; after activation, python … does the same thing.

3. Confirm the install with the tests

Run every test that does not need Java. -m "not e2e" excludes the end-to-end tests that start the Java calc service (the jar), so this step needs only Python.

  • 294 passed: everything passed. The number of tests changes as the repository is updated; what matters is that there is no failed or error.
  • 5 deselected: the end-to-end tests excluded by -m "not e2e". They need a built jar; see Run tests & evals for how to run them.
Why no -qThe pytest settings in pyproject.toml already contain addopts = "-q". Adding -q on the command line makes it the even quieter -qq: running pytest -q -m "not e2e" prints only the progress dots and no final 294 passed, … line. To see the summary line, leave out -q as shown above.

5. Where runtime files go

All files produced at run time go into .echolab/ under the repository root. Like .venv/, it is excluded by .gitignore and does not show up in git status.

FileContentsWhen it is written
.echolab/traces/<run ID>.jsonlThe trace of one question: the question, LLM calls, tool calls, verification verdicts, the answerEvery run (all paths)
.echolab/costs.jsonlCost ledger: usage and amount of each Claude call, used to enforce the daily and monthly capsOnly in path C (--llm anthropic). Usage in scripted mode is fictitious; it is recorded in a temporary ledger that is deleted after each run, and this file is not written

For how to read traces, see Traces & evals in the user guide. To clear the history, just delete the files under .echolab/traces/.
