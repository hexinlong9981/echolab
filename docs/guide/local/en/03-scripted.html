Run in scripted mode (no API key)

Scripted mode replaces Claude with a YAML file: which tools to call and what the drafts say are written in advance. The tool calculations, the verifier, the renderer and the traces are all real code. This page runs the bundled example, explains the status line, then writes a script of your own and runs it.

All terminal sessions on this page are real runs; the path of the repository has been shortened to ~/echolab.

The question text is not "understood"

Scripted mode ignores what the question says. Ask "Hello" with the same script and you get exactly the same answer as above:

The question matters in two places: it is written into the trace, and the verifier allows the answer to cite numbers that appear in the question. So if a script's draft writes numbers directly, the verification result can change when the question changes. For a system that really understands the question, see Run with real Claude.

Writing your own script

Script format

The format is defined by core/agent/llm/scripted.py. The top level of the file is turns: (or the file can be a plain list); each element is one LLM turn, used in order:

KeyRequired?Description
tool_usesOptionalThe list of tools to call in this turn, each as {name, input} (id may be omitted and is then generated). Multiple calls in the same turn run in parallel. When tool_uses is present, the turn's stop_reason defaults to tool_use
textOptionalWithout tool_uses, this is the answer draft (a template) handed to the verifier; numbers are cited with placeholders
expectOptionalA string that must appear in the previous message sent to the LLM. For example, expect: 差し戻し confirms that the previous draft really was rejected; if it does not match, the run ends with an error
usageOptionalFictitious token usage, such as {input_tokens: 1200, output_tokens: 80}; cache_creation_input_tokens and cache_read_input_tokens are also accepted. All default to 0. Used to demonstrate the cost calculation
stop_reasonOptionalBy default decided by whether tool_uses is present; you can also write refusal or max_tokens to simulate those cases

Write tool names as their "wire names", with the dot replaced by an underscore:

In the scriptToolSource fields (examples)
damage_expecteddamage.expectedtotal, base, bonus_multiplier, crit_multiplier, defense_multiplier, resistance_multiplier
echo_scoreecho.scorescore, percent_of_ideal
gacha_probability_withingacha.probability_withinprobability
compare_diffcompare.diffdiff
compare_ratiocompare.ratioratio, change

A source ID is "call number.field": the 1st tool call of the run is c1, the 2nd is c2, and so on (a call that fails also takes a number). Compare tool inputs take source IDs, such as {a: c2.total, b: c1.total}.

Placeholders come in three forms (thousands separators in the integer part, round half to even):

FormEffectExample
[[c1.total]]Up to 2 decimal places, trailing zeros removed6192.000000 → 6,192
[[c1.total|1]]Exactly N decimal places6192.000000 → 6,192.0
[[c4.change|%1]]Multiplied by 100, N decimal places, with %0.151163 → 15.1%

Apart from placeholders, a draft may contain only three kinds of numbers: numbers that appear in the question, list numbers at the start of a line (such as 1.), and integers of 10 or less immediately followed by a counting word (in English, words such as "ways", "steps", "options" or "builds", as in "3 steps"; Japanese and Chinese counters are also recognized).

Reference examplesEvery eval case in evals/faithfulness/cases.yaml has a turns section in the same format (covering expected damage, echo scores, gacha probabilities and compare tools), which you can adapt. Keys there such as fake_unverified and expect.status are only for the eval runner; the CLI ignores them. For tool inputs, see the input of each case in domains/wuwa/golden/*.yaml.

Example: gacha probabilities

Here is a new script. It uses the toy rules from domains/wuwa/golden/gacha.yaml (the values are illustrative, not official game values) to calculate the chance of getting the featured character within 10 pulls and within 20 pulls. To demonstrate a rejection, turn 2 deliberately writes a self-estimated number. The script lives outside the repository, in ~/echolab-scripts/; it does not need to be added to the repository.

# My own script: gacha probabilities under toy rules (illustrative values, not official game values)
turns:
  # Turn 1: two tool calls in parallel (within 10 pulls, within 20 pulls)
  - tool_uses:
      - name: gacha_probability_within
        input:
          rules: {base_rate: 0.1, soft_pity_start: 5, soft_pity_increment: 0.1, hard_pity: 10, featured_rate: 0.5, guarantee_after_loss: true}
          start_pity: 0
          guaranteed: false
          pulls: 10
      - name: gacha_probability_within
        input:
          rules: {base_rate: 0.1, soft_pity_start: 5, soft_pity_increment: 0.1, hard_pity: 10, featured_rate: 0.5, guarantee_after_loss: true}
          start_pity: 0
          guaranteed: false
          pulls: 20
    usage: {input_tokens: 2000, output_tokens: 150}
  # Turn 2: deliberately write a self-estimated number (73%); the verifier rejects it
  - text: The chance of getting the featured character within 10 pulls is about 73%.
    usage: {input_tokens: 400, output_tokens: 40}
  # Turn 3: cite tool results only through placeholders; passes verification
  - expect: 差し戻し
    text: |-
      Under the rules you gave:
      - Chance of getting the featured character within 10 pulls: [[c1.probability|%1]]
      - Chance of getting the featured character within 20 pulls: [[c2.probability|%1]]
    usage: {input_tokens: 600, output_tokens: 80}

~/echolab-scripts/gacha_toy.yaml

expect: 差し戻し stays in Japanese: it must match the rejection notice the program actually sends. When you run it, put the rules in the question as well (the script does not read the question, but the verifier treats numbers in the question as citable):

  • The raw value of c1.probability, 0.7344054712000005, matches the expected value 0.7344054712 of golden case gacha-001 (probabilities are floating-point numbers returned as-is in their shortest representation, not rounded to 6 decimal places like expected damage). [[c1.probability|%1]] renders it as 73.4%.
  • 20 pulls is twice the hard pity, and "after losing the 50/50 the next 5-star is always featured" applies, so the featured character is guaranteed: 1.0 → 100.0%.
  • "10 pulls" and "20 pulls" in the draft were not rejected, because 10 and 20 both appear in the question.
  • 費用: $0.0174 (cost) comes from the fictitious usage in the script: 3,000 input tokens in total × $4 per million + 270 output tokens in total × $20 per million (the claude-opus-5-5 prices in config/budget.yaml). It only demonstrates how cost is calculated; nothing is actually charged, and nothing is written to .echolab/costs.jsonl.

Looking at the rejected draft

The rejected first draft is recorded in the trace's verdict events:

The problem with draft 1: "The number '73%' has no source. Cite tool results with [[source ID]] and compute differences and ratios with the compare tools (citing numbers from the question is allowed)." This text is sent back to the LLM as the rejection notice, which is why expect: 差し戻し in turn 3 matches.

What if the draft keeps writing numbers?

If every draft writes numbers directly, the run ends with fallback once the rejection limit is reached: no numbers are given, and the exit code is 1. The script ~/echolab-scripts/always_bad.yaml below writes "The chance is about 73%." for three turns in a row after the tool call:

# Every draft writes the number directly: verification never passes
turns:
  - tool_uses:
      - name: gacha_probability_within
        input:
          rules: {base_rate: 0.1, soft_pity_start: 5, soft_pity_increment: 0.1, hard_pity: 10, featured_rate: 0.5, guarantee_after_loss: true}
          start_pity: 0
          guaranteed: false
          pulls: 10
  - text: The chance is about 73%.
  - text: The chance is about 73%.
  - text: The chance is about 73%.

The "… (same as above) …" in the command is shortened for layout; the actual run used the full question. The fixed answer means: "Sorry. I could not write an answer whose calculation results can be traced to their sources, so I will not give an answer containing numbers. Please make the conditions more specific and ask again." The source table says 「（引用した出典はありません）」 ("no sources cited"). Better no numbers than numbers without a source.
