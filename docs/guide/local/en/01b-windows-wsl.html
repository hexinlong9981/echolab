Set up WSL on Windows

For Windows users who have never used WSL: this page takes you from installing WSL 2 and Ubuntu to having the Git, Python and JDK that EchoLab needs installed inside Ubuntu. When you finish, continue with Setup.

The Windows-side steps follow Microsoft's official documentation (links in References at the end of the page). The terminal sessions inside Ubuntu were recorded on a real Ubuntu 24.04 environment.

What WSL is, and why EchoLab runs inside it

WSL (Windows Subsystem for Linux) lets you use a Linux distribution (such as Ubuntu) and its command-line tools directly on Windows, without a traditional virtual machine or dual-boot setup. WSL 2 runs a real Linux kernel in a lightweight utility virtual machine.

On Windows, EchoLab should run inside WSL because:

  • It matches CI: the repository's GitHub Actions run the tests on ubuntu-latest with Python 3.12 and JDK 21. Inside WSL's Ubuntu, commands, paths and line endings all behave the same as in CI.
  • This guide's commands are Linux commands: things like .venv/bin/python, ./gradlew and export JAVA_HOME=… do not work as written in PowerShell.
  • Work on one side only: keep the tools (Git, Python, JDK) and the code in Linux, and do not mix in Windows-side tools. For the reasons, see "run every command inside WSL" in Prerequisites.

1. Check your Windows version and virtualization

wsl --install requires Windows 10 version 2004 or later (Build 19041 or later), or Windows 11. To check: press Windows logo key + R, type winver and select "OK". The window that opens shows the version and the OS build number. You can also find them under Settings → System → About.

If your version is too old, update it through Windows Update first. Microsoft also provides manual installation steps for older versions, but this guide does not cover them.

WSL 2 also needs your computer's virtualization feature to be enabled. Most computers have it on by default; if you see error 0x80370102 during installation or startup, see Common problems below.

2. Install WSL and Ubuntu

Find PowerShell (or Windows Terminal) in the Start menu, right-click it, choose "Run as administrator", and enter:

wsl --install

PowerShell (administrator). For Windows-side commands, this page shows only the command itself, without example output.

According to Microsoft's documentation, this single command: enables the two optional components "Windows Subsystem for Linux" and "Virtual Machine Platform"; downloads and installs the latest Linux kernel; sets WSL 2 as the default version; and downloads and installs the Ubuntu distribution. You will need to restart your computer along the way; restart when prompted.

Choosing an Ubuntu version (optional)

The distribution installed by default is named "Ubuntu". To pick a specific version, first list the distributions available online, then give the name with -d:

wsl -l -o
wsl --install -d Ubuntu-24.04

PowerShell. wsl -l -o is short for wsl --list --online. Use the name exactly as it appears in the NAME column of the list after -d.

The package names and output on the Ubuntu side of this page were verified on Ubuntu 24.04. Which version the default "Ubuntu" points to changes over time, so after installing, check it with cat /etc/os-release as shown below.

First launch: create a Linux user

After restarting, open Ubuntu from the Start menu (or open an Ubuntu tab in Windows Terminal). On first launch, wait while files are decompressed; you are then asked for a new user name and password. Things to know (all from Microsoft's documentation):

  • This user name and password belong only to this Linux distribution and have nothing to do with your Windows user name or password. You can choose different ones.
  • While you type the password, nothing appears on screen (not even *). This is normal; just press Enter when you are done.
  • This account becomes the distribution's default user and is signed in automatically at launch. It is the Linux administrator and can run administrative commands with sudo. The password sudo asks for later is the one you set here.
  • If you forget the password: in PowerShell, run wsl -u root to enter as root, reset it with passwd <username>, then exit.

3. Check the installation

In PowerShell (administrator not needed), run:

wsl -l -v

PowerShell. wsl -l -v is short for wsl --list --verbose.

It lists the installed distributions, with each one's state (running or stopped) and the WSL version it uses. Check that the Ubuntu row shows VERSION 2. Distributions newly installed with wsl --install use WSL 2 by default.

If VERSION shows 1, or if you want to update WSL itself to the latest version first, use these commands:

wsl --update
wsl --set-default-version 2
wsl --set-version Ubuntu 2

PowerShell. In order: update WSL; make WSL 2 the default for distributions installed from now on; convert an installed distribution (here the one named Ubuntu; use the name shown by wsl -l -v) to WSL 2.

Microsoft's documentation warns that converting between WSL 1 and WSL 2 can take a long time and may fail; if the distribution already holds important files, back them up first. A freshly installed, empty distribution is nothing to worry about.

5. Where to put the repository

Clone the repository into your Ubuntu home directory, for example ~/echolab (that is, /home/<username>/echolab), and not under /mnt/c/… (the Windows C: drive):

  • Speed: Microsoft recommends keeping files you work on with Linux tools in the WSL file system. Accessing files across operating systems works but can be much slower; installing dependencies and running tests read and write many small files, so the difference is very noticeable.
  • Consistent behavior: under /mnt/c, file permissions, case sensitivity and so on follow the rules of the Windows file system, which differ from CI's Linux environment.

The clone command itself is in Setup. Just run cd ~ first to return to your home directory.

Viewing files from the Windows side

  • In the Ubuntu terminal, go to a directory and run explorer.exe . (note the trailing dot) to open the current directory in Windows File Explorer.
  • Type \\wsl$ into File Explorer's address bar to see all installed distributions and their files; your home directory is at \\wsl$\<distribution name>\home\<username>.
  • To edit with VS Code: install VS Code's WSL extension, then run code . in the repository directory in the Ubuntu terminal. VS Code connects to WSL and edits and runs things on the Linux side. For details, see Microsoft's Get started using VS Code with WSL. This step is optional.
Viewing is fine; run everything in UbuntuOpening and browsing files from the Windows side is no problem, but run Python, Git and Java commands only in the Ubuntu terminal. Do not use the Windows versions of Git or Python on the repository under \\wsl$.

6. Set up Git in WSL

If you only git clone the public repository and run EchoLab locally, no Git setup and no GitHub account are needed. If you want to commit locally, first set your name and email in Ubuntu:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Ubuntu terminal. These settings are stored in Ubuntu's ~/.gitconfig and are completely separate from any Git settings on the Windows side.

To push to your own repository on GitHub, you need to authenticate. GitHub does not accept your account password for Git operations over HTTPS; you can choose to:

  • install the GitHub CLI (gh) in Ubuntu and sign in by running gh auth login and following the prompts;
  • or use a personal access token instead of a password;
  • or set up an SSH key.

Whichever you choose, set it up in Ubuntu, and run Git commands only in Ubuntu.
