Operating system

  • Linux: any reasonably recent distribution works.
  • macOS: the commands are the same as on Linux (run them in Terminal).
  • Windows: use WSL2 (Windows Subsystem for Linux) and do everything in this guide inside WSL's Linux.
Never used WSL?Start with Set up WSL on Windows: it covers everything from installing WSL 2 and Ubuntu to installing the Python, Git and JDK 21 listed on this page inside Ubuntu.
Windows users: run every command inside WSL and do not mix in Windows-side tools In a WSL terminal, PATH includes Windows directories (/mnt/c/…) by default, so the Windows versions of python.exe and git.exe can also be found. They see the Windows file system and line-ending conventions and are not compatible with the commands in this guide. Make sure that:
  • Python, Git and the JDK are all installed inside WSL's Linux, and your commands never include .exe.
  • You clone the repository into your WSL home directory (such as ~/echolab), not under /mnt/c/…. It is faster and avoids permission and line-ending problems.
  • You do not run this guide's commands in Windows PowerShell or Command Prompt.

Confirm that you are inside WSL and not on the Windows side:

If the output of uname -sr contains microsoft-standard-WSL2, you are in WSL2. The second command is only there to show that Windows programs are also on PATH (the user name has been replaced with <username>); this guide uses only the Linux commands without .exe.

Python 3.12 or later

The project targets Python 3.12 (ruff's target-version = "py312" in pyproject.toml). All output in this guide was produced with Python 3.12.11. You also need the standard library's venv (to create the virtual environment).

  • If the second command prints False, the system python3 is too old. Check whether a separate python3.12 is installed (python3.12 --version); if so, replace python3 with python3.12 in the later commands. If not, install 3.12 or later with your distribution's package manager or the python.org installer.
  • If the third command raises ModuleNotFoundError: some Linux distributions ship venv / ensurepip as a separate package (usually named something like python3.12-venv). Install it.

Git

Git is only used for git clone, so any version will do. The repository is public, so cloning does not require a GitHub account.

JDK 21 (path B, and path C when using the Java service)

The calc service calc-engine is written in Java 21. Building the jar needs a JDK (not just a JRE), and running it needs Java 21. Any distribution works; Eclipse Temurin is used as the example here.

The CLI looks for java in this order: first java on PATH, then $JAVA_HOME/bin/java if none is found. So you do not have to put Java on PATH; setting JAVA_HOME is enough. The ./gradlew used for building also reads JAVA_HOME.

For example: download the Temurin 21 Linux x64 archive from Adoptium, extract it into ~/.local/jdk, and create a version-free link ~/.local/jdk/21 (below is a real session in an empty home directory):

What to look for: the first line says version "21.…", and javac runs too (so it is a JDK). export JAVA_HOME=… only applies to the current terminal; to make it permanent, add that line to ~/.bashrc (or your shell's config file). Installing through your distribution's package manager or the macOS installer also works, as long as java -version shows 21.

No java on PATH is fineIn this guide's environment, command -v java || echo "no java on PATH" prints no java on PATH; everything runs on JAVA_HOME alone. Conversely, if there is an older java on PATH (Java 8, for example), the CLI uses it first, and a jar built with Java 21 will not run on an older Java. In that case, put JDK 21 at the front of PATH. See Troubleshooting local runs.

Docker (optional)

If you would rather not install a JDK, the README gives commands for building and testing the Java code in a gradle:8-jdk21 container (running ./gradlew check in services/calc-engine). For details, see Run with the Java calc service.

docker --version only checks the clientYou also need to be able to reach the Docker engine. In this guide's environment, when the current user lacks access, docker version prints permission denied while trying to connect to the docker API at unix:///var/run/docker.sock. In that case, add the user to the docker group (or follow the instructions for your Docker installation). On Windows with Docker Desktop, also enable WSL integration for your WSL distribution in its settings.

Note: the container is only for building and testing. In path B, the CLI starts the calc service on your machine with java -jar …, so actually running the Java service still requires Java 21 on your machine.

Anthropic API key (path C only)

You need one only to have real Claude answer. Paths A and B make no API calls over the network and incur no cost. Check whether a key is set (without printing it):

For how to set it, the cost caps (default $1 per day, $10 per month) and what happens without a key, see Run with real Claude.

Never write the key into a file in the repositorySet it only as an environment variable. .gitignore already excludes files such as .env and *.key, but the safest approach is to never put the key in the working directory at all.
