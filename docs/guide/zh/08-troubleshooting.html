① 找不到 java

原因：没有加 --fake-backend，CLI 要启动 Java 计算服务，但 PATH 上没有 java，也没有设置 JAVA_HOME（CLI 在启动子进程之前就检查这一点）。在 WSL 中，Windows 侧安装的 Java 通常不能直接用于 Linux 侧。

解决（任选其一）：

  • 设置 JAVA_HOME 指向 JDK 21：export JAVA_HOME=$HOME/.local/jdk/21（按你的实际安装位置）。CLI 会自动改用 $JAVA_HOME/bin/java。
  • 或把 JDK 21 的 bin 加到 PATH。
  • 暂时不用 Java：加 --fake-backend。

② 找不到 jar（未构建计算服务）

原因：找到了 Java，但 services/calc-engine/build/libs/calc-engine-mcp.jar 不存在。config/services.yaml 的启动命令是 java -jar <路径>，CLI 在启动 Java 之前先检查 -jar 后面的文件是否存在，所以不会启动一个马上退出的进程。如果 jar 存在但服务启动后立刻退出，则显示 エラー: サービス calc-engine を起動できませんでした（…）。起動コマンド: …，同样以退出码 2 结束。

解决：构建 jar，然后回到仓库根目录重试。

cd services/calc-engine && JAVA_HOME=$HOME/.local/jdk/21 ./gradlew bootJar -q
ls build/libs/        # 应看到 calc-engine-mcp.jar
cd ../..

③ llm_error：没有凭据（或凭据无效）

原因：默认的 --llm anthropic 需要 Anthropic 凭据。CLI 按 Anthropic SDK 的异常类型把失败分成 4 类，屏幕上的回答直接说明类别和对策；轨迹的 llm_error 事件里有分类 kind 和 SDK 的原始信息：

kind 与屏幕上的回答（开头）轨迹里的 error（例）含义与对策
credentials：Claude API の認証情報が見つからないため、…Claude API の認証情報が見つかりません（ANTHROPIC_API_KEY などを設定してください）没有凭据。export ANTHROPIC_API_KEY=… 或 ant auth login。
auth：Claude API の認証に失敗したため、…ANTHROPIC_API_KEY（または ant auth login のログイン）が有効かを確かめてください。Claude API の認証に失敗しました（HTTP 401）: … 'authentication_error', 'message': 'API key is invalid.' …密钥无效或没有权限（HTTP 401/403，实测用假密钥得到 401）。检查密钥是否复制完整、是否已被撤销。
transient：Claude API が混み合っているか、接続できなかったため、…時間をおいてお試しください。Claude API が一時的なエラーを返しました（HTTP 429）: … / Claude API に接続できませんでした: …限流、过载、服务器暂时错误或网络不通。稍后重试，或检查网络、代理。
other：Claude API の呼び出しに失敗したため、…詳細はトレースの llm_error の行を確かめてください。Claude API がエラーを返しました（HTTP 400）: …其他 API 错误。按轨迹里的原始信息处理。

不想用 Claude 时，可以改用台本模式：--llm scripted --script core/agent/examples/compare_builds.yaml。

④ budget_exceeded：达到费用上限

把每日上限设为 0，就能用台本模式安全地复现（台本模式只用一次性的临时台账，不影响你真实的台账）：

原因：每次调用 AI 之前都会把台账中今天（UTC）和本月（UTC）的合计与上限比较；达到上限就不再调用。台本模式也会检查（见上例）。回答本身就写明是「今日（日次）」还是「今月（月次）」的上限、已用金额 / 上限、何时恢复，以及用哪个环境变量或 config/budget.yaml 的哪个键修改。

解决：

  • 等到 UTC 换日（北京时间每天 8:00）或下个月（UTC）。
  • 确有需要时临时调高：export ECHOLAB_DAILY_USD=2.00（每月上限用 ECHOLAB_MONTHLY_USD）。
  • 检查是否误用了别的台账：ECHOLAB_LEDGER 是否指向了意外的文件。台账某一行无法解析时，程序不会跳过它，而是以退出码 2 停止，并报出文件和行号（见 ⑦）。

⑤ 工具输入错误（通常会自动纠正）

AI 调用工具时如果参数不对（缺字段、超范围、rules 和 banner 同时给或都不给等），计算服务不会停止，而是把错误信息作为结果交回 AI，让它改正后重新调用。下面的运行中，第一次调用漏了 rules，第二次补上后成功：

（my-toolerr.yaml 是复现用的台本，内容取自评估用例 tool-error-recovery。）

参数不满足工具的输入规格（JSON Schema）时，网关在调用工具之前就把错误交回 AI，信息是日语并带字段路径，例如 入力が不正です: pulls: 20000 は最大値 10000 より大きい値です、入力が不正です: (全体): 必須の項目がありません: pulls。

怎么看出来：出典 ID 是 c2.probability 而不是 c1…——第 1 次调用（c1）失败了。你需要做什么：通常什么都不用做。如果用真实 Claude 时反复出现工具错误、最终没有得到回答，请在问题里把计算所需的条件写全（例如抽卡规则的基础概率、软保底、硬保底等，或明确说用示例卡池）。

⑥ fallback：校验没有通过

（my-fallback.yaml 是复现用的台本，内容取自评估用例 never-corrected。）

原因：AI 的三版草稿都直接写了数字（73.4%、0.734、73%），而不是用占位符引用工具结果。校验器每次都给出类似这样的意见（轨迹的 verdict 事件的 problems）：

数値「73.4%」の出典がありません。ツールの結果は [[出典ID]] で引用し、差や比は比較ツールで計算してください（質問にある数値の引用は可）。

退回 3 次后，EchoLab 宁可不给数字，也不给可能错误的数字。解决：按提示把条件写得更具体后重新提问；问题里写过的数字，回答可以原样引用。

FAQ

为什么它不回答工具范围以外的问题（比如角色强度排行）？

EchoLab 的设计原则是「数字只来自工具」。现在的工具只有：期望伤害（damage.expected）、声骸评分（echo.score）、抽卡概率（gacha.probability_within、gacha.simulate）和比较（compare.diff、compare.ratio）。没有工具能算出的数字，回答里就不能出现——出现了会被校验器退回，最终以 fallback 结束。网关也只允许 domain.yaml 中声明过的工具被调用。详见 能问什么：功能一览。

为什么示例数据是「未確認」？

domains/wuwa/data 中的数值是人工整理的示例值，未经与游戏官方数据核对，标为 verified: false。它们仍然可以用于计算，但只要计算用到了它们，回答末尾就一定会加上 ※ この回答の数値の一部は、未確認のサンプルデータに基づいています。，出典表的「未確認データ」列也会写出具体是哪条数据（如 gacha_rules:featured-character）。想得到不依赖示例数据的结果，就在问题里写全所有参数。

用一次要花多少钱？

台本模式（--llm scripted）和评估的默认模式不花钱，状态行显示 費用: $0.0000。真实 Claude 模式按 token 计费，config/budget.yaml 中 claude-opus-5-5 的单价是每百万 token 输入 4.00 美元、输出 20.00 美元（缓存读取 0.20、缓存写入 5.00）。每次运行的实际费用显示在状态行，并逐次记入 .echolab/costs.jsonl；默认每天 1 美元、每月 10 美元封顶。详见 成本上限与数据可信度。

我的问题会被发送到哪里？

只有在 --llm anthropic（默认）模式下，问题、系统提示、工具定义和工具的计算结果会发送给 Anthropic 的 API。台本模式完全在本机运行，计算服务也在本机以子进程运行。另外，每次运行的问题和全过程会以明文保存在本机 .echolab/traces/ 中（已被 git 忽略）；不需要时可以自行删除。

台本模式下我换了问题，为什么回答一样？

台本模式的工具调用和草稿都由台本文件决定，问题只用于记录和校验（问题里写过的数字允许在回答中引用）。实测把问题换成「こんにちは」，同一台本仍给出同样的比较结果。要让系统理解你的问题，请用真实 Claude 模式。

有图形界面（Web 版）吗？

没有。目前只能通过命令行使用。Web 界面、轨迹回放、评估仪表盘属于路线图 M5，尚未实现。见 今后的功能（路线图）。

不装 JDK 能用吗？

能。加 --fake-backend 就用 Python 参考实现代替 Java 计算服务（它与 Java 实现用同一批黄金用例核对过）。只是假服务不提供蒙特卡洛模拟工具 gacha_simulate。出典表的原始值与 Java 版一样按小数 6 位返回。
