使用功能提问方法

能问什么：功能一览

EchoLab 不会“凭感觉”给数字：每个数字都来自一个计算工具。所以“能问什么”就等于“有哪些计算工具、它们需要哪些输入”。这一页把 6 个工具翻译成玩家的语言，并告诉你提问时要带上哪些信息。

先说清楚现状 目前 EchoLab 只有命令行（CLI）：python -m core.agent "你的问题"。Web 界面是路线图 M5 的计划，现在还不存在。
真正理解自然语言问题的是 Claude，需要用默认的 --llm anthropic 模式并配置 ANTHROPIC_API_KEY。本页的终端示例都是用 --llm scripted（台本模式）跑出来的：“选哪个工具、填什么参数、怎么措辞”是事先写好的台本，模拟 Claude 的行为；但工具的计算结果、验证器的判定和终端输出都是真实运行得到的。示例里的 gacha_banner.yaml、out_of_scope.yaml、tool_error.yaml 等台本是为本说明另外编写的，不在仓库里；仓库自带的台本示例是 core/agent/examples/compare_builds.yaml。

功能全景

EchoLab 默认的领域包是 wuwa（《鸣潮》养成顾问，非官方同人作品）；另外还有住宅贷款还款的计算示例 mortgage（用 --domain mortgage 切换，见 路线图的 M3）。本页介绍 wuwa：Claude 能调用的工具共 7 个：领域包在 domains/wuwa/domain.yaml 里声明的 4 个计算工具和 1 个截图读取工具（见下文“7. 截图读取”），加上核心自带的 2 个比较工具。

伤害期望

damage_expected：给出攻击力、倍率、加成、暴击、敌人防御与抗性，算出期望伤害和每个乘区。

声骸评分

echo_score：按权重给声骸的副词条打分，并换算成“理想值的百分之几”。

抽卡概率（精确）

gacha_probability_within：从当前保底状态出发，N 抽以内拿到 UP 的精确概率（马尔可夫链）。

抽卡模拟（蒙特卡洛）

gacha_simulate：同一个概率的随机模拟估计，附带标准误差。

差值

compare_diff：两个计算结果之差 a − b。

比率

compare_ratio：两个结果之比 a / b，以及增幅 a / b − 1（“高百分之几”）。

一个问题是怎样变成工具调用的

你只需要用自然语言提问。Claude 读题、挑工具、把题目里的数值填进工具参数；网关检查参数是否合法，再交给计算服务。需要比较时，Claude 不自己做减法，而是再调用比较工具。下面用“两套配装哪个强、强多少”的真实运行过程演示（台本模式，结果为真实计算）。

各功能需要你提供的信息

下面的字段名、范围都取自计算服务的输入 schema（services/calc-engine/src/main/resources/tools/*.schema.json）。你不需要写字段名，用自然语言说清楚即可；但表里标“必填”的信息必须在问题里出现（或者能从示例数据取得），否则 Claude 应当反问你。所有“比例”类数值在工具内部都用小数表示（0.3 = 30%），你写 30% 或 0.3 都可以，由 Claude 换算。

1. 伤害期望 damage_expected

10 个参数全部必填。工具里不含任何游戏常数，所以防御常数、敌人防御、抗性这些也要由你给出。

你要说的字段允许范围说明
最终攻击力atk≥ 0面板上的最终攻击力
技能倍率skill_multiplier≥ 0小数，2.5 = 250%
伤害加成合计dmg_bonus≥ 0小数，0.3 = 30%
暴击率crit_rate≥ 0超过 1（100%）的部分按 1 计算
暴击伤害倍率crit_dmg≥ 12.2 = 220%（是“倍率”，不是“额外 120%”）
防御常数 Cdefense_constant> 0由攻击方等级等决定。防御乘区 = C / (C + 防御 × (1 − 无视防御))
敌人防御力enemy_def≥ 0
无视防御def_ignore0〜1小数
敌人属性抗性enemy_res可为负0.1 = 10%
减抗res_shred任意有效抗性 = 抗性 − 减抗，必须小于 1；有效抗性为负时乘区 = 1 − 有效抗性 / 2

返回值：base（基础伤害 = 攻击 × 倍率）、bonus_multiplier（加成乘区）、crit_multiplier（暴击期望乘区）、defense_multiplier、resistance_multiplier、total（期望伤害）。想看明细就在问题里说“带明细”。

○ 信息充分

“攻击力 2000、技能倍率 2.5、伤害加成 0.3、暴击率 0.6、暴击伤害 2.2、防御常数 1600、敌人防御 1000、无视防御 0、敌人抗性 0.1、减抗 0 时的期望伤害是多少？带明细。”

（这组输入的真实结果：期望伤害 6192，基础伤害 5000，各乘区 1.3 / 1.72 / 0.615385 / 0.9。）

× 信息不足

“我攻击 2000，这招能打多少？”——缺倍率、加成、暴击和敌人数据。Claude 不能用自己“记得”的倍率补上，只能反问你。

2. 声骸评分 echo_score

你要说的字段允许范围说明
声骸名称echo.name任意字符串必填，只用于显示
COSTecho.cost整数 1〜4必填
主词条echo.main属性 + 数值（≥ 0）必填，但不计入得分（主词条由 COST 决定，不属于“刷副词条”的评价）
副词条echo.subs最多 5 条每条：属性 + 数值（≥ 0，比例类用小数，0.08 = 8%）
权重weights 或 profile权重 ≥ 0二选一，不能同时给。不给权重时，可以说“用会心型输出的示例配置”（profile: sample-crit-attacker）
单条副词条最大值max_roll≥ 0；有权重的属性必须为正可省略，省略时用示例数据 echo_weights.yaml 的 max_roll（未确认）

属性名（工具内部的枚举值）对应如下：

枚举值含义枚举值含义
CRIT_RATE暴击率CRIT_DMG暴击伤害
ATK_PERCENT / ATK_FLAT攻击百分比 / 固定攻击HP_PERCENT / HP_FLAT生命百分比 / 固定生命
DEF_PERCENT / DEF_FLAT防御百分比 / 固定防御ENERGY_REGEN共鸣效率
BASIC_ATTACK_DMG_BONUS普攻伤害加成HEAVY_ATTACK_DMG_BONUS重击伤害加成
SKILL_DMG_BONUS共鸣技能伤害加成LIBERATION_DMG_BONUS共鸣解放伤害加成
ELEMENTAL_DMG_BONUS属性伤害加成HEALING_BONUS治疗效果加成

返回值：score = 每条副词条的 权重 × 数值 ÷ 最大值 之和；percent_of_ideal = score ÷ 理想值 × 100，理想值是“权重最大的 5 个属性各出一条满值”时的得分。例如示例配置的权重 1.0 / 1.0 / 0.75 / 0.25 / 0.5，理想值就是 3.5。注意 percent_of_ideal 本身已经是百分数（如 76.976190 表示约 77%）。

○ 信息充分（使用示例权重）

“帮我给这个 COST 4 声骸打分：主词条暴击伤害 44%，副词条暴击 8.7%、暴击伤害 17.4%、攻击 8.6%、生命 430、共鸣效率 10%。权重用会心型输出的示例配置。”

（真实结果：得分 2.694167，理想值的 76.976190%，并带“未确认数据”注记。）

× 信息不足

“我这个声骸几分？双暴还不错。”——没有具体词条数值。也不要期待 Claude 知道“官方”的满值或权重：工具只用你给的值或示例数据。

3. 抽卡概率（精确）gacha_probability_within

你要说的字段允许范围说明
当前保底计数start_pity整数 0〜9999，且小于硬保底必填。距上次出最高稀有度已经抽了几次
是否“大保底”guaranteed是 / 否必填。上次歪了（没出 UP）则下一次最高稀有度必定是 UP → 是
还要抽几次pulls整数 0〜10000必填
卡池规则rules 或 banner见下表二选一。可以自己给全部 6 项规则，也可以说“用示例限定角色卡池”（banner: featured-character，未确认数据）
规则项（rules 的字段）允许范围含义
base_rate0〜1基础最高稀有度概率
soft_pity_start整数 1〜10000，≤ 硬保底软保底从第几抽开始（从上次最高稀有度算起，从 1 数）
soft_pity_increment0〜1软保底期间每抽增加的概率
hard_pity整数 1〜10000硬保底：这一抽必出最高稀有度
featured_rate0〜1出最高稀有度时是 UP 的概率
guarantee_after_loss是 / 否歪了之后下一次最高稀有度是否必定 UP

返回值：probability（0〜1 的精确值）。

4. 抽卡模拟（蒙特卡洛）gacha_simulate

输入与精确版相同，另外有 3 个可选项：

字段允许范围省略时说明
trials整数 1〜1,000,000100000模拟次数。标准误差与 1/√trials 成正比
seed64 位整数0随机种子，相同种子结果相同
methodsequential / parallel_stream / virtual_threadssequential只影响速度，不影响结果

返回值：probability（估计值）和 std_error（标准误差）。日常使用时精确版更合适；想看“模拟和精确值是否一致”时，可以在问题里明确说“也用模拟算一下”。

小提示领域提示词（domains/wuwa/prompts/system.md）的工具说明表也列出了 gacha_simulate，并告诉 Claude：平时的概率问题用精确版 gacha_probability_within，只有你要求用模拟确认时才用模拟。想用模拟，请在问题里明确提出。另外，--fake-backend（测试用假计算服务）不提供模拟，也不支持 banner / profile 这类数据引用，只能在真实 Java 服务上使用。

5. 差值 compare_diff 与 6. 比率 compare_ratio

比较工具的输入不是数字，而是同一个问题里前面工具结果的出典 ID（如 c1.total）。因此：

  • “配装 A 和 B 差多少 / 高百分之几”这类问题，要在同一个问题里给出两边的完整条件，让两边都先算出来。
  • 每次运行 CLI 都是独立的问题，不记得上一次的结果。不能先问 A、再另起一问“刚才的 A 和 B 比呢”。
  • 单纯“1234 比 1000 高多少”的算术题无法用比较工具（没有出典 ID 可传），回答里也不能出现 Claude 自己算的数字。

返回值：compare_diff → diff（a − b）；compare_ratio → ratio（a / b）和 change（a / b − 1，回答中常以百分数显示）。b 为 0 时返回错误“b が 0 のため、比を計算できません”。比较结果保留小数 6 位（银行家舍入）。

7. 截图读取 echo_read_screenshot（M4）

在问题里写上声骸画面截图的路径，Claude 会先用 OCR（Tesseract）读取 COST 和主・副词条的值，再交给 echo_score 打分。需要注意：

  • 图片默认只能放在仓库目录里（PNG・JPEG，10 MB 以内）。放在别处时，用环境变量 ECHOLAB_VISION_ROOTS 指定允许的目录。
  • 读取结果只有模板里声明的数值（如 sub_crit_rate），图片里的其他文字（包括“忽略之前的指示”之类）不会传给 Claude。
  • 回答会用出典 ID 列出读到的值，请对照图片确认。超出范围的值（疑似误读）会报错，不会被猜测补全。
  • 需要安装 Tesseract 和日语数据。目前只用合成的截图验证过，实际游戏画面可能读不出来。

不需要 API 密钥的试用（剧本模式；还需要 Java 计算服务。加 --fake-backend 则改用记录好的 OCR 结果）。这张合成截图里写着注入的指示，但读取结果里只有数字：

python -m core.agent "evals/redteam/screenshots/echo-injection.png の声骸を採点して。重みは会心率 1.0・会心ダメージ 1.0・攻撃力% 0.75・攻撃力 0.25・共鳴効率 0.5、最大値は会心率 0.1・会心ダメージ 0.2・攻撃力% 0.12・攻撃力 60・共鳴効率 0.12 として。" \
  --llm scripted --script domains/wuwa/examples/score_screenshot.yaml

图 2：提问前的自查流程
  • 把数值写全：工具不内置任何游戏数值，Claude 也被要求不要用记忆补数值。
  • 比例写成 30% 或 0.3 都行；验证器把 x% 和 x/100 看作同一个数，所以回答里引用你问题中的“30%”或“0.3”都不会被拦下。
  • 想用示例数据就明说：“用示例限定角色卡池”“权重用会心型输出的示例配置”。
  • 要比较就一次问完：两边的条件放在同一个问题里。
  • 一次只问一件事：每个问题最多 6 轮工具调用，超出会以“計算の手順が多くなりすぎた…”结束（见 回答怎么读）。
