理解费用隐私数据

成本上限与数据可信度

用真实的 Claude 回答问题会产生 API 费用。EchoLab 在每次调用 Claude 之前检查日、月两道上限，并把每次调用的费用记进本地台账。本页说明价格、上限、超限时的表现、台账格式，以及你的数据会被发往哪里、哪些数据可以信任。

模型与价格

默认模式（--llm anthropic）使用 claude-opus-5-5。价格表在 config/budget.yaml，单位是每 100 万 token 的美元价格：

模型输入输出缓存读取缓存写入（5 分钟 TTL）用途
claude-opus-5-54.0020.000.205.00默认模型
claude-opus-55.0025.000.506.25服务器端回退（fallback）可能用到
claude-opus-4-85.0025.000.506.25同上

请求开启了服务器端回退（fallbacks: "default"）：当默认模型因安全分类器拒绝时，服务器可能改由其他模型作答。这时 EchoLab 会按每次尝试分别记账（每个模型按自己的价格）。台本模式（--llm scripted）不调用任何 API；台本里没写 usage 时费用为 0。台本若写了模拟的 usage，CLI 会按价格表算出这笔“模拟费用”并显示在状态行，但只记进本次运行专用的临时台账（运行结束即删除），不写入真实台账（评估 python -m core.evals 的台本模式也一样）。

日上限与月上限

上限默认值环境变量配置文件
每日1.00 USDECHOLAB_DAILY_USDconfig/budget.yaml → caps_usd.daily
每月10.00 USDECHOLAB_MONTHLY_USDconfig/budget.yaml → caps_usd.monthly
台账位置.echolab/costs.jsonlECHOLAB_LEDGERconfig/budget.yaml → ledger（相对路径以仓库根目录为基准；只用于 anthropic 模式）
  • 环境变量优先于配置文件。例如只放宽今天这次运行：ECHOLAB_DAILY_USD=2 python -m core.agent "…"。
  • “今天”“本月”按 UTC 划分：北京时间每天 08:00 换日，每月 1 日 08:00 换月。
  • 上限必须是 0 以上的数字。写成 abc 这样的值时，CLI 不调用 Claude，在标准错误输出 エラー: 環境変数 ECHOLAB_DAILY_USD の値「abc」はコストの上限（USD）として使えません。0 以上の数値（例 1.00）を指定してください，以退出码 2 结束（实测；config/budget.yaml 里的值不对时同样报错，并写明是哪个键）。

每次调用 Claude 前后发生了什么

sequenceDiagram
  participant U as 你（CLI）
  participant A as Agent
  participant B as 预算（台账）
  participant C as Claude API
  U->>A: 问题
  loop 每次调用 LLM（一个问题通常 2 次以上）
    A->>B: check()
    B->>B: 汇总台账中今天、本月（UTC）的 usd
    alt 今天 ≥ 日上限 或 本月 ≥ 月上限
      B-->>A: BudgetExceeded
      A-->>U: 固定回答，状态 budget_exceeded
    else 未达上限
      A->>C: 请求（提示词、工具定义、对话）
      C-->>A: 回复和 token 用量
      A->>B: record(model, usage)
      B->>B: 追加一行 JSONL
    end
  end
  A-->>U: 回答和本次费用
图 3：预算检查发生在每一次 LLM 调用之前，而不是每个问题之前

因为检查发生在调用之前，而费用要到调用之后才知道，所以总额可能略微超过上限，超出部分最多是一次调用的费用。超过之后，下一次调用就会被拦下。

达到上限时会看到什么

下面用一个临时台账真实重现（台账里事先写入一行今天 1.000000 美元的记录；台账路径为示例）。这里用默认的 anthropic 模式：预算检查在调用 Claude 之前进行，达到上限就不会调用，所以没有 API key 也能重现。台本模式只用一次性的临时台账，不读 ECHOLAB_LEDGER，因此不能用来重现。

回答的意思是“今天（UTC）的费用达到了每日上限，现在无法回答（已用 1.000000 美元 / 上限 1.00 美元）。UTC 换日后即可使用。上限可以用环境变量 ECHOLAB_DAILY_USD 或 config/budget.yaml 的 caps_usd.daily 修改”。达到的是月上限时，回答会写月上限的金额和设置项（用 ECHOLAB_DAILY_USD=5 ECHOLAB_MONTHLY_USD=0.5 实测得到 今月（UTC）のコストが月次の上限に達したため、今は回答できません（使用額 1.000000 USD / 上限 0.5 USD）。UTC の月が変わると使えるようになります。上限は環境変数 ECHOLAB_MONTHLY_USD か config/budget.yaml の caps_usd.monthly で変えられます。）。同样的信息也记录在执行轨迹的 budget_exceeded 事件里。这时 Claude 一次也没有被调用，费用为 0。回答里的金额来自台账和设置，不是 AI 写的，所以评估统计忠实度时不把它当作无出典的数字。

解决办法：等到 UTC 换日 / 换月；或者有意识地提高上限（环境变量或 config/budget.yaml）。不要为了“清零”而删除台账——它是你实际花费的记录。

台账文件的格式

台账是 JSONL：每次 LLM 调用追加一行。下面是用示例 token 数写入临时台账得到的真实内容：

{"ts": "2026-10-03T02:00:00+00:00", "model": "claude-opus-5-5", "usage": {"input_tokens": 2400, "output_tokens": 180, "cache_creation_input_tokens": 2100, "cache_read_input_tokens": 0}, "usd": "0.0237"}
{"ts": "2026-10-03T02:00:00+00:00", "model": "claude-opus-5-5", "usage": {"input_tokens": 300, "output_tokens": 140, "cache_creation_input_tokens": 0, "cache_read_input_tokens": 2100}, "usd": "0.00442"}
{"ts": "2026-10-03T02:00:00+00:00", "model": "claude-sonnet-x", "usage": {"input_tokens": 2400, "output_tokens": 180, "cache_creation_input_tokens": 2100, "cache_read_input_tokens": 0}, "usd": "0.029625", "estimated": true}
字段含义
ts记录时间（UTC，ISO 8601）。按它划分“今天”“本月”
model实际计费的模型
usage4 类 token 数：输入、输出、缓存写入、缓存读取
usd这次调用的费用，用字符串保存的十进制数（避免浮点误差）
estimated仅当模型不在价格表里时出现，值为 true，见下节
  • 只有 --llm anthropic 的调用会写进这个台账。台本模式的模拟用量只记在每次运行专用的临时台账里，不会出现在 .echolab/costs.jsonl。
  • 如果台账中有读不懂的行，EchoLab 不会跳过（跳过可能导致超支），而是在调用 Claude 之前停止，以退出码 2 结束，并写明文件和行号，例如 エラー: コストの台帳 /tmp/broken.jsonl の 1 行目が読めないため、コストの上限を安全に判定できません（JSONDecodeError: Expecting ',' delimiter: line 1 column 35 (char 34)）。その行を直すか消してください（实测；不打印 Traceback）。请修复或移走那一行。

价格表里没有的模型：保守估算

回退时服务器可能返回价格表里没有的模型。调用已经计费了，所以 EchoLab 仍然记账，但按价格表中最贵的模型估算，并标记 "estimated": true。上面第 3 行就是例子：同样的 token 数，按 claude-opus-5-5 是 $0.0237，而未知模型按最贵的价格估为 $0.029625。这样上限判断只会偏严，不会偏松。（单纯“查询价格”时则不做推测：Budget.cost() 对未知模型报错 料金表に無いモデルです（config/budget.yaml に追加してください）。）如果你经常遇到某个新模型，把它的价格加进 config/budget.yaml 的 pricing_usd_per_mtok 即可。

数据可信度：已确认与示例

计算服务的公式由 Java 与 Python 两套实现对同一批黄金用例交叉验证；但游戏数值是否准确，取决于输入从哪里来：

输入来源可信度回答中的表现
你在问题里给出的数值与你给的数一样可信无注记；出典表“未確認データ”为 -
示例数据 verified: false（目前全部数据都是这种）作者手工整理的示例值，source 为 "TODO: 要確認"，不是官方数值自动附加注记 ※ この回答の数値の一部は、未確認のサンプルデータに基づいています。，出典表列出 gacha_rules:featured-character、echo_weights:sample-crit-attacker、echo_weights:max_roll 等 ID
