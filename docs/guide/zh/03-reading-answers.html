使用输出验证

回答怎么读

EchoLab 的 CLI 每次输出 4 部分：回答正文、（必要时的）未确认注记、出典表、状态行。读懂它们，你就能自己核对“这个数字从哪里来、可信到什么程度”。

关于语言回答正文使用你提问的语言（由 Claude 决定）；但 CLI 固定输出的部分——“出典”“状態”“差し戻し”“費用”“トレース”等标签、未确认注记、以及失败时的固定回答——目前都是日文。本页逐一给出中文对照。本页的示例都来自真实运行（--llm scripted 台本模式模拟 Claude 的措辞，计算、验证与输出为真实结果；命令中的 gacha_banner.yaml、compare_zh.yaml、never_corrected.yaml 是为本说明编写的台本，不在仓库里）。

数字是怎样格式化的

Claude 写的回答其实是一个模板：数字的位置写成占位符 [[出典ID]] 或 [[出典ID|格式]]，由渲染器（core/verifier/render.py）把原值按格式换成文字。规则：

  • 不写格式：最多 2 位小数，去掉末尾的 0 和小数点。
  • |N（N 为 0〜9）：固定 N 位小数。
  • |%N：乘以 100，固定 N 位小数，再加 %。
  • 整数部分每 3 位加逗号；舍入方式是银行家舍入（ROUND_HALF_EVEN，正好一半时取偶数）；不会显示“-0”。

正文和出典表的数字不一样？这是正常的：出典表显示原值（如 0.7546548474342011），正文显示格式化后的值（如 75.5%）。需要更多位数时，可以在问题里说“保留两位小数”之类，由 Claude 选择格式。

“未确认”注记意味着什么

注记的原文是 ※ この回答の数値の一部は、未確認のサンプルデータに基づいています。，意思是“此回答中的部分数值基于未经确认的示例数据”。它不是 Claude 写的，而是渲染器在下面这种情况下自动追加的：回答引用的出典里，至少有一个的“未確認データ”列不是 -。

  • 你在问题里给出全部数值（如伤害计算、自己给出卡池规则）→ 没有注记。
  • 引用示例卡池 featured-character、示例权重 sample-crit-attacker，或省略声骸的 max_roll → 有注记。

计算本身是正确的；“未确认”指的是输入的游戏数值没有经过出处核对，可能与游戏实际不符。详见 成本上限与数据可信度。

草稿被退回（差し戻し）是怎么回事

Claude 的每份回答草稿都要先过验证器（core/verifier/verify.py）。验证器检查：

  1. 占位符格式正确，且出典 ID 是本问题里真实发出的；
  2. 去掉占位符后，正文里出现的每个数字都属于下列之一：你问题里的数字（忽略千位逗号，x% 与 x/100 视为相同）；行首的列表序号（1.、2)）；10 以下的整数后面紧跟助数词：日文的“つ・点・種類・位・番目”、中文的“个・种・项・条・步”，或英文名词 ways・points・steps・options・items・reasons・types・kinds・parts・things・tools・builds（中间最多一个空格）。

退回 3 次后的固定回答

默认最多让 Claude 重写 2 次（DEFAULT_MAX_RETRIES = 2）。第 3 次退回时，EchoLab 放弃这份回答，改为输出一段不含任何数字的固定文字，状态为 fallback，退出码为 1：

固定回答的意思：“抱歉，由于未能生成可核实计算结果出处的回答，暂不提供含数值的回答。请把条件写得更具体后再问一次。”这次运行里 3 份草稿分别是“概率大约是 73.4%。”“概率是 0.734。”“概率约为 73%（[[c1.probability|%1]]）。”——第 3 份虽然用了占位符，但同时写了无出典的“73%”，仍然不合格。

状态一览

只有 answered 的退出码是 0，其余都是 1。除 answered 外，回答正文都是下面的固定日文文字（不含数字）。具体原因写在执行轨迹里。
