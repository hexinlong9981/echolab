背后发生了什么（动画）

你按下回车之后，EchoLab 在几秒内做了十几件事。本页用一次真实运行留下的执行轨迹，一步一步演示：问题怎样变成计算、计算结果怎样变成“出典 ID”、写错的草稿怎样被退回，以及为什么最终答案里的每个数字都可以追溯。

一句话版本Claude（AI）只负责“理解问题、决定调用哪个计算工具、组织语言”；答案里的每一个数字都来自确定性的计算工具。Claude 写答案时不能直接写数字，只能写 [[c1.total]] 这样的“引用”，最后由程序把真实数值填进去。

为什么这样数字就可信

① AI 没有“写数字”的通道

Claude 的最终输出只是模板，数字位置只能写 [[出典ID]]。真正的数字由渲染器程序填进去，不存在抄错、四舍五入不一致的问题。

② 每个数字都有出处

出典 ID 由网关按“第几次调用.哪个字段”编号，答案下方的出典表告诉你每个数来自哪个工具。

③ 验证器逐字检查

草稿里出现的任何来历不明的数字（包括 AI 心算的差值、“约 73%”这样的估算）都会被退回。

④ 改不好就不给数字

最多允许退回改写 2 次；第 3 份草稿仍不合格时，EchoLab 返回一段不含任何数字的固定说明，而不是一个可疑的答案。

⑤ 只能用登记过的工具

网关只放行领域包里登记的工具（默认拒绝），并在调用前检查输入格式。

⑥ 示例数据会被标出

如果数值依赖尚未确认的示例数据，答案末尾会自动附上注记：※ この回答の数値の一部は、未確認のサンプルデータに基づいています。

⑦ 全程留痕

每次提问都会写下一份执行轨迹，事后可以逐条核对。见执行轨迹与评估。

验证器允许哪些“裸数字”

占位符以外的正文中，只有下面这些数字可以直接出现（全角数字会先转成半角再比较）：

允许的情况例子说明
引用你问题里出现过的数字“攻撃力 2000 のとき…”忽略千位分隔符；60% 和 0.6 视为相同
行首的列表序号1.、2)、３．小数（如 1.5）不算序号
10 以下的整数 + 特定量词“3 つの方法”日语的 つ・点・種類・位・番目、中文的 个・种・项・条・步，以及英文名词 ways・points・steps・options・items・reasons・types・kinds・parts・things・tools・builds（紧跟在数字后面，中间最多一个空格）
量词白名单也包括中文和英文回答用你提问的语言书写，所以中文回答里的“3 种方法”“2 个要点”、英文回答里的“3 ways”“2 points”同样被允许。英文名词必须紧跟在数字后面，像“2 key points”这样中间隔了别的词就会被退回。超过 10 的数仍然必须来自工具或问题。

其他结束方式

上面是正常结束（状态 answered）。遇到下列情况，EchoLab 会给出不含数字的固定说明并在轨迹里记下状态：

状态什么时候
fallback草稿被退回超过 2 次仍未改好
budget_exceeded达到每日或每月的成本上限（调用 Claude 前检查，不会产生费用）
tool_round_limit工具调用的往返超过 6 轮
llm_error调用 Claude 失败，例如没有设置 API 密钥
refusal / max_tokens模型的安全机能拒绝回答 / 回答过长被截断（这两种情况不会执行半截的工具调用）
