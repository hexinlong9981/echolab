使い方出力検証

回答の読み方

EchoLab の CLI は毎回 4 つの部分を出力します。回答本文、（必要なときの）未確認のデータの注記、出典の表、状態の行です。これらが読めれば、「この数字はどこから来て、どこまで信頼できるか」をご自分で確かめられます。

このページの例についてこのページの例はすべて実際の実行から取っています。--llm scripted（台本モード）で Claude の書きぶりを模していますが、計算・検証・出力は実際の結果です。コマンドに出てくる gacha_banner.yaml と never_corrected.yaml はこのガイド用に書いた台本で、リポジトリには含まれていません。回答本文は質問と同じ言語で書かれます（Claude が判断します）。一方、「出典」「状態」「差し戻し」「費用」「トレース」などのラベル、未確認のデータの注記、失敗したときの定型の回答は、CLI が決まった日本語の文で出力します。

出力の構成

「サンプルの限定キャラクターガチャで、いまの天井カウントは 30、すり抜け確定なし。あと 100 回以内にピックアップキャラクターが出る確率は？」に対する実際の出力（実際の Java 計算サービス）に、番号を付けて示します。

  1. 回答本文：検証に通り、レンダラが数字を埋めた回答です。本文の数字はどれも、計算ツールから来たものか、質問に書かれていた数です（ここでは「30」と「100」が質問からの引用です）。
  2. 未確認のデータの注記：回答が引用した結果のうち 1 つでも verified: false のデータを使っていれば、自動で付きます。
  3. 出典の表：回答が実際に引用した値の一覧です。次の節で説明します。
  4. 状態の行：状態、差し戻し（下書きが差し戻された回数）、費用（今回 LLM を呼んだ費用。ドル単位で、台本モードではふつう 0）、実行 ID。
  5. 実行トレースのファイル：今回の実行の各ステップを記録した JSONL で、手元の .echolab/traces/ に保存されます。詳しくは実行トレースと評価をご覧ください。

数字の書式

Claude が書く回答は、実はテンプレートです。数字の位置にはプレースホルダ [[出典ID]] または [[出典ID|書式]] を書き、レンダラ（core/verifier/render.py）が元の値を書式に従って文字に置き換えます。規則は次のとおりです。

  • 書式なし：小数点以下最大 2 桁で、末尾の 0 と小数点は省きます。
  • |N（N は 0〜9）：小数点以下 N 桁に固定します。
  • |%N：100 倍して小数点以下 N 桁に固定し、% を付けます。
  • 整数部は 3 桁ごとにカンマで区切ります。丸めは銀行丸め（ROUND_HALF_EVEN。ちょうど半分のときは偶数側へ）で、「-0」は表示しません。

次の表の「表示結果」は、実際のレンダラ format_value() で計算したものです。

元の値（出典の表の「値」）プレースホルダの書き方表示結果

6192.000000[[c1.total|0]]6,192

0.615385[[c1.defense_multiplier]]0.62

本文と出典の表で数字が違う？これは正常です。出典の表は元の値（例：0.7546548474342011）を、本文は書式を整えた値（例：75.5%）を表示します。もっと細かい桁が必要なら、質問に「小数第 2 位まで」などと書けば、Claude が書式を選びます。

「未確認」の注記の意味

注記の文は ※ この回答の数値の一部は、未確認のサンプルデータに基づいています。 です。これはClaude が書いたものではなく、次の場合にレンダラが自動で追加します：回答が引用した出典のうち、少なくとも 1 つの「未確認データ」列が - ではないとき。

  • 数値をすべて質問で与えた場合（ダメージ計算、ガチャのルールを自分で指定した場合など）→ 注記なし。
  • サンプルのガチャ featured-character やサンプルの重み sample-crit-attacker を参照した場合、または声骸の max_roll を省略した場合 → 注記あり。

計算そのものは正しく行われています。「未確認」とは、入力したゲームの数値の出典が確認されておらず、実際のゲームと異なる可能性があるという意味です。詳しくはコストの上限とデータの確かさをご覧ください。

下書きの差し戻しとは

Claude の回答の下書きは、まず検証器（core/verifier/verify.py）を通ります。検証器は次の点を確かめます。

  1. プレースホルダの形式が正しく、出典 ID がその質問の中で実際に発行されたものであること。
  2. プレースホルダを除いた本文に出てくる数字が、どれも次のいずれかであること：質問に書かれた数字（桁区切りのカンマは無視し、x% と x/100 は同じとみなす）、行頭の箇条書きの番号（1.、2)）、10 以下の整数の直後に助数詞が続くもの（日本語の「つ・点・種類・位・番目」、中国語の「个・种・项・条・步」、英語の名詞 ways・points・steps・options・items・reasons・types・kinds・parts・things・tools・builds。間の空白は 1 つまで）。

不合格の下書きは問題点の一覧とともに Claude へ返され、書き直しになります。これが状態の行の「差し戻し: N 回」です。次のアニメーションは、実際の実行トレース 20261003T024449Z-4423a9.jsonl に沿って「差し戻し → 修正」を再現したものです。

小さな個数はそのまま書けます「2 つのポイント」のように、10 以下の整数の直後に助数詞（日本語の つ・点・種類・位・番目、中国語の 个・种・项・条・步）が続く場合は、出典がなくてもそのまま書けます。英語で答える場合は、ways・points・steps・options・items・reasons・types・kinds・parts・things・tools・builds の名詞が数字の直後に続くときだけ許されます。たとえば 2 つの要点：[[c1.total]]、有 2 个要点：[[c1.total]]、There are 2 points: [[c1.total]] は合格しますが、There are 2 key points: [[c1.total]] は、数字と名詞の間に別の語があるため「2」が出典のない数字として差し戻されます。また 10 を超える数は、助数詞が付いていても差し戻されます。

3 回差し戻されたときの定型の回答

既定では、Claude に書き直させるのは最大 2 回です（DEFAULT_MAX_RETRIES = 2）。3 回目の差し戻しで EchoLab はその回答をあきらめ、数字を一切含まない定型の文を出力します。状態は fallback、終了コードは 1 です。

この実行での 3 つの下書きは、それぞれ「確率はおよそ 73.4% です。」「確率は 0.734 です。」「確率は約 73%（[[c1.probability|%1]]）です。」でした。3 つ目はプレースホルダを使っていますが、出典のない「73%」も書いているため、やはり不合格になります。

状態の一覧

終了コードが 0 になるのは answered だけで、ほかはすべて 1 です。answered 以外では、回答本文は次の決まった文（数字を含まない）になります。詳しい原因は実行トレースに記録されます。

状態発生するとき定型の回答
answered下書きが検証に通った（Claude の回答。数字を含まないこともあります）
fallback下書きが 3 回目の差し戻しを受けた申し訳ありません。計算結果の出典を確かめられる回答を作れなかったため、数値を含む回答は控えます。条件を具体的にして、もう一度質問してください。
budget_exceededその日またはその月の費用が上限に達している。使用額と上限、使えるようになる時期、変更に使う環境変数と設定キーが示されます（月の上限の場合は「今月…月次…ECHOLAB_MONTHLY_USD」となります）。コストの上限とデータの確かさを参照今日（UTC）のコストが日次の上限に達したため、今は回答できません（使用額 1.02 USD / 上限 1.00 USD）。UTC の日付が変わると使えるようになります。上限は環境変数 ECHOLAB_DAILY_USD か config/budget.yaml の caps_usd.daily で変えられます。
refusalモデルの安全機能が応答を止めたこの質問には回答できませんでした（モデルの安全機能により応答が止まりました）。
max_tokens応答が長すぎて途中で切れた応答が長くなりすぎて途中で切れたため、回答を完成できませんでした。質問を分けてお試しください。
tool_round_limitツールの呼び出しが 6 ラウンドを超えた計算の手順が多くなりすぎたため、回答を完成できませんでした。質問を分けてお試しください。
llm_errorClaude API の呼び出しに失敗した（認証情報がない）Claude API の認証情報が見つからないため、回答できませんでした。環境変数 ANTHROPIC_API_KEY を設定する（または ant auth login でログインする）か、API キーの要らない台本モード（--llm scripted）をお使いください。
llm_error認証に失敗した（HTTP 401/403）Claude API の認証に失敗したため、回答できませんでした。ANTHROPIC_API_KEY（または ant auth login のログイン）が有効かを確かめてください。
llm_errorレート制限・過負荷・ネットワークの問題Claude API が混み合っているか、接続できなかったため、回答できませんでした。時間をおいてお試しください。
llm_errorその他の API エラーClaude API の呼び出しに失敗したため、回答できませんでした。詳細はトレースの llm_error の行を確かめてください。
llm_error の回答は原因ごとに変わりますCLI は Anthropic SDK の例外の種類で原因を分類し、「時間をおいてお試しください」と案内するのはレート制限・過負荷・ネットワークの問題のときだけです。認証情報がない、または認証に失敗したときは、ANTHROPIC_API_KEY を設定するよう直接案内します（認証情報がない状態で実測すると、上の表の 1 つ目が表示されました）。実行トレースの llm_error イベントには、分類 kind（credentials・auth・transient・other）と SDK の元のエラーメッセージも記録されます。トラブルシューティングと FAQを参照してください。
