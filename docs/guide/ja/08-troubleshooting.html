トラブルシューティングと FAQ

このページの問題はすべて、実際の環境で再現を確かめたものです。まず「症状」の出力があなたの画面と一致するかを確かめ、次に「原因」「対処」に沿って進めてください。

設定や起動でエラーが起きた場合、状態行は出ません。CLI は標準エラーに エラー: … を 1 行出して原因と直し方を示し、終了コード 2 で終わります。Traceback は表示しません（必要なら --debug を付けます）。状態行がある場合は、画面の回答に原因の種類が書かれています。さらに詳しい情報は実行トレースにあります。共通の確認方法：

# 実行 ID は状態行にあります。置き換えて実行してください
grep -E 'llm_error|budget_exceeded|verdict|tool_result' .echolab/traces/<実行 ID>.jsonl

① java が見つからない

原因：--fake-backend を付けていないので CLI は Java の計算サービスを起動しようとしますが、PATH に java がなく、JAVA_HOME も設定されていません（CLI は子プロセスを起動する前にこれを確認します）。WSL では、Windows 側に入れた Java はふつう Linux 側からそのままでは使えません。

対処（どれか 1 つ）：

  • JAVA_HOME を JDK 21 に向けます：export JAVA_HOME=$HOME/.local/jdk/21（実際のインストール先に合わせてください）。CLI は自動で $JAVA_HOME/bin/java を使います。
  • または JDK 21 の bin を PATH に追加します。
  • 当面 Java を使わない場合は、--fake-backend を付けます。

② jar が見つからない（計算サービスが未ビルド）

原因：Java は見つかりましたが、services/calc-engine/build/libs/calc-engine-mcp.jar がありません。config/services.yaml の起動コマンドは java -jar <パス> で、CLI は Java を起動する前に -jar の後ろのファイルがあるかを確かめるので、すぐに終了してしまうプロセスを起動することはありません。jar はあるのにサービスが起動直後に終了した場合は、エラー: サービス calc-engine を起動できませんでした（…）。起動コマンド: … と表示され、やはり終了コード 2 で終わります。

対処：jar をビルドしてから、リポジトリのルートに戻ってやり直します。

cd services/calc-engine && JAVA_HOME=$HOME/.local/jdk/21 ./gradlew bootJar -q
ls build/libs/        # calc-engine-mcp.jar があれば OK
cd ../..

③ llm_error：認証情報がない（または無効）

原因：既定の --llm anthropic には Anthropic の認証情報が必要です。CLI は Anthropic SDK の例外の種類によって失敗を 4 つに分類し、画面の回答で種類と対処法を直接示します。トレースの llm_error イベントには分類 kind と SDK の元のメッセージが記録されます：

kind と画面の回答（冒頭）トレースの error（例）意味と対処
credentials：Claude API の認証情報が見つからないため、…Claude API の認証情報が見つかりません（ANTHROPIC_API_KEY などを設定してください）認証情報がありません。export ANTHROPIC_API_KEY=… または ant auth login を実行します。
auth：Claude API の認証に失敗したため、…ANTHROPIC_API_KEY（または ant auth login のログイン）が有効かを確かめてください。Claude API の認証に失敗しました（HTTP 401）: … 'authentication_error', 'message': 'API key is invalid.' …キーが無効か、権限がありません（HTTP 401/403。偽のキーで実測すると 401）。キーを最後までコピーできているか、失効していないかを確かめます。
transient：Claude API が混み合っているか、接続できなかったため、…時間をおいてお試しください。Claude API が一時的なエラーを返しました（HTTP 429）: … / Claude API に接続できませんでした: …レート制限、過負荷、サーバの一時的なエラー、またはネットワークの不通です。時間をおいてやり直すか、ネットワークやプロキシを確認します。
other：Claude API の呼び出しに失敗したため、…詳細はトレースの llm_error の行を確かめてください。Claude API がエラーを返しました（HTTP 400）: …その他の API エラーです。トレースにある元のメッセージに従って対処します。

Claude を使わない場合は、台本モードに切り替えられます：--llm scripted --script core/agent/examples/compare_builds.yaml。

④ budget_exceeded：コストの上限に到達

日次の上限を 0 にすれば、台本モードで安全に再現できます（台本モードは使い捨ての一時台帳しか使わないので、本物の台帳には影響しません）：

原因：AI を呼ぶ前に毎回、台帳にある今日（UTC）と今月（UTC）の合計を上限と比べ、上限に達していれば呼び出しません。台本モードでも確認は行われます（上の例）。回答には、どちらの上限（日次か月次か）に達したか、使用額と上限、いつ使えるようになるか、どの環境変数または config/budget.yaml のどのキーで変えられるかが書かれています。

対処：

  • UTC の 0 時（日本時間の 9 時）に日付が変わるか、翌月（UTC）になるのを待ちます。
  • どうしても必要なときは一時的に引き上げます：export ECHOLAB_DAILY_USD=2.00（月次の上限は ECHOLAB_MONTHLY_USD）。
  • 別の台帳を誤って使っていないか確かめます：ECHOLAB_LEDGER が意図しないファイルを指していないか。台帳に読めない行があると、プログラムはその行を読み飛ばさず、終了コード 2 で止まってファイル名と行番号を示します（⑦を参照）。

⑤ ツールの入力エラー（ふつうは自動で直る）

AI がツールを呼ぶときに引数が正しくない場合（項目の不足、範囲外の値、rules と banner を両方指定した・どちらも指定しなかった、など）、計算サービスは止まらず、エラーメッセージを結果として AI に返し、直してから呼び直させます。次の実行では、1 回目の呼び出しで rules が抜けており、2 回目で補って成功しています：

（my-toolerr.yaml は再現用の台本で、内容は評価ケース tool-error-recovery から取っています。）

引数がツールの入力仕様（JSON Schema）を満たさない場合は、ゲートウェイがツールを呼ぶ前にエラーを AI に返します。メッセージは日本語で、項目のパスが付きます。例：入力が不正です: pulls: 20000 は最大値 10000 より大きい値です、入力が不正です: (全体): 必須の項目がありません: pulls。

見分け方：出典 ID が c1… ではなく c2.probability になっています。1 回目の呼び出し（c1）が失敗したということです。あなたがすること：ふつうは何もありません。本物の Claude でツールのエラーが繰り返され、最終的に回答が得られない場合は、計算に必要な条件を質問の中にすべて書いてください（ガチャのルールなら基本確率、ソフト天井、ハード天井など。またはサンプルのガチャを使うと明記します）。

⑥ fallback：検証に合格しなかった

（my-fallback.yaml は再現用の台本で、内容は評価ケース never-corrected から取っています。）

原因：AI の 3 つの下書きがどれも、プレースホルダでツールの結果を引用せず、数値（73.4%、0.734、73%）を直接書いていました。検証器は毎回、次のような指摘を返しています（トレースの verdict イベントの problems）：

数値「73.4%」の出典がありません。ツールの結果は [[出典ID]] で引用し、差や比は比較ツールで計算してください（質問にある数値の引用は可）。

3 回差し戻されると、EchoLab は誤っているかもしれない数値を出すよりも、数値を出さないことを選びます。対処：案内に従って条件をより具体的にし、もう一度質問してください。質問に書いた数値は、回答でそのまま引用できます。

FAQ

ツールの範囲外の質問（キャラクターの強さランキングなど）に答えないのはなぜですか？

EchoLab の設計方針は「数値はツールからしか出さない」です。現在あるツールは、期待ダメージ（damage.expected）、声骸スコア（echo.score）、ガチャの確率（gacha.probability_within、gacha.simulate）、比較（compare.diff、compare.ratio）だけです。ツールで計算できない数値は回答に出せず、出せば検証器に差し戻されて、最終的に fallback で終わります。ゲートウェイも、domain.yaml で宣言されたツールしか呼ばせません。詳しくは何を聞けるか：機能一覧をご覧ください。

サンプルデータが「未確認」なのはなぜですか？

domains/wuwa/data の数値は手作業でまとめたサンプル値で、ゲームの公式データとはまだ照合しておらず、verified: false になっています。計算には使えますが、計算でそれを使った場合は必ず回答の末尾に ※ この回答の数値の一部は、未確認のサンプルデータに基づいています。 が付き、出典表の「未確認データ」の列にも具体的にどのデータか（gacha_rules:featured-character など）が示されます。サンプルデータに頼らない結果がほしい場合は、質問の中ですべてのパラメータを指定してください。

1 回使うといくらかかりますか？

台本モード（--llm scripted）と評価の既定のモードは費用がかからず、状態行には 費用: $0.0000 と表示されます。本物の Claude のモードはトークン単位の課金で、config/budget.yaml の claude-opus-5-5 の単価は 100 万トークンあたり入力 4.00 ドル、出力 20.00 ドル（キャッシュ読み取り 0.20、キャッシュ書き込み 5.00）です。実行ごとの実際の費用は状態行に表示され、1 回ずつ .echolab/costs.jsonl に記録されます。既定では 1 日 1 ドル、1 か月 10 ドルが上限です。詳しくはコストの上限とデータの確かさをご覧ください。

質問はどこへ送られますか？

--llm anthropic（既定）のモードのときだけ、質問、システムプロンプト、ツール定義、ツールの計算結果が Anthropic の API に送られます。台本モードは完全に手元のマシンで動き、計算サービスも手元で子プロセスとして動きます。なお、実行ごとの質問と処理の全体は、手元の .echolab/traces/ に平文で保存されます（Git の無視対象）。不要になったら自分で削除できます。

台本モードで質問を変えたのに、回答が同じなのはなぜですか？

台本モードでは、ツールの呼び出しも下書きも台本ファイルで決まっており、質問は記録と検証にしか使いません（質問に書いた数値は回答での引用が許されます）。実測でも、質問を「こんにちは」に変えても、同じ台本からは同じ比較結果が返りました。質問の内容を理解させたい場合は、本物の Claude のモードを使ってください。

画面で操作できる版（Web 版）はありますか？

ありません。現在はコマンドラインからのみ使えます。Web の画面、トレースの再生、評価のダッシュボードはロードマップの M5 で予定しているもので、まだ実装されていません。今後の機能（ロードマップ）をご覧ください。

JDK を入れなくても使えますか？

使えます。--fake-backend を付けると、Java の計算サービスの代わりに Python の参照実装を使います（Java の実装と同じゴールデンケースで照合済みです）。ただし、この試験用のサービスにはモンテカルロ法のシミュレーションのツール gacha_simulate がありません。出典表の元の値は、Java 版と同じく小数 6 桁で返ります。
