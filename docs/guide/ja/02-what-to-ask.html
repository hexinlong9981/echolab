使い方機能質問のしかた

何を聞けるか：機能一覧

EchoLab は「なんとなく」で数字を出しません。どの数字も、いずれかの計算ツールから来ています。つまり「何を聞けるか」は「どんな計算ツールがあり、それぞれに何を入力する必要があるか」と同じです。このページでは 6 つのツールをプレイヤーの言葉で説明し、質問に含めるべき情報を紹介します。

はじめに現状を確認します 現在の EchoLab はコマンドライン（CLI）のみです：python -m core.agent "質問"。Web 画面はロードマップ M5 の計画で、まだ存在しません。
自然文の質問を実際に理解するのは Claude で、既定の --llm anthropic モードと ANTHROPIC_API_KEY の設定が必要です。このページのターミナルの例は、すべて --llm scripted（台本モード）で実行しています。「どのツールを選び、どの引数を入れ、どう書くか」はあらかじめ用意した台本で、Claude の振る舞いを模したものです。一方、ツールの計算結果、検証器の判定、ターミナルの出力は実際に実行して得たものです。例に出てくる gacha_banner.yaml、out_of_scope.yaml、tool_error.yaml などの台本はこのガイド用に別途書いたもので、リポジトリには含まれていません。リポジトリ付属の台本の例は core/agent/examples/compare_builds.yaml です。

機能の全体像

現在の EchoLab にあるドメインパックは wuwa（『鳴潮』の育成アドバイザー、非公式のファン作品）の 1 つだけです。Claude が呼べるツールは全部で 6 つで、ドメインパックが domains/wuwa/domain.yaml で宣言している 4 つの計算ツールと、コアに組み込まれた 2 つの比較ツールです。

mindmap
  root((EchoLab で計算できること))
    期待ダメージ
      damage_expected
      合計の期待ダメージ
      乗算区分ごとの明細
    声骸のスコア
      echo_score
      重み付きスコア
      理想値に対する割合
    ガチャ確率 厳密
      gacha_probability_within
      N 回以内にピックアップを得る確率
    ガチャのシミュレーション モンテカルロ

      確率の推定値と標準誤差
    比較
      compare_diff 差
      compare_ratio 比と増加率
図 1：6 つのツール。最初の 4 つは Java の計算サービス calc-engine が、比較ツールは Python のコアが計算します

期待ダメージ

damage_expected：攻撃力、倍率、バフ、会心、敵の防御と耐性から、期待ダメージと各乗算区分を求めます。

声骸のスコア

echo_score：声骸のサブステータスを重みに従って採点し、「理想値の何 %」かに換算します。

ガチャ確率（厳密）

gacha_probability_within：現在の天井の状態から、N 回以内にピックアップを獲得できる厳密な確率（マルコフ連鎖）。

ガチャのシミュレーション（モンテカルロ）

gacha_simulate：同じ確率をランダムなシミュレーションで推定し、標準誤差も示します。

差

compare_diff：2 つの計算結果の差 a − b。

比

compare_ratio：2 つの結果の比 a / b と、増加率 a / b − 1（「何 % 高いか」）。

質問がツールの呼び出しになるまで

質問は自然な文章で書くだけでかまいません。Claude が質問を読み、ツールを選び、質問中の数値をツールの引数に入れます。ゲートウェイが引数の妥当性を確かめてから、計算サービスに渡します。比較が必要なときも、Claude は自分で引き算をせず、比較ツールを呼びます。以下では「2 つのビルドのどちらが、どれだけ強いか」を実際に実行した過程で説明します（台本モード、計算結果は実際のものです）。

機能ごとに必要な情報

以下のフィールド名と範囲は、計算サービスの入力スキーマ（services/calc-engine/src/main/resources/tools/*.schema.json）から取っています。フィールド名を書く必要はなく、自然な文章で伝えれば十分です。ただし表で「必須」とある情報は質問に含めてください（またはサンプルデータから取れる必要があります）。足りなければ Claude が聞き返します。「割合」の数値はツール内部ではすべて小数（0.3 = 30%）で扱います。30% と書いても 0.3 と書いてもかまいません。換算は Claude が行います。

1. 期待ダメージ damage_expected

10 個の引数はすべて必須です。ツールにはゲームの定数が一切含まれていないため、防御定数、敵の防御、耐性なども質問で指定してください。

伝える内容フィールド許される範囲説明
最終攻撃力atk≥ 0ステータス画面の最終的な攻撃力
スキル倍率skill_multiplier≥ 0小数。2.5 = 250%
ダメージバフの合計dmg_bonus≥ 0小数。0.3 = 30%
会心率crit_rate≥ 01（100%）を超えた分は 1 として計算
会心ダメージ倍率crit_dmg≥ 12.2 = 220%（「倍率」であり、「追加で 120%」ではありません）
防御定数 Cdefense_constant> 0攻撃側のレベルなどで決まります。防御の乗算区分 = C / (C + 防御 × (1 − 防御無視))
敵の防御力enemy_def≥ 0
防御無視def_ignore0〜1小数
敵の属性耐性enemy_res負の値も可0.1 = 10%
耐性ダウンres_shred任意実効耐性 = 耐性 − 耐性ダウン。1 未満である必要があります。実効耐性が負のときは乗算区分 = 1 − 実効耐性 / 2

戻り値：base（基礎ダメージ = 攻撃力 × 倍率）、bonus_multiplier（バフの乗算区分）、crit_multiplier（会心の期待値の乗算区分）、defense_multiplier、resistance_multiplier、total（期待ダメージ）。明細を見たいときは、質問に「明細つきで」と書いてください。

○ 情報が十分

「攻撃力 2000、スキル倍率 2.5、ダメージバフ 0.3、会心率 0.6、会心ダメージ 2.2、防御定数 1600、敵の防御 1000、防御無視 0、敵の耐性 0.1、耐性ダウン 0 のときの期待ダメージは？ 明細つきで。」

（この入力での実際の結果：期待ダメージ 6192、基礎ダメージ 5000、各乗算区分 1.3 / 1.72 / 0.615385 / 0.9。）

× 情報が不足

「攻撃力 2000 なんだけど、この技でどれくらい出る？」――倍率、バフ、会心、敵のデータが足りません。Claude は自分が「覚えている」倍率で補うことはできず、聞き返すしかありません。

2. 声骸のスコア echo_score

伝える内容フィールド許される範囲説明

COSTecho.cost整数 1〜4必須

サブステータスecho.subs最大 5 個それぞれステータス＋数値（≥ 0。割合は小数で、0.08 = 8%）

○ 情報が十分（サンプルの重みを使用）

「この COST 4 の声骸を採点して。メインは会心ダメージ 44%、サブは会心率 8.7%、会心ダメージ 17.4%、攻撃力 8.6%、HP 430、共鳴効率 10%。重みは会心型アタッカーのサンプル設定で。」

（実際の結果：スコア 2.694167、理想値の 76.976190%。「未確認のデータ」の注記が付きます。）

× 情報が不足

「この声骸って何点？ 会心系はまあまあ付いてる。」――具体的なサブステータスの数値がありません。また、Claude が「公式」の最大値や重みを知っていると期待しないでください。ツールが使うのは、あなたが与えた値かサンプルデータだけです。

4. ガチャのシミュレーション（モンテカルロ）gacha_simulate

入力は厳密版と同じで、加えて 3 つの任意項目があります。

フィールド許される範囲省略時説明
trials整数 1〜1,000,000100000試行回数。標準誤差は 1/√trials に比例します
seed64 ビット整数0乱数のシード。同じシードなら同じ結果になります
methodsequential / parallel_stream / virtual_threadssequential速度だけに影響し、結果には影響しません

戻り値：probability（推定値）と std_error（標準誤差）。ふだん使うなら厳密版が適しています。「シミュレーションと厳密な値が一致するか」を見たいときは、質問に「シミュレーションでも計算して」とはっきり書いてください。

ヒントドメインのプロンプト（domains/wuwa/prompts/system.md）のツール説明表にも gacha_simulate が載っており、Claude には「ふだんの確率の質問には厳密版 gacha_probability_within を使い、シミュレーションでの確認を求められたときだけシミュレーションを使う」よう指示しています。シミュレーションを使いたい場合は、質問ではっきり求めてください。なお、--fake-backend（試験用の計算サービス）はシミュレーションに対応しておらず、banner / profile のようなデータの参照もできません。これらは実際の Java サービスでのみ使えます。

5. 差 compare_diff と 6. 比 compare_ratio

比較ツールの入力は数字ではなく、同じ質問の中で先に呼んだツールの結果の出典 ID（例：c1.total）です。そのため、次の点に注意してください。

  • 「ビルド A と B の差はいくつか／何 % 高いか」といった質問では、両方の条件をすべて1 つの質問の中に書き、両方を先に計算させます。
  • CLI の実行は 1 回ごとに独立した質問で、前回の結果は覚えていません。A について聞いた後、別の質問で「さっきの A と B を比べると？」と聞くことはできません。
  • 「1234 は 1000 より何 % 高い？」のような単なる算数の問題には比較ツールを使えません（渡せる出典 ID がないため）。Claude が自分で計算した数字を回答に書くこともできません。

戻り値：compare_diff → diff（a − b）。compare_ratio → ratio（a / b）と change（a / b − 1。回答ではパーセントで表示されることが多い）。b が 0 のときは「b が 0 のため、比を計算できません」というエラーを返します。比較結果は小数点以下 6 桁（銀行丸め）です。

サンプルデータ：そのまま参照できるガチャと重みの設定

ガチャのルールや声骸の重みを指定しないときは、domains/wuwa/data/v2.x/ のサンプルデータを Claude に参照させることができます。これらの値はすべて verified: false（未確認）で、公式の数値ではありません。使った回答には自動で注記が付きます（コストの上限とデータの確かさを参照）。

よい質問の書き方

flowchart TD
  Q["聞きたいこと"] --> K{"4 種類の計算のどれか？<br/>ダメージ / 声骸 / ガチャ確率 / シミュレーション"}
  K -- いいえ --> X["数字は出せない<br/>Claude が範囲を説明するか聞き返す"]
  K -- はい --> V{"必須の数値は<br/>すべて質問に書いた？"}
  V -- はい --> OK["計算できる"]
  V -- いいえ --> D{"サンプルデータで代用できる？<br/>ガチャ / 重みの設定"}
  D -- はい --> OK2["計算できる<br/>回答に未確認の注記が付く"]
  D -- いいえ --> ASK["Claude が聞き返す<br/>数値を推測しない"]
  OK --> C{"2 つの結果を<br/>比べたい？"}
  OK2 --> C
  C -- はい --> SAME["両方の条件を<br/>1 つの質問に書く"]
図 2：質問する前のセルフチェック
  • 数値はすべて書く：ツールにはゲームの数値が組み込まれておらず、Claude も記憶で数値を補わない決まりです。
  • 割合は 30% でも 0.3 でもよい：検証器は x% と x/100 を同じ数として扱うので、質問中の「30%」や「0.3」を回答で引用しても差し戻されません。
  • サンプルデータを使うならそう書く：「サンプルの限定キャラクターガチャで」「重みは会心型アタッカーのサンプル設定で」。
  • 比べるなら 1 回で聞く：両方の条件を同じ質問に入れます。
  • 1 回に 1 つのことを聞く：1 つの質問でツールを呼べるのは最大 6 ラウンドです。超えると「計算の手順が多くなりすぎた…」で終わります（回答の読み方を参照）。

答えられない質問と、そのときに起きること

質問の種類例理由
主観的な評価、ランキング、編成のおすすめ「今のバージョンで最強のキャラは？」対応する計算ツールがない
ゲーム内のデータが必要なのに与えていない「あるキャラの解放の倍率は？」EchoLab はゲームのデータを持たず（未確認のサンプルのみ）、Claude も記憶で数値を出せない
単なる算数「1234 は 1000 より何割高い？」比較ツールが受け付けるのは、同じ質問の中のツール結果の出典 ID だけ
前回の続き「さっきのに会心率を 10% 足したら？」実行は 1 回ごとに独立していて会話の記憶がない。条件をすべて書き直してください
スクリーンショットの読み取り、住宅ローン試算など「このスクショで採点して」スクリーンショットの読み取り（M4）と住宅ローンのドメインパック（M3）はどちらもロードマップ上の計画です。今後の機能（ロードマップ）を参照

このような場合、Claude は数字を含まない文章で、できることを説明するか、足りない情報を聞き返す決まりです。Claude が何を書いても、出典のない数字は検証器が止めます。そのため最悪の場合でも「数字のない回答」になるだけで、「でっち上げの数字」が出ることはありません。以下の 2 つはどちらも実際の実行です（Claude の応答は台本で模しています）。

2 つ目の例では、ゲートウェイが計算サービスを呼ぶ前にスキーマに従って pulls: 20000 を拒否しています。実行トレースに記録されたエラーは 入力が不正です: pulls: 20000 は最大値 10000 より大きい値です です（フィールドのパス付き。必須項目の欠落、型の誤り、範囲外、選択肢にない値、余分なフィールド、形式の不一致といったよくある誤りも、同じように説明されます）。エラーを受け取った Claude は、引数を直して再試行することも、この例のようにあなたに説明することもできます。なお、状態 answered は「回答が検証に通った」ことを表すだけで、必ず数字が出たという意味ではありません。「出典」の欄が空なら、その回答は計算結果を 1 つも引用していません。

次に読む
  • 回答の読み方：出典の表、状態の行、数字の書式、「未確認」の注記の意味。
  • コマンドリファレンス：--llm、--script、--fake-backend などのオプション。
  • コストの上限とデータの確かさ：サンプルデータが「未確認」である理由。
