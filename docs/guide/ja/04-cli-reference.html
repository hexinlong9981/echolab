使い方リファレンス

コマンドリファレンス

EchoLab には現在 2 つのコマンドがあります。質問用の python -m core.agent と、評価用の python -m core.evals です。このページでは、そのすべてのオプション、実行モード、出力の形式、状態と終了コード、環境変数をまとめます。

前提コマンドはすべて、リポジトリのルートで仮想環境を有効にした状態（source .venv/bin/activate）で実行します。現在はコマンドラインのみで、GUI はありません。

python -m core.agent（質問）

引数 / オプション既定値説明
question（必須）—質問の文。空白を含むときは引用符で囲みます。省略すると argparse が error: the following arguments are required: question を表示し、終了コード 2 で終わります。
--domain DOMAINwuwaドメインパック（domains/<DOMAIN>/domain.yaml を読み込みます）。現在は wuwa（鳴潮）のみです。存在しないドメインを指定すると、--fake-backend の有無にかかわらず エラー: ドメインが見つかりません: <DOMAIN>（使えるドメイン: wuwa） と表示し、終了コード 2 で終わります。
--llm {anthropic,scripted}anthropicanthropic：実際の Claude（モデル claude-opus-5-5）を呼びます。認証情報が必要です。scripted：台本ファイルを再生します。認証情報は不要です。
--script SCRIPT—台本の YAML ファイルのパス（相対パスはカレントディレクトリ基準）。--llm scripted のときは必須で、ないと エラー: --llm scripted には --script（台本の YAML）が必要です、ファイルがないと エラー: 台本が見つかりません: <パス> と表示します。どちらも終了コードは 2 です。付属の例：core/agent/examples/compare_builds.yaml。
--fake-backendオフJava 計算サービスを起動せず、試験用の Python の参照実装で計算します。どちらの --llm とも組み合わせられます。注意：試験用のサービスには gacha_simulate（モンテカルロ）ツールがありません。
--trace-dir TRACE_DIR.echolab/traces実行トレース（JSONL）の保存先。相対パスはリポジトリのルート基準です。
--debugオフ設定や起動の誤り（終了コード 2）のとき、短い説明に加えて Python のトレースバックも表示します。ふだんは不要で、原因の調査や不具合の報告に使います。
-h, --help—ヘルプを表示して終了します（終了コード 0）。

実行モード

--llm は「誰が AI を演じるか」を、--fake-backend は「誰が計算するか」を決めます。2 つは自由に組み合わせられます。

組み合わせAPI の認証情報JDK + jar費用用途
--llm scripted --script … --fake-backend不要不要かからないいちばん手軽なデモ。Python だけで動きます
--llm scripted --script …不要必要かからないJava 計算サービスが正しく動くかの確認
--fake-backend（つまり anthropic）必要不要かかるJDK はないが自由に質問したいとき
オプションなし（既定）必要必要かかる本来の使い方：実際の Claude ＋ 実際の計算サービス
 
flowchart LR
  Q["あなたの質問"] --> L{"--llm"}
  L -- "anthropic（既定）" --> C["実際の Claude<br/>claude-opus-5-5"]
  L -- scripted --> S["台本 YAML<br/>手順どおりに再生"]
  C --> G["ゲートウェイ<br/>許可リスト・引数の検査・コストの上限"]

  G --> B{"--fake-backend?"}
  B -- いいえ --> J["Java 計算サービス<br/>calc-engine-mcp.jar"]

図 1：2 つのオプションが、それぞれ「AI」と「計算」を差し替えます。ゲートウェイ、検証器、出典の表はどのモードでも同じように動きます
台本モードは使い捨ての台帳を使います台本に書かれた使用量は架空の値です。そのため --llm scripted のとき、CLI は使用量を実行ごとの一時的な台帳に記録し、実行が終わると削除します。本物の台帳 .echolab/costs.jsonl には書き込みません（python -m core.evals の台本モードと同じ扱いで、--help の末尾にも記載があります）。上限の確認はふだんどおり行われるので、ECHOLAB_DAILY_USD を 0 にすると、台本モードでも budget_exceeded で終わります。本物の台帳を使うのは --llm anthropic のときだけです。

実行の状態と終了コード

状態（状態）は全部で 7 種類です。ツールから来た数字を回答に含むのは answered だけで、ほかの状態ではいずれも計算結果を含まない定型の文を返します（budget_exceeded に出る金額は費用の台帳と設定から取ったもので、AI が書いたものではありません）。

状態発生するとき画面に表示される回答終了コード
answered下書きが検証に通った数字を埋めた回答 ＋ 出典の表0
fallback差し戻しと書き直しを繰り返し、差し戻しが累計 3 回（書き直しは 2 回まで）になっても合格しなかった申し訳ありません。計算結果の出典を確かめられる回答を作れなかったため、数値を含む回答は控えます。条件を具体的にして、もう一度質問してください。1
budget_exceededAI を呼ぶ前に、今日または今月の費用が上限に達していることがわかったどの上限か、使用額と上限、いつ使えるようになるか、どう変えるかが示されます。例：今日（UTC）のコストが日次の上限に達したため、今は回答できません（使用額 1.02 USD / 上限 1.00 USD）。UTC の日付が変わると使えるようになります。上限は環境変数 ECHOLAB_DAILY_USD か config/budget.yaml の caps_usd.daily で変えられます。（月の上限の場合は 今月（UTC）…月次の上限…ECHOLAB_MONTHLY_USD…caps_usd.monthly）1
llm_errorClaude の呼び出しに失敗した。SDK の例外の種類で 4 つに分類され、回答もそれぞれ異なります認証情報がない：Claude API の認証情報が見つからないため、回答できませんでした。環境変数 ANTHROPIC_API_KEY を設定する（または ant auth login でログインする）か、API キーの要らない台本モード（--llm scripted）をお使いください。
認証に失敗（HTTP 401/403）：Claude API の認証に失敗したため、回答できませんでした。ANTHROPIC_API_KEY（または ant auth login のログイン）が有効かを確かめてください。
レート制限・過負荷・ネットワーク：Claude API が混み合っているか、接続できなかったため、回答できませんでした。時間をおいてお試しください。
その他の API エラー：Claude API の呼び出しに失敗したため、回答できませんでした。詳細はトレースの llm_error の行を確かめてください。		1
refusalモデルの安全機能が応答を止めたこの質問には回答できませんでした（モデルの安全機能により応答が止まりました）。1
max_tokensAI の出力が長すぎて途中で切れた応答が長くなりすぎて途中で切れたため、回答を完成できませんでした。質問を分けてお試しください。1
tool_round_limitツールを呼んだラウンドが 6 を超えた計算の手順が多くなりすぎたため、回答を完成できませんでした。質問を分けてお試しください。1

スクリプトから使うときは、$? で「数字のある回答が得られた（0）」「実行はしたが回答が得られなかった（1）」「設定や使い方の誤り（2）」を区別できます。

python -m core.evals（忠実度の評価）

evals/faithfulness/cases.yaml の 8 つの評価ケースを順に実行し、回答に「出典のない数字」が含まれていないかを集計します。既定では台本モードと試験用の計算サービスを使うので、API キーも Java も要りません。

オプション既定値説明
--llm {scripted,anthropic}scripted既定値が core.agent と逆である点に注意してください。scripted では試験用の計算サービスと使い捨ての一時的な台帳を、anthropic では実際の Claude、Java 計算サービス、本物の台帳を使います（費用がかかります）。
--cases CASESevals/faithfulness/cases.yamlケースのファイル。
--out OUT—Markdown のレポートをこのファイルにも保存します（指定しないときは画面に表示するだけです）。
--raw-dir RAW_DIRevals/reports/raw生の記録（ケースごとに 1 行の JSONL）と、ケースごとのトレース（traces/ サブディレクトリ）の保存先。
--case ONLYすべて指定した ID のケースだけを実行します。複数回指定できます。存在しない ID を指定すると 1 件も実行せず、使える ID を一覧表示して終了コード 2 で終わります。
--debugオフ設定や起動の誤りのとき、トレースバックも表示します（core.agent と同じ）。

終了コードは、すべてのケースが「合格」なら 0、不合格があれば 1、--case の ID の書き間違いなど使い方の誤りなら 2 です。

指標の意味は実行トレースと評価をご覧ください。
