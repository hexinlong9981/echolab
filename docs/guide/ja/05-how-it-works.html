しくみアニメーション実際の実行トレース

裏側で起きていること（アニメーション）

Enter キーを押してから数秒のあいだに、EchoLab は十数個の処理を行います。このページでは、実際の実行で残った実行トレースをもとに、質問がどのように計算に変わるか、計算結果がどのように「出典 ID」になるか、誤った下書きがどのように差し戻されるか、そして最終的な回答のすべての数値をなぜたどれるのかを、順を追って見ていきます。

ひとことで言うとClaude（AI）が担当するのは「質問を理解する」「どの計算ツールを呼ぶか決める」「文章を組み立てる」ことだけです。回答に出る数値はすべて決定的なツールが計算します。Claude は回答に数値を直接書けず、[[c1.total]] のような「引用」しか書けません。実際の値は最後にプログラムが埋め込みます。

まず結果から：実際の 1 回の実行

以下は、リポジトリで実際に実行したコマンドと出力です（2 つのビルド「ビルド A」「ビルド B」の期待ダメージを比べる質問です。長いため途中を … で省略しています）。ここでは台本モード（--llm scripted。あらかじめ用意した台本どおりに Claude の役を演じるため、API キーは不要）と試験用の計算サービス（--fake-backend。Java を起動しない）を使っています。差し戻しの様子を見せるため、台本では最初の下書きにわざと誤りを入れています。

「出典」の表は、回答が引用した各数値がどのツールから来たかを示します。差し戻し: 1 回 は、下書きが 1 回検証器に差し戻されたという意味です。最後の行はこの実行の実行トレースのファイルで、このページのアニメーションはこのファイルをもとに作っています。

本物の Java 計算サービスでも結果は同じ--fake-backend を外して（JAVA_HOME を Java 21 に向けて）実行しても、回答の文面も出典表もまったく同じです。試験用の計算サービスも Java のサービスと同じく、数値を小数 6 桁（銀行丸め）で返します（例：6192.000000）。実測の実行 ID は 20261003T031434Z-0b1739 です。回答に表示する桁数は、レンダラがまとめて決めます。

なぜこれで数値を信頼できるのか

① AI には「数値を書く」経路がない

Claude の最終出力はテンプレートにすぎず、数値の位置には [[出典ID]] しか書けません。実際の数値はレンダラというプログラムが埋めるので、書き写しの誤りや丸め方のばらつきが起きません。

② すべての数値に出所がある

出典 ID はゲートウェイが「何回目の呼び出し.どのフィールド」で採番します。回答の下の出典表で、各数値がどのツールから来たかを確認できます。

③ 検証器が 1 字ずつ検査する

下書きに出所の分からない数字（AI が暗算した差や「約 73%」のような概算も含む）があれば、差し戻されます。

④ 直せなければ数値を出さない

差し戻しによる書き直しは最大 2 回までです。3 つ目の下書きも不合格なら、EchoLab は疑わしい回答ではなく、数値を一切含まない定型の説明を返します。

⑤ 登録済みのツールしか使えない

ゲートウェイはドメインパックに登録されたツールだけを通し（既定は拒否）、呼び出しの前に入力の形式を検査します。

⑥ サンプルデータは明示される

数値が未確認のサンプルデータに依存する場合、回答の末尾に注記が自動で付きます：※ この回答の数値の一部は、未確認のサンプルデータに基づいています。

⑦ すべてを記録に残す

質問のたびに実行トレースが 1 つ書き出され、あとから 1 件ずつ確認できます。実行トレースと評価をご覧ください。

検証器が許す「むき出しの数字」

プレースホルダ以外の本文に直接書いてよい数字は、次のものだけです（全角数字は半角に変換してから比べます）：

許される場合例補足
あなたの質問に出てきた数字の引用「攻撃力 2000 のとき…」桁区切りは無視します。60% と 0.6 は同じとみなします
行頭の箇条書きの番号1.、2)、３．小数（1.5 など）は番号とみなしません
10 以下の整数 + 特定の助数詞「3 つの方法」日本語の つ・点・種類・位・番目、中国語の 个・种・项・条・步、英語の名詞 ways・points・steps・options・items・reasons・types・kinds・parts・things・tools・builds（数字の直後。間の空白は 1 つまで）
助数詞の許可リストには中国語と英語も含まれます回答は質問と同じ言語で書かれるため、中国語の「3 种方法」「2 个要点」や英語の「3 ways」「2 points」のような表現も同様に許されます。英語では名詞が数字の直後に必要で、「2 key points」のように間に別の語が入ると差し戻されます。10 を超える数は、やはりツールか質問に由来していなければなりません。

そのほかの終わり方

ここまでは正常な終わり方（状態 answered）です。次の場合、EchoLab は数値を含まない定型の説明を返し、トレースに状態を記録します：

状態どんなときか
fallback2 回を超えて差し戻されても下書きが直らなかった
budget_exceeded日次または月次のコストの上限に達した（Claude を呼ぶ前に確認するため、費用は発生しません）
tool_round_limitツール呼び出しの往復が 6 回を超えた
llm_errorClaude の呼び出しに失敗した（API キーが未設定の場合など）
refusal / max_tokensモデルの安全機能が回答を拒否した／回答が長すぎて途中で切れた（どちらの場合も、途中までのツール呼び出しは実行しません）
次に読む
  • コストの上限とデータの確かさ：コストの上限の設定方法と、「未確認のデータ」の注記の意味。
  • 実行トレースと評価：トレースファイルを自分で開いて確認する方法と、数値の忠実度の評価。
  • 回答の読み方：回答・出典表・状態行のそれぞれの意味。
