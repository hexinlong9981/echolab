応用ロードマップ予定

今後の機能（ロードマップ）

EchoLab は段階（M1～M5）に分けて開発しています。このページでは、プロジェクトの設計文書（docs/architecture.md、README のロードマップ、設計判断の記録 ADR）をもとに今後の予定をまとめます。あわせて、どんな機能が加わっても「数値を信頼できる」という点は変わらないことを説明します。

ご注意：このページの M3～M5 はすべて予定で、まだ実装されていません現在使えるのはコマンドライン（CLI）だけです：python -m core.agent "質問" と評価のコマンド python -m core.evals。Web の画面（Web UI）、スクリーンショットの読み取り、住宅ローン試算はまだ存在しません。具体的な時期は文書でも公表しておらず、予定の内容は変わる可能性があります。

M3（予定）：2 つ目のドメインパック――住宅ローン試算

EchoLab のコア（ゲートウェイ、検証器、評価、トレース）は、ゲームの概念を一切含みません。ドメインの知識はすべて「ドメインパック」に置き、使えるツールを domain.yaml で宣言します。M3 では、ごく小さな住宅ローンのパックでこれを実証する予定です：

  • 予定している内容：元利均等返済と元金均等返済の比較、繰り上げ返済の効果。計算部分は Python で書き、同じくゴールデンケースとプロンプトを用意します。
  • 目標：新しいコードは約 300 行、コアの差分はゼロ。「このパックを加えても core/ が変わっていない」ことを CI で検査します。
  • README と回答の両方に、これは計算の例であり、金融に関する助言ではないことを明記します。

利用者にとっては：将来は --domain 引数で別のドメインに切り替えられるようになる見込みです（この引数はすでにあり、既定は wuwa です。現在のドメインパックは wuwa の 1 つだけです）。

M4（予定）：スクリーンショットの読み取りと注入の評価

予定している部分役割
servers/vision_mcp/スクリーンショットを構造化された JSON に変換します（形式の検証付き、Python）。たとえば声骸のスクリーンショットからステータスを読み取り、手入力の手間を省きます
evals/redteam/プロンプトインジェクションの評価セットです。画像や文章に「これまでの指示を無視せよ」のような内容が紛れ込んでいても、EchoLab がそれに従わないことを確かめます。ゲームの画像ではなく、合成したスクリーンショットを使います
CI での評価注入の評価セットも CI に加えます（README によれば、台本モードは CI で実行し、本物の Claude による評価は引き続き手元で手動実行します）

EchoLab はすでに、外部から来た文字列（ツールの結果、ユーザーの入力）を指示ではなくデータとして扱っています。M4 では、これを専用の評価セットで測ります。

M5（予定）：Web UI とトレースの再生

web/ ディレクトリに React + TypeScript で Web の画面を作り、Vite で静的ファイルにビルドして Cloudflare Pages に置く予定です。予定している機能：

対話

コマンドを打たずに、Web 上で質問し、出典付きの回答を読めます。

トレースの再生

.jsonl の実行トレースをフローチャート（React Flow）として描き、1 ステップずつ再生します。このガイドの 5 ページのアニメーションに近いものです。

評価ダッシュボード

数値の忠実度や差し戻し率などの評価指標とその推移をグラフで示します。

デモの公開

公開デモで費用が膨らまないようにする方法は未定です。現在の日次・月次のコストの上限をそのまま使うか、あらかじめ録っておいた回答を使うか、などを検討しています（構想・未決定）。

変わらないこと

新しいドメインでも、スクリーンショットの入力でも、Web の画面でも、通るのは同じコアの流れです。そのため、利用者にとって次の保証はこれからも変わりません：

数値は計算ツールからだけ

AI は [[出典ID]] を含むテンプレートを書くだけで、数値はプログラムが埋めます。

検証器が関門になる

出所の分からない数値は差し戻され、直らなければ数値を含まない説明を返します。

出典をたどれる

どの数値もツールと元の値までたどることができ、実行トレースに残ります。

コストには上限がある

日次・月次の上限に達したら、Claude をそれ以上呼びません。

未確認のデータには注記が付く

サンプルデータを使った数値には、自動で注意書きが付きます。
