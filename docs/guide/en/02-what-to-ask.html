Using EchoLabFeaturesAsking questions

What you can ask

EchoLab never gives numbers "by feel": every number comes from a calculation tool. So "what can I ask?" really means "which calculation tools exist, and what inputs do they need?" This page explains the 6 tools in player terms and tells you what information to include in a question.

Current state, first Today EchoLab only has a command line (CLI): python -m core.agent "your question". A web interface is planned for roadmap milestone M5 and does not exist yet.
Understanding natural-language questions is Claude's job, which requires the default --llm anthropic mode and an ANTHROPIC_API_KEY. The terminal examples on this page were produced in --llm scripted (scripted) mode: "which tool to pick, which arguments to fill in, and how to word the answer" are written in a script that imitates Claude, but the tool results, the verifier's verdicts and the terminal output are from real runs. The scripts used in the examples, such as gacha_banner.yaml, out_of_scope.yaml and tool_error.yaml, were written separately for this guide and are not in the repository; the example script that ships with the repository is core/agent/examples/compare_builds.yaml.

Feature overview

EchoLab's default domain pack is wuwa (a Wuthering Waves character-building advisor, a non-official fan project); there are also mortgage, example mortgage repayment calculations (switch with --domain mortgage; see M3 in the Roadmap), and mushoku, spoiler-protected Mushoku Tensei lore (for example --domain mushoku --context progress=novel:5; see M6 in the Roadmap). This page covers wuwa: Claude can call 7 tools in total: the 4 calculation tools and 1 screenshot-reading tool (see "7. Screenshot reading" below) the domain pack declares in domains/wuwa/domain.yaml, plus the 2 compare tools built into the core.

Expected damage

damage_expected: given attack, multiplier, bonuses, crit, enemy defense and resistance, computes the expected damage and each multiplier.

Echo score

echo_score: scores an echo's sub-stats by weight and converts the score to "what percent of the ideal".

Gacha probability (exact)

gacha_probability_within: the exact probability (Markov chain) of getting the featured character within N pulls from your current pity state.

Gacha simulation (Monte Carlo)

gacha_simulate: a random-simulation estimate of the same probability, with its standard error.

Difference

compare_diff: the difference a − b between two calculation results.

Ratio

compare_ratio: the ratio a / b of two results, and the increase a / b − 1 ("how many percent higher").

How a question turns into tool calls

You just ask in natural language. Claude reads the question, picks tools, and fills the values from the question into the tool arguments; the gateway checks that the arguments are valid and passes them to the calculation service. When a comparison is needed, Claude does not subtract by itself; it calls a compare tool. What each feature needs from you

The field names and ranges below come from the calculation service's input schemas (services/calc-engine/src/main/resources/tools/*.schema.json). You do not need to write field names; just say it clearly in natural language. But information marked "required" must appear in the question (or be obtainable from sample data), otherwise Claude should ask you for it. All "rate" values are decimals inside the tools (0.3 = 30%); you can write either 30% or 0.3 and Claude converts.

1. Expected damage damage_expected

All 10 arguments are required. The tool contains no game constants, so you also have to give the defense constant, enemy DEF and resistance.

Enough information

"What is the expected damage for ATK 2000, skill multiplier 2.5, DMG bonus 0.3, crit rate 0.6, crit DMG 2.2, defense constant 1600, enemy DEF 1000, DEF ignore 0, enemy RES 0.1 and RES shred 0? With a breakdown."

(Real result for these inputs: expected damage 6192, base damage 5000, multipliers 1.3 / 1.72 / 0.615385 / 0.9.)

Not enough information

"My ATK is 2000. How much does this skill hit for?" The multiplier, bonuses, crit and enemy data are missing. Claude may not fill in a multiplier it "remembers"; it can only ask you.

Enough information (sample weights)

"Score this COST 4 echo: main stat crit DMG 44%, sub-stats crit rate 8.7%, crit DMG 17.4%, ATK 8.6%, HP 430, Energy Regen 10%. Use the sample crit attacker profile for weights."

(Real result: score 2.694167, 76.976190% of the ideal, with the unverified-data note.)

Not enough information

4. Gacha simulation (Monte Carlo) gacha_simulate

Same inputs as the exact version, plus 3 optional ones:

FieldAllowed rangeIf omittedNotes
trialsInteger 1–1,000,000100000Number of simulated runs. The standard error is proportional to 1/√trials
seed64-bit integer0Random seed; the same seed gives the same result
methodsequential / parallel_stream / virtual_threadssequentialAffects speed only, not the result

Returns: probability (the estimate) and std_error (standard error). For everyday use the exact version is the better fit; if you want to see whether the simulation agrees with the exact value, say "also check it with a simulation" in the question.

TipThe tool table in the domain prompt (domains/wuwa/prompts/system.md) also lists gacha_simulate, and tells Claude to use the exact gacha_probability_within for ordinary probability questions and to simulate only when you ask for a simulation check. If you want a simulation, ask for it explicitly. Also, --fake-backend (the fake calculation service for testing) does not offer the simulation and does not support data references such as banner / profile; those work only with the real Java service.

5. Difference compare_diff and 6. Ratio compare_ratio

The inputs of the compare tools are not numbers but the source IDs (such as c1.total) of earlier tool results within the same question. Therefore:

  • For questions like "how much stronger / how many percent higher is build B than build A", give the full conditions of both sides in the same question, so both get calculated first.
  • Every CLI run is a separate question with no memory of the previous one. You cannot ask about A first and then follow up with "and how does that A compare to B?"
  • Plain arithmetic such as "how much higher is 1234 than 1000?" cannot use the compare tools (there is no source ID to pass), and a number Claude computes itself may not appear in the answer either.

Returns: compare_diff → diff (a − b); compare_ratio → ratio (a / b) and change (a / b − 1, usually shown as a percentage in the answer). When b is 0 it returns the error 「b が 0 のため、比を計算できません」 ("cannot compute the ratio because b is 0"). Compare results keep 6 decimal places (banker's rounding).

7. Screenshot reading echo_read_screenshot (M4)

Put the path of an Echo screen screenshot in your question. Claude first reads COST and the main and sub-stat values with OCR (Tesseract), then passes them to echo_score. Note:

  • By default the image must be inside the repository directory (PNG or JPEG, at most 10 MB). For other places, set the allowed directories with the environment variable ECHOLAB_VISION_ROOTS.
  • The result contains only the numbers declared in the template (such as sub_crit_rate). Any other text in the image (including things like "ignore the previous instructions") never reaches Claude.
  • The answer lists the values it read, with source IDs; check them against the image. Out-of-range values (likely misreads) are errors and are never guessed.
  • Tesseract and its Japanese data must be installed. So far it has been checked only with synthetic screenshots; real game screens may not be readable.

How to write a good question

flowchart TD
  Q["What you want to know"] --> K{"One of the 4<br/>calculation types?<br/>damage / echo /<br/>gacha probability /<br/>gacha simulation"}
  K -- No --> X["No numbers possible<br/>Claude explains the scope<br/>or asks you"]
  K -- Yes --> V{"All required<br/>values in<br/>the question?"}
  V -- Yes --> OK["Can be calculated"]
  V -- No --> D{"Can sample data<br/>fill in?<br/>banner /<br/>weight profile"}
  D -- Yes --> OK2["Can be calculated<br/>answer carries the<br/>unverified note"]
  D -- No --> ASK["Claude should ask you<br/>it does not guess values"]
  OK --> C{"Comparing two<br/>results?"}
  OK2 --> C
  C -- Yes --> SAME["Put both sides' conditions<br/>in the same question"]
Figure 2: A self-check before you ask
  • Give all the values: the tools have no built-in game values, and Claude is told not to fill values in from memory.
  • Rates as 30% or 0.3 both work: the verifier treats x% and x/100 as the same number, so an answer quoting "30%" or "0.3" from your question is not blocked.
  • Say so if you want sample data: "use the sample limited character banner", "use the sample crit attacker profile for weights".
  • Ask comparisons in one go: put the conditions of both sides in the same question.
  • Ask one thing at a time: each question allows at most 6 rounds of tool calls; beyond that the run ends with 「計算の手順が多くなりすぎた…」 ("the calculation took too many steps…"; see Reading the answers).

Questions it cannot answer, and what happens then

Type of questionExampleWhy
Subjective ratings, rankings, team recommendations"Which character is the strongest in the current version?"There is no calculation tool for it
Needs in-game data you did not provide"What is this character's Liberation multiplier?"EchoLab contains no game data (only unverified samples), and Claude may not give values from memory
Plain arithmetic"How many percent higher is 1234 than 1000?"The compare tools only accept source IDs of tool results from the same question
Following up on the last question"What about that last one with 10% more crit rate?"Each run is independent with no conversation memory; write out the full conditions again
Images without a path, screens with a different layout"Look at the screenshot I just sent"The CLI reads a screenshot only through a path written in the question (see "7. Screenshot reading" above). It has been checked only with synthetic screenshots; real game screens with other layouts or fonts may not be readable, and then it reports an error instead of guessing.
