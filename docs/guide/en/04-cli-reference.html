Using EchoLabReference

CLI reference

EchoLab currently provides two commands: python -m core.agent for asking questions and python -m core.evals for evals. This page lists all their options, the run modes, the output format, statuses and exit codes, and environment variables.

PrerequisitesRun every command from the repository root with the virtual environment activated (source .venv/bin/activate). There is only a command line for now, no GUI.

python -m core.agent (ask a question)

The help text in English: the program "answers questions with sources". question is the question (e.g. "What is the expected damage at ATK 2000?"). The cost ledger section says that --llm anthropic records real costs in the real ledger (default .echolab/costs.jsonl) and respects the daily and monthly caps (config/budget.yaml, environment variables ECHOLAB_DAILY_USD and ECHOLAB_MONTHLY_USD), while --llm scripted usage is made-up values from the script, so it is recorded in a throwaway ledger for each run and never written to the real ledger (the same as the evals in python -m core.evals). The exit codes section reads: 0 answered / 1 could not answer (ended with a fixed answer) / 2 configuration or usage error. Each option is described in the table below.

Argument / optionDefaultDescription
question (required)—The question text. Put it in quotes if it contains spaces. To read a screenshot, write the image path in the question (M4; see What you can ask). If it is missing, argparse reports error: the following arguments are required: question and exits with code 2.
--domain DOMAINwuwaThe domain pack (reads domains/<DOMAIN>/domain.yaml). Two packs exist today: wuwa (Wuthering Waves) and mortgage (example mortgage repayment calculations; sample script domains/mortgage/examples/compare_methods.yaml). For a domain that does not exist, with or without --fake-backend, it prints エラー: ドメインが見つかりません: <DOMAIN>（使えるドメイン: mortgage、wuwa） ("Error: domain not found: <DOMAIN> (available domains: mortgage, wuwa)") and exits with code 2.
--llm {anthropic,scripted}anthropicanthropic: calls the real Claude (model claude-opus-5-5); needs credentials. scripted: replays a script file; needs no credentials.
--script SCRIPT—Path to the script YAML file (relative paths are resolved against the current directory). Required with --llm scripted; if missing it prints エラー: --llm scripted には --script（台本の YAML）が必要です ("Error: --llm scripted requires --script (the script YAML)"); if the file does not exist it prints エラー: 台本が見つかりません: <path> ("Error: script not found: <path>"). Both exit with code 2. The bundled example: core/agent/examples/compare_builds.yaml.
--fake-backendOffDoes not start the Java calculation service; uses the Python reference implementation for testing instead. Works with either --llm value. Note: the fake service does not offer the gacha_simulate (Monte Carlo) tool.
--trace-dir TRACE_DIR.echolab/tracesDirectory where execution traces (JSONL) are saved. Relative paths are resolved against the repository root.
--debugOffOn a configuration or startup error (exit code 2), also prints the Python traceback in addition to the short explanation. Not needed normally; use it when investigating a problem or reporting a bug.
-h, --help—Shows the help and exits (exit code 0).

Run modes

--llm decides "who plays the AI", and --fake-backend decides "who does the calculations". They can be combined freely:

--llm scripted --script …NoYesNoConfirm the Java calculation service works
--fake-backend (i.e. anthropic)YesNoYesNo JDK installed, but you want to ask freely
No options (default)YesYesYesNormal use: real Claude + real calculation service

Scripted mode uses a throwaway ledgerUsage in a script is made up, so with --llm scripted the CLI records usage in a temporary ledger dedicated to that run and deletes it at the end; it is never written to the real ledger .echolab/costs.jsonl (the same as scripted mode in python -m core.evals; the end of --help says so too). The caps are still checked as usual: if you set ECHOLAB_DAILY_USD to 0, scripted mode also ends with budget_exceeded. Only --llm anthropic uses the real ledger.

Output structure

Every run writes the same structure to standard output:

PartContents
① AnswerThe answer after it passed verification and the numbers were filled in; if it did not pass, a single fixed text (see the status table below). If the calculation used unverified data, an extra line is added at the end: ※ この回答の数値の一部は、未確認のサンプルデータに基づいています。 ("Some of the numbers in this answer are based on unverified sample data.")
② Source table (出典)Columns: 出典 ID (source ID, c<call number>.<result field>), 値 (the raw value returned by the tool), ツール (tool name), 未確認データ (IDs of unverified data used; - if none). When the status is not answered, it shows （引用した出典はありません） ("no sources were cited").

差し戻し: N 回The number of drafts the verifier rejected.

トレースThe execution trace file of this run (<trace-dir>/<run ID>.jsonl). See Traces & evals for how to inspect it.

python -m core.evals (faithfulness evals)

Runs each of the 8 eval cases in evals/faithfulness/cases.yaml and measures whether the answers contain any "numbers without a source". By default it uses scripted mode and the fake calculation service, so no key and no Java are needed.

OptionDefaultDescription
--llm {scripted,anthropic}scriptedNote that the default is the opposite of core.agent. scripted uses the fake calculation service and a throwaway temporary ledger; anthropic uses the real Claude, the Java calculation service and the real ledger (this costs money).
--cases CASESevals/faithfulness/cases.yamlThe case file.
--out OUT—Also saves the Markdown report to this file (without it, the report is only printed to the screen).
--raw-dir RAW_DIRevals/reports/rawWhere the raw records (one JSONL line per case) and per-case traces (the traces/ subdirectory) are saved.
--case ONLYAllRuns only the case with the given ID; can be repeated. If an ID does not exist, no case is run; it lists the available IDs and exits with code 2.
--debugOffAlso prints the traceback on configuration or startup errors (same as core.agent).

The report in English: the title is "Eval report: numeric faithfulness", followed by the date (UTC), the LLM mode and the case file (1 case). Under 指標 (metrics): faithfulness (share of answers with no unsourced numbers) 1.000; rejection rate (rejected drafts / drafts) 1.000 (3 / 3); passed cases 1 / 1; total cost (USD) 0.000000. Under ケースごとの結果 (per-case results), the never-corrected row reads "if rejections do not fix the draft, fall back to an answer without numbers", with status fallback and the verdict 合格 (passed).

Exit codes: 0 when every case passes, 1 when any case fails, and 2 for usage errors such as a misspelled --case ID:

The error means "Error: case not found: nope (cases in cases.yaml: …)" followed by the list of valid case IDs. The metrics are explained in Traces & evals.

python -m servers.web_api (web UI)

Replay execution traces and view the eval dashboard in a browser (M5). Three commands:

python -m servers.web_api.export                 # run every demo and eval in scripted mode → web/public/data/
(cd web && npm ci && npm run build)              # build the site → web/dist/ (needs Node.js)
python -m servers.web_api                        # listens on 127.0.0.1 only → http://127.0.0.1:8765/
TabContents
ReplayPlays an execution trace step by step as a flow diagram: boxes passed, rejections and refusals are colored, with the source table at that moment. The URL #replay/<run ID>/<step> opens a specific step
EvalsMetrics and per-case results for faithfulness (Wuthering Waves, mortgages) and the injection evals, with links to the replays
Run (local)Only when opened through python -m servers.web_api: run scripted demos or (with an API key) ask real Claude, within the cost caps

Option: --port (default 8765). This server is for your own machine only; do not expose it. The public replay site is static files generated by CI (Cloudflare (Workers static assets, formerly Pages): https://echolab-web.echolab-web.workers.dev/). See web/README.en.md in the repository.

Environment variables

VariableDefault (source)Effect
ANTHROPIC_API_KEYNoneAPI key for the real Claude. Other credential methods supported by the Anthropic SDK, such as ant auth login, also work. Used only with --llm anthropic.
ECHOLAB_DAILY_USD1.00 (config/budget.yaml)Daily (UTC) cost cap in USD.
ECHOLAB_MONTHLY_USD10.00 (config/budget.yaml)Monthly (UTC) cost cap in USD.
ECHOLAB_LEDGER.echolab/costs.jsonl (config/budget.yaml)The cost ledger file. Relative paths are resolved against the repository root. Used only with --llm anthropic; scripted mode uses a throwaway temporary ledger each time.
JAVA_HOMENoneIf java is not found on PATH, the calculation service is started with $JAVA_HOME/bin/java instead.
PATHSystemjava is looked up on PATH first.
ECHOLAB_DATA_ROOTdomains (config/services.yaml)Root directory from which the Java calculation service reads sample data. The domains value in config/services.yaml is only a default: if the variable is set in your shell, the CLI uses the shell's value when starting the service (for example ECHOLAB_DATA_ROOT=/path/to/data python -m core.agent …). Normally you do not need to set it.
