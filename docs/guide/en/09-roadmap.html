Roadmap

EchoLab is developed in milestones (M1–M5). Based on the project's design documents (docs/architecture.md, the roadmap in the README and the architecture decision records, ADRs), this page summarizes what is planned, and explains why trustworthy numbers will stay the same for you no matter what new features are added.

Please note: everything about M3–M5 on this page is planned and not implemented yetWhat you can use today is the command line (CLI) only: python -m core.agent "question" and the eval command python -m core.evals. The web UI, screenshot reading and the mortgage calculator do not exist yet. The documents give no dates, and the details of the plans may change.

M3 (Planned): a second domain pack, the mortgage calculator

EchoLab's core (gateway, verifier, evals, traces) contains no game concepts at all; domain knowledge lives in “domain packs”, which declare their available tools in domain.yaml. M3 is meant to prove this with a very small mortgage pack:

  • Planned contents: comparing equal-payment (annuity) and equal-principal repayment, and the effect of early repayment. The calculations are written in Python and likewise come with golden test cases and prompts.
  • Goal: about 300 lines of new code with zero changes to the core, and a CI check that core/ did not change when the pack was added.
  • Both the README and the answers will state: this is a calculation example, not financial advice.

What it means for you: in the future you may be able to switch to another domain with the --domain option (the option already exists, defaults to wuwa, and wuwa is currently the only domain pack).

M4 (Planned): screenshot reading and injection evals

Planned componentPurpose
servers/vision_mcp/Converts screenshots into structured JSON (with schema validation, Python). For example, it would read the stats from an Echo screenshot so you do not have to type them in
evals/redteam/A prompt-injection eval set: when an image or text hides something like “ignore the previous instructions”, EchoLab must not follow it. Uses synthetic screenshots, not game images
Evals in CIAdd the evals to CI (per the README: scripted mode runs in CI; the real Claude is still run manually, locally)

EchoLab already treats text coming from outside (tool results, user input) as data, not instructions; M4 will measure this with a dedicated eval set.

M5 (Planned): web UI and trace replay

The plan is a web interface in the web/ directory using React + TypeScript, built into static files with Vite and hosted on Cloudflare Pages. Planned features:

Chat

Ask questions and read answers with sources in the browser, without typing commands.

Trace replay

Draw .jsonl execution traces as flow diagrams (React Flow) and replay them step by step, similar to the animation on page 5 of this guide.

Eval dashboard

Charts of eval metrics such as faithfulness and rejection rate, and how they change over time.

Public demo

How to keep costs under control in a public demo has not been decided yet: it could keep the current daily / monthly cost caps, or switch to prerecorded answers (Concept, undecided).

What will not change

New domains, screenshot input and the web interface would all go through the same core flow. So for you, the following guarantees stay in place:

Numbers come only from calculation tools

The AI only writes templates with [[sourceID]], and the program fills in the numbers.

The verifier guards the answer

Numbers of unknown origin get the draft rejected; if it cannot be fixed, you get an explanation without numbers.

Sources can be checked

Every number can be traced to a tool and its raw value, and is kept in the execution trace.

Costs are capped

Once the daily / monthly cap is reached, Claude is not called any more.

Unverified data is flagged

Values that use sample data come with an automatic note.
