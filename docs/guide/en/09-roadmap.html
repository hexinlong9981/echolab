Roadmap

EchoLab is developed in milestones (M1–M6). Based on the project's design documents (docs/architecture.md, the roadmap in the README and the architecture decision records, ADRs), this page summarizes what each milestone delivered, and explains why trustworthy numbers will stay the same for you no matter what new features are added.

Status: M1–M6 are all implementedThe command line (python -m core.agent "question", python -m core.evals), the mortgage pack (--domain mortgage), screenshot reading (OCR), the web UI (M5) and the Mushoku Tensei lore pack (M6, --domain mushoku) are all available. Not done yet: a systematic eval with real Claude (it needs an API key) and checking the Mushoku Tensei data (currently an unverified draft written from memory). The public site: https://echolab-web.echolab-web.workers.dev/ (republished automatically on every push to main).

M3 (Done): a second domain pack, example mortgage repayment calculations

EchoLab's core (gateway, verifier, evals, traces) contains no game concepts at all; domain knowledge lives in “domain packs”, which declare their available tools in domain.yaml. M3 proved this with a very small mortgage pack:

  • Contents: comparing equal-payment (annuity) and equal-principal repayment, and the effect of a partial prepayment (shorter term or lower payment). A Python MCP server inside the pack does the calculations, so Java is not needed; the pack also has golden test cases, prompts and scripted evals (5 cases).
  • Zero changes to the core: the commit that added the pack did not touch core/, and the pack-isolation CI job checks this every time. The three generic features that were missing (starting Python services, running evals per domain, an answer note) went into the core first, in a separate commit (ADR-0009).
  • Every answer that passes verification ends with a note added automatically: this is a calculation example, not financial advice.

What it means for you: switch to mortgages with --domain mortgage (the default is still wuwa). To try it without an API key:

python -m core.agent "3000 万円を年 1.5%、35 年で借りるとき、元利均等と元金均等では利息の合計はどれだけ違う？" \
  --domain mortgage --llm scripted --script domains/mortgage/examples/compare_methods.yaml

M4 (Done): screenshot reading and injection evals

ComponentPurpose
servers/vision_mcp/An MCP server (Python, domain-agnostic) that reads screenshots with OCR (Tesseract). A domain pack's template (domains/wuwa/vision/echo_screenshot.yaml) decides what to read, and it returns only the numeric fields declared there (such as sub_crit_rate). Any other text in the image is dropped and never reaches Claude. Out-of-range values (likely misreads) are errors and are never guessed
Image path limitsOnly PNG or JPEG files of at most 10 MB inside ECHOLAB_VISION_ROOTS (default: the repository directory) can be read. Paths such as /etc/passwd are refused
evals/redteam/7 prompt-injection eval cases: a script plays a Claude that "was fooled" (writing a number from the image, calling an undeclared tool, reading a file outside the allowed place…), and the cases check that reading, the gateway and the verifier still stop it. Uses synthetic screenshots, not game images. Runs in CI every time: 7/7 pass, no attack succeeds

You need Tesseract and its Japanese data (for example sudo dnf install tesseract tesseract-langpack-jpn or sudo apt-get install tesseract-ocr tesseract-ocr-jpn). Put the screenshot path in the question. To try it without an API key (the Java calc service is also needed; with --fake-backend the recorded OCR results are used instead):

python -m core.agent "evals/redteam/screenshots/echo-injection.png の声骸を採点して。重みは会心率 1.0・会心ダメージ 1.0・攻撃力% 0.75・攻撃力 0.25・共鳴効率 0.5、最大値は会心率 0.1・会心ダメージ 0.2・攻撃力% 0.12・攻撃力 60・共鳴効率 0.12 として。" \
  --llm scripted --script domains/wuwa/examples/score_screenshot.yaml

M5 (Done): the web UI

The web/ directory is built with React + TypeScript + Vite. The policy is cost first, completely free (ADR-0011): only a static site is public. No server runs and Claude is never called, so there is no cost and nobody can run up an API bill.

Replay

Plays an execution trace step by step as a flow diagram (React Flow). Boxes passed, rejected drafts and refused tools are shown in color, together with the source table at that moment. The URL #replay/<key>/<step> (the key is a demo ID or "suite ID-case ID"; it does not change between deployments, e.g. demo-compare-builds) opens a specific step.

Eval dashboard

Metrics and per-case results for numeric faithfulness (Wuthering Waves, mortgages) and the injection evals; every case links to its replay.

Run (local only)

Appears only when opened through python -m servers.web_api on your own machine: run the scripted demos, or ask real Claude when you have an API key (protected by the daily and monthly cost caps). It listens on 127.0.0.1 only and is not public.

Public site

Hosted on Cloudflare (Workers static assets, formerly Pages) (free plan): https://echolab-web.echolab-web.workers.dev/. CI generates the data in scripted mode, builds and publishes; the public replays are scripted-mode records, not real Claude answers. It is republished automatically on every push to main.

To try it on your own machine (Node.js needed):

python -m servers.web_api.export && (cd web && npm ci && npm run build)
python -m servers.web_api        # open http://127.0.0.1:8765/ in a browser

M6 (Done): a third domain pack — Mushoku Tensei lore (spoiler protection)

The third domain pack answers questions about the setting of Mushoku Tensei (an unofficial fan project). Its highlight is spoiler protection, which has the same structure as filtering search results by user permissions in business systems (permission-aware RAG) (ADR-0012).

Lore lookup

Finds short, self-written facts by character, place or keyword. Only returns what is within your progress.

Timeline

A character's age at an event, or the years between two events. The tool calculates the numbers.

Routes

The shortest route (in days) on a home-made map. The days are the author's rough estimates.

How to ask: you set your progress

Tell it how far you have read or watched with --context progress=…: novel:<volume> for the novels (e.g. novel:5) or anime:<season>-<episode> for the anime (e.g. anime:2-12). To try it without an API key:

python -m core.agent "転移事件のとき、ルーデウスは何歳だった？" \
  --domain mushoku --context progress=novel:3 \
  --llm scripted --script domains/mushoku/examples/teleport_age.yaml

Output (excerpt; the program answers in Japanese):

転移事件のとき、ルーデウスは 10 歳でした（甲龍歴 417 年、生まれは 407 年）。
資料によると、フィットア領で大規模な転移事件が起き、住民が世界各地に飛ばされました（小説 3 巻）。

※ この回答の数値の一部は、未確認のサンプルデータに基づいています。

※ 設定は記憶をもとに書いた非公式の下書き資料に基づき、誤りを含むことがあります。地図の日数は自作の目安です。

How spoilers are prevented

  • Only you set the progress: it never appears in the tool descriptions the AI sees. If the AI fills in a progress value itself (for example when lured into "checking later volumes"), the gateway always refuses and adds the value you set.
  • Filtering in the retrieval layer: only the annotations for the medium you declared (novels or anime) are used, with no conversion between them; data without annotations is never returned.
  • "Hidden" and "does not exist" give the same answer, so not even the existence of something is leaked.
  • Aliases have progress too: an alias that reveals someone's identity only works from the volume or episode where it is revealed.
  • Without a progress value it does not search; it first asks how far you are.

All of this is written as evals (7 spoiler-luring cases that run in CI every time; all are stopped).

Please note
  • The data is an unverified draft: facts, characters, years, volume and episode numbers, and map days were written from memory and may be wrong. Answers carry a note saying so automatically. When unsure of a volume, the data uses the later one (better late than an early spoiler).
  • Known limitation: a spoiler sentence without numbers that the AI writes from its own memory cannot be stopped structurally (only the prompt forbids it); sentences with numbers are stopped by the verifier.
  • No source text, dialogue, illustrations or anime images are included; only short self-written points and volume/episode numbers.

What will not change

New domains, screenshot input and the web interface would all go through the same core flow. So for you, the following guarantees stay in place:

Numbers come only from calculation tools

The AI only writes templates with [[sourceID]], and the program fills in the numbers.

The verifier guards the answer

Numbers of unknown origin get the draft rejected; if it cannot be fixed, you get an explanation without numbers.

Sources can be checked

Every number can be traced to a tool and its raw value, and is kept in the execution trace.

Costs are capped

Once the daily / monthly cap is reached, Claude is not called any more.

Unverified data is flagged

Values that use sample data come with an automatic note.
