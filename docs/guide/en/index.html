Getting startedOverview

What is EchoLab

A command-line Q&A assistant that never lets the AI do the math: you ask a question in one sentence, every number is computed by deterministic tools, and every number in the answer can be traced back to its source.

What it can do for you

EchoLab is themed on character building in the game Wuthering Waves (a non-official, non-commercial fan project). You type a question in the terminal, and it:

  • understands the question and picks the right calculation tools (expected damage, echo score, gacha probability, plus compare tools for differences and growth rates);
  • has the tools compute the results, then writes an explanation from those results;
  • attaches a source table below the answer: which calculation each number came from, its raw value, and whether unverified data was used.
Command line (CLI) only for nowToday EchoLab can only be used from a terminal, with python -m core.agent "question". There is no graphical interface. A web interface is planned for roadmap milestone M5 but is not implemented yet (see Roadmap).
About the interface languageThe CLI's labels and fixed messages (such as 状態 "status", 出典 "source" and 差し戻し "rejected drafts") are in Japanese. This guide shows the real output unchanged and explains each part in English. Some examples also use the Japanese sample questions that ship with the project; you can ask your own questions in English.

Why you can trust its numbers

Numbers come only from tools

The AI does no arithmetic at all. Even the difference between two numbers or a growth rate is computed by the compare tools (compare.diff / compare.ratio).

A verifier checks every number

The AI writes a draft with placeholders (such as [[c1.total|0]]). If a number without a source appears in the draft, the draft is rejected (「差し戻し」) and must be rewritten.

The source table is traceable

Every number has a source ID (such as c3.diff), listed below the answer with its raw value and the tool that computed it.

Unverified data is flagged

Most of the sample data is verified: false. When it is used, a note is added to the end of the answer automatically: 「未確認のサンプルデータに基づいています」 ("based on unverified sample data").

No numbers rather than wrong ones

If a draft is still not acceptable after 3 rejections, you get a fixed answer with no numbers (status fallback) instead of questionable numbers.

Cost caps

When the real Claude is called, a cap of 1 USD per day and 10 USD per month is checked before every call (adjustable with environment variables).

A real recorded run

Below is the real output of the same example (scripted mode with the real Java calculation service; no API key needed). The command is long because every stat of both builds is written into the question.

The question asks: "Build A (ATK 2000, skill multiplier 2.5, DMG bonus 0.3, crit rate 0.6, crit DMG 2.2, enemy DEF 1000, no RES shred) vs Build B (ATK 1800, skill multiplier 3.0, DMG bonus 0.2, crit rate 0.5, crit DMG 2.5, enemy DEF 1200, RES shred 0.3): which is stronger, and by how much? Both use defense constant 1600, DEF ignore 0, enemy RES 0.1."

How to read the output:

  • The answer (top four lines): "Build B is stronger. Build A expected damage: 6,192. Build B expected damage: 7,128. Difference: 936 (15.1% more than A)."
  • The source table under 出典: ("sources") lists every number the answer cites. Its columns are 出典 ID (source ID), 値 (raw value), ツール (tool) and 未確認データ (unverified data used; - means none).
  • The status line: 状態 (status), 差し戻し: 1 回 (1 rejected draft), 費用 (cost; $0.0000 because scripted mode does not call a real AI) and 実行 ID (run ID). トレース is the path of the execution trace.

Each part is explained in detail in Reading the answers.

What it looks like when unverified data is used

If a calculation uses sample data marked verified: false (for example the rules of the limited character banner), the answer automatically gets an extra note line, and the 未確認データ (unverified data) column of the source table names the data item:

The question asks for the chance of getting the featured character within 80 pulls on the limited character banner, starting from a pity count of 0 with no guarantee. The answer reads "The chance of getting the featured character within 80 pulls is 60.6%." The line starting with ※ is the automatic note: "Some of the numbers in this answer are based on unverified sample data."

(my-unverified.yaml is a script written for this demo: it has the tool reference the sample banner data with banner: featured-character. How to write scripts is covered in Traces & evals.)
