Cost Caps and Data Trust

Answering questions with the real Claude incurs API costs. Before every Claude call, EchoLab checks two caps, daily and monthly, and records the cost of each call in a local ledger. This page explains the prices, the caps, what happens when a cap is exceeded, the ledger format, where your data is sent, and which data you can trust.

Models and prices

The default mode (--llm anthropic) uses claude-opus-5-5. The price table lives in config/budget.yaml, in US dollars per million tokens:

ModelInputOutputCache readCache write (5-minute TTL)Use
claude-opus-5-54.0020.000.205.00Default model
claude-opus-55.0025.000.506.25May be used by server-side fallback
claude-opus-4-85.0025.000.506.25Same as above

Requests enable server-side fallback (fallbacks: "default"): when the default model declines because of a safety classifier, the server may have another model answer instead. In that case EchoLab records each attempt separately (each model at its own price). Scripted mode (--llm scripted) does not call any API; if the script has no usage, the cost is 0. If the script contains simulated usage, the CLI computes this “simulated cost” from the price table and shows it in the status line, but records it only in a temporary ledger dedicated to that run (deleted when the run ends), and never in the real ledger (the same applies to scripted mode in the evals, python -m core.evals).

Daily and monthly caps

CapDefaultEnvironment variableConfig file
Daily1.00 USDECHOLAB_DAILY_USDconfig/budget.yaml → caps_usd.daily
Monthly10.00 USDECHOLAB_MONTHLY_USDconfig/budget.yaml → caps_usd.monthly
Ledger location.echolab/costs.jsonlECHOLAB_LEDGERconfig/budget.yaml → ledger (relative paths are resolved from the repository root; used only in anthropic mode)
  • Environment variables take precedence over the config file. For example, to raise the cap for just this one run: ECHOLAB_DAILY_USD=2 python -m core.agent "…".
  • “Today” and “this month” are based on UTC: the day rolls over at 00:00 UTC (for example, 08:00 in Beijing or 09:00 in Tokyo), and the month rolls over at 00:00 UTC on the 1st.
  • A cap must be a number of 0 or more. If it is set to something like abc, the CLI does not call Claude, prints エラー: 環境変数 ECHOLAB_DAILY_USD の値「abc」はコストの上限（USD）として使えません。0 以上の数値（例 1.00）を指定してください to standard error (“Error: the value ‘abc’ of the environment variable ECHOLAB_DAILY_USD cannot be used as a cost cap (USD). Specify a number of 0 or more, e.g. 1.00”), and exits with code 2 (measured; an invalid value in config/budget.yaml produces the same error, naming the key).

What happens before and after each Claude call

sequenceDiagram
  participant U as You (CLI)
  participant A as Agent
  participant B as Budget (ledger)
  participant C as Claude API
  U->>A: Question
  loop Every LLM call (usually 2 or more per question)
    A->>B: check()
    B->>B: Sum usd in the ledger for today and this month (UTC)
    alt today ≥ daily cap or this month ≥ monthly cap
      B-->>A: BudgetExceeded
      A-->>U: Fixed reply, status budget_exceeded
    else under the caps
      A->>C: Request (prompt, tool definitions, conversation)
      C-->>A: Reply and token usage
      A->>B: record(model, usage)
      B->>B: Append one JSONL line
    end
  end
  A-->>U: Answer and the cost of this run
Figure 3: The budget check runs before every LLM call, not just once per question

Because the check runs before the call while the cost is only known after it, the total can slightly exceed the cap, by at most the cost of one call. Once the cap is exceeded, the next call is blocked.

What you see when a cap is reached

The following is a real reproduction with a temporary ledger (the ledger was pre-filled with one line recording 1.000000 USD for today; the ledger path is an example). It uses the default anthropic mode: the budget check runs before Claude is called, and once the cap is reached no call is made, so you can reproduce it even without an API key. Scripted mode cannot be used for this, because it only uses a one-off temporary ledger and does not read ECHOLAB_LEDGER.

(The question in the command asks, in Chinese, “What is the expected damage at 2000 ATK?”.) The answer means: “Today's (UTC) cost has reached the daily cap, so I cannot answer right now (used 1.000000 USD / cap 1.00 USD). It becomes available again when the UTC date changes. The cap can be changed with the environment variable ECHOLAB_DAILY_USD or caps_usd.daily in config/budget.yaml.” The sources table says （引用した出典はありません） (“no sources cited”), and the command exits with code 1. When the monthly cap is the one reached, the answer states the monthly cap amount and setting instead (measured with ECHOLAB_DAILY_USD=5 ECHOLAB_MONTHLY_USD=0.5: 今月（UTC）のコストが月次の上限に達したため、今は回答できません（使用額 1.000000 USD / 上限 0.5 USD）。UTC の月が変わると使えるようになります。上限は環境変数 ECHOLAB_MONTHLY_USD か config/budget.yaml の caps_usd.monthly で変えられます。, which says the same thing for the month and ECHOLAB_MONTHLY_USD / caps_usd.monthly). The same information is also recorded in the budget_exceeded event of the execution trace (reason: “today's (UTC) cost has reached the cap: 1.000000 / 1.00 USD”). In this case Claude is not called even once, and the cost is 0. The amounts in the reply come from the ledger and the settings, not from the AI, so the evals do not count them as unsourced numbers when measuring faithfulness.

What to do: wait for the UTC day or month to change, or deliberately raise the cap (environment variable or config/budget.yaml). Do not delete the ledger to “reset” it: it is the record of what you have actually spent.

Ledger file format

The ledger is JSONL: one line is appended for each LLM call. Below is the real content of a temporary ledger written with the example token counts:

{"ts": "2026-10-03T02:00:00+00:00", "model": "claude-opus-5-5", "usage": {"input_tokens": 2400, "output_tokens": 180, "cache_creation_input_tokens": 2100, "cache_read_input_tokens": 0}, "usd": "0.0237"}
{"ts": "2026-10-03T02:00:00+00:00", "model": "claude-opus-5-5", "usage": {"input_tokens": 300, "output_tokens": 140, "cache_creation_input_tokens": 0, "cache_read_input_tokens": 2100}, "usd": "0.00442"}
{"ts": "2026-10-03T02:00:00+00:00", "model": "claude-sonnet-x", "usage": {"input_tokens": 2400, "output_tokens": 180, "cache_creation_input_tokens": 2100, "cache_read_input_tokens": 0}, "usd": "0.029625", "estimated": true}
FieldMeaning
tsTime of the record (UTC, ISO 8601). “Today” and “this month” are determined from it
modelThe model actually billed
usage4 kinds of token counts: input, output, cache write, cache read
usdCost of this call, stored as a decimal string (to avoid floating-point errors)
estimatedPresent only when the model is not in the price table, with the value true; see the next section
  • Only calls made with --llm anthropic are written to this ledger. Simulated usage in scripted mode is recorded only in each run's temporary ledger and never appears in .echolab/costs.jsonl.
  • If the ledger contains a line that cannot be read, EchoLab does not skip it (skipping could lead to overspending). Instead it stops before calling Claude, exits with code 2, and names the file and line, for example エラー: コストの台帳 /tmp/broken.jsonl の 1 行目が読めないため、コストの上限を安全に判定できません（JSONDecodeError: Expecting ',' delimiter: line 1 column 35 (char 34)）。その行を直すか消してください (“Error: line 1 of the cost ledger /tmp/broken.jsonl cannot be read, so the cost caps cannot be checked safely (…). Fix or delete that line.”; measured, no traceback is printed). Fix or remove that line.

Models not in the price table: a conservative estimate

During fallback, the server may return a model that is not in the price table. The call has already been billed, so EchoLab still records it, but estimates the cost at the price of the most expensive model in the table and marks it "estimated": true. The 3rd line above is an example: with the same token counts, claude-opus-5-5 costs $0.0237, while the unknown model is estimated at the highest price, $0.029625. This way the cap check can only err on the strict side, never the lenient side. (A plain “price lookup” does not guess: for an unknown model, Budget.cost() raises 料金表に無いモデルです（config/budget.yaml に追加してください）, “model not in the price table (add it to config/budget.yaml)”.) If you often see a new model, add its prices to pricing_usd_per_mtok in config/budget.yaml.

Data trust: verified vs. sample

The formulas of the calculation service are cross-checked by two implementations, Java and Python, against the same set of golden cases. Whether the game numbers are accurate, however, depends on where the inputs come from:

Input sourceTrustworthinessHow it shows in the answer
Values you give in the questionAs trustworthy as the numbers you gaveNo note; the 未確認データ (“unverified data”) column of the sources table shows -
Sample data with verified: false (currently all data is like this)Sample values compiled by hand by the author; source is "TODO: 要確認" (“TODO: needs checking”); not official valuesThe note ※ この回答の数値の一部は、未確認のサンプルデータに基づいています。 (“Some numbers in this answer are based on unverified sample data.”) is added automatically, and the sources table lists IDs such as gacha_rules:featured-character, echo_weights:sample-crit-attacker and echo_weights:max_roll
Verified data with verified: trueThe data schema requires an https:// source URL, a check date checked_at and a game version game_versionNo note (the repository does not contain any such data yet)
