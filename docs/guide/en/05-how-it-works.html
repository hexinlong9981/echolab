What Happens Behind the Scenes (Animated)

Within a few seconds of pressing Enter, EchoLab does more than a dozen things. This page uses the execution trace left by one real run to walk through them step by step: how a question turns into calculations, how calculation results become “source IDs”, how a faulty draft gets rejected, and why every number in the final answer can be traced back to its origin.

The one-sentence versionClaude (the AI) only understands the question, decides which calculation tools to call, and writes the wording. Every number in the answer comes from a deterministic calculation tool. When Claude writes the answer it cannot write numbers directly; it can only write “citations” such as [[c1.total]], and the program fills in the real values at the end.

The result first: one real run

Below are the command and output from an actual run in the repository. The question is in the original Japanese and compares the expected damage of two character builds, “Build A” and “Build B”; because it is long, parts are elided with …. This run uses scripted mode (--llm scripted, which plays Claude's role from a prewritten script and needs no API key) and the test calculation service (--fake-backend, which does not start Java). The script deliberately makes the first draft wrong so you can see how a rejection happens.

The answer reads: “Build B is stronger. Build A's expected damage is 6,192, Build B's is 7,128, a difference of 936 (15.1% higher than A).” The 出典 (“Sources”) table below it lists which tool produced each number the answer cites, with the columns source ID, value, tool and unverified data. 差し戻し: 1 回 (“rejected: 1 time”) means one draft was sent back by the verifier. The last line, トレース (“Trace”), is the path of this run's execution trace file; the animations on this page are built from it.

Same result with the real Java calculation serviceRemove --fake-backend (and set JAVA_HOME to Java 21) and run again: the answer text and the sources table are exactly the same. Like the Java service, the test calculation service returns values with 6 decimal places (banker's rounding), for example 6192.000000. Measured run ID: 20261003T031434Z-0b1739. How many digits the answer displays is decided centrally by the renderer.

Why this makes the numbers trustworthy

① The AI has no channel for writing numbers

Claude's final output is only a template, and number positions can only contain [[sourceID]]. The actual numbers are filled in by the renderer program, so there are no copying mistakes or inconsistent rounding.

② Every number has an origin

The gateway assigns source IDs as “call number.field”, and the sources table under the answer tells you which tool each number came from.

③ The verifier checks every number

Any number of unknown origin in a draft (including a difference the AI worked out itself, or an estimate such as “about 73%”) gets the draft rejected.

④ No fix, no numbers

At most 2 rewrites are allowed. If the 3rd draft still fails, EchoLab returns a fixed message containing no numbers at all instead of a questionable answer.

⑤ Only registered tools can be used

The gateway only lets through tools registered in the domain pack (default deny), and checks the input schema before each call.

⑥ Sample data is flagged

If a value depends on sample data that has not been verified yet, a note is automatically added to the end of the answer: ※ この回答の数値の一部は、未確認のサンプルデータに基づいています。 (“Some numbers in this answer are based on unverified sample data.”)

⑦ Everything is recorded

Every question writes an execution trace that you can check entry by entry afterwards. See Traces & evals.

Which “bare numbers” the verifier allows

In the text outside placeholders, only the following numbers may appear directly (full-width digits are converted to half-width before comparison):

Allowed caseExampleNotes
Quoting a number that appeared in your question“攻撃力 2000 のとき…” (“at 2000 ATK…”)Thousands separators are ignored; 60% and 0.6 are treated as the same
List numbers at the start of a line1., 2), ３．Decimals (such as 1.5) do not count as list numbers
Integers up to 10 + certain counter words“3 つの方法” (“3 methods”)The Japanese counters つ・点・種類・位・番目, the Chinese counters 个・种・项・条・步, and the English nouns ways・points・steps・options・items・reasons・types・kinds・parts・things・tools・builds (directly after the number, at most one space in between)
The counter-word allowlist also covers Chinese and EnglishAnswers are written in the language you asked in, so Chinese answers such as “3 种方法” (“3 methods”) or “2 个要点” and English answers such as “3 ways” or “2 points” are allowed too. In English the noun must come directly after the number: “2 key points” is rejected because another word stands in between. Numbers above 10 must still come from a tool or from the question.

Other ways a run can end

The run above ended normally (status answered). In the cases below, EchoLab gives a fixed message without numbers and records the status in the trace:

StatusWhen
fallbackDrafts were rejected more than 2 times and still not fixed
budget_exceededThe daily or monthly cost cap was reached (checked before calling Claude, so no cost is incurred)
tool_round_limitTool calls went back and forth more than 6 rounds
llm_errorCalling Claude failed, for example because no API key is set
refusal / max_tokensThe model's safety mechanism declined to answer / the answer was too long and was cut off (in both cases, partial tool calls are not executed)
