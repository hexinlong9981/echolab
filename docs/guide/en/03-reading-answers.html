Using EchoLabOutputVerification

Reading the answers

Every run of the EchoLab CLI prints 4 parts: the answer text, the unverified-data note (when needed), the source table and the status line. Once you can read them, you can check for yourself "where this number came from and how far it can be trusted".

About languageThe answer text is written in the language of your question (Claude decides this), but the parts the CLI prints itself (labels such as 「出典」 "sources", 「状態」 "status", 「差し戻し」 "rejected drafts", 「費用」 "cost" and 「トレース」 "trace", the unverified-data note, and the fixed answers on failure) are currently in Japanese. This page gives an English gloss for each. All examples on this page come from real runs (--llm scripted scripted mode imitates Claude's wording; the calculation, verification and output are real). The scripts in the commands, gacha_banner.yaml, compare_en.yaml and never_corrected.yaml, were written for this guide and are not in the repository.

How numbers are formatted

The answer Claude writes is really a template: each number position is a placeholder [[sourceID]] or [[sourceID|format]], and the renderer (core/verifier/render.py) turns the raw value into text according to the format. The rules:

  • No format: at most 2 decimal places, with trailing zeros and a trailing decimal point removed.
  • |N (N from 0 to 9): exactly N decimal places.
  • |%N: multiply by 100, exactly N decimal places, then append %.
  • The integer part gets a comma every 3 digits; rounding is banker's rounding (ROUND_HALF_EVEN: exact halves go to the even digit); "-0" is never shown.

If you want more digits, say something like "to two decimal places" in your question, and Claude chooses the format.

What the "unverified" note means

The note reads ※ この回答の数値の一部は、未確認のサンプルデータに基づいています。, meaning "Some of the numbers in this answer are based on unverified sample data." It is not written by Claude; the renderer appends it automatically whenever at least one cited source has something other than - in its 未確認データ (unverified data) column.

  • You give every value in the question (damage calculations, or your own banner rules) → no note.
  • You reference the sample banner featured-character or the sample weights sample-crit-attacker, or omit an echo's max_roll → note.

The calculation itself is correct; "unverified" means the input game values have not been checked against a source and may not match the actual game. See Cost caps & data trust.

What a rejected draft (差し戻し) is

Every draft answer from Claude first goes through the verifier (core/verifier/verify.py). The verifier checks that:

  1. placeholders are well formed and their source IDs were really issued within this question;
  2. after removing placeholders, every number in the text is one of the following: a number from your question (thousands separators are ignored, and x% and x/100 count as the same); a list marker at the start of a line (1., 2)); or an integer of 10 or less directly followed by a counter word: Japanese 「つ・点・種類・位・番目」, Chinese 「个・种・项・条・步」, or one of the English nouns ways, points, steps, options, items, reasons, types, kinds, parts, things, tools, builds (at most one space in between).

A failing draft is sent back to Claude with a list of problems to rewrite; that is the 「差し戻し: N 回」 ("N rejected drafts") in the status line. The animation below replays one "rejected → corrected" cycle from the real execution trace 20261003T032631Z-920ada.jsonl:

Small counts in English answersIn English answers, an integer of 10 or less may be written as a digit only when one of the nouns ways, points, steps, options, items, reasons, types, kinds, parts, things, tools or builds comes directly after it. In a check against the real verifier, There are 2 points: [[c1.total]], There are two key points: [[c1.total]] and 有 2 个要点：[[c1.total]] passed, but There are 2 key points: [[c1.total]] was rejected: another word stands between the number and the noun, so "2" counts as an unsourced number. When in doubt, spell small counts out as words. Numbers above 10 (such as 「有 12 个要点」 or “12 points”) are rejected as unsourced in any language.

The fixed answer after 3 rejections

By default Claude may rewrite at most 2 times (DEFAULT_MAX_RETRIES = 2). At the 3rd rejection EchoLab gives up on the answer and prints a fixed text without any numbers instead, with status fallback and exit code 1:

The fixed answer means: "Sorry. We could not produce an answer whose calculation results can be traced to sources, so we will not give an answer containing numbers. Please make the conditions more specific and ask again." The status line reads 状態: fallback　差し戻し: 3 回 (status fallback, 3 rejected drafts). The 3 drafts in this run were "The probability is about 73.4%.", "The probability is 0.734." and "The probability is about 73% ([[c1.probability|%1]])." The third one uses a placeholder, but it also writes an unsourced "73%", so it still fails.

llm_error answers depend on the causeThe CLI classifies errors by the Anthropic SDK's exception type, and only rate limits, overload and network problems get "please try again later". With no credentials or failed authentication it tells you directly to set ANTHROPIC_API_KEY (a real run without credentials shows the first of the four texts above). The llm_error event in the execution trace also records the category kind (credentials, auth, transient, other) and the SDK's original error message; see Troubleshooting & FAQ.
