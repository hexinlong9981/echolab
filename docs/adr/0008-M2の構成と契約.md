# ADR-0008: M2 の構成と部品間の契約

- 状態: 採用
- 日付: 2026-10-03

## 背景

M2 では「質問 → ゲートウェイ → calc-engine → 数値トレース検証器 → 出典付きの回答」を CLI で通す（[ADR-0007](0007-縦の切片を優先する.md)）。
Java の計算サービスと Python のコアを並行して作るため、境界の形を先に決める必要がある。

## 決定

### 全体

| 部品 | 場所 | 役割 |
|---|---|---|
| 契約 | `core/contracts.py` | 部品間で受け渡すデータの形 |
| ゲートウェイ | `core/gateway/` | 許可リスト（`domain.yaml`、既定拒否）・入力のスキーマ検証・呼び出し ID と出典 ID の採番・コスト上限 |
| 比較ツール | `core/compare/` | 差・比・増加率（[ADR-0005](0005-数値トレース検証器.md)）。入力は出典 ID |
| 検証器・レンダラ | `core/verifier/` | 回答テンプレートの検査と、プレースホルダの置換 |
| Agent・CLI | `core/agent/` | Claude とのツール呼び出しの往復、差し戻し、CLI |
| 実行トレース | `core/trace/` | 1 回の質問を 1 つの JSONL（`.echolab/traces/<run_id>.jsonl`）に記録 |
| 評価 | `core/evals/`・`evals/` | 数値の忠実度 |
| MCP サーバ | `services/calc-engine`（`dev.echolab.app`） | Spring Boot + Spring AI の MCP サーバ（stdio）。`calc` の公開 API を呼ぶだけ（[ADR-0004](0004-M1ではSpringを導入しない.md)） |

### LLM は数値を書かない

- LLM の最終回答は**テンプレート**で、数値は必ずプレースホルダ `[[c1.total]]`（書式付き `[[c1.total|0]]`・`[[c2.ratio|%1]]`）で引用する。
- 数値への置換は決定的なレンダラが行う。LLM が数字を書き写す経路が無いので、写し間違い・丸めの食い違いが起きない。
- 検証器は、テンプレート中のプレースホルダ以外の数字（全角は NFKC で正規化）が、利用者の質問にある数値の引用か、許可リスト（箇条書きの番号など）のどちらかであることを検査する。
  どちらでもなければ差し戻す。
- 引用した値に未確認データ由来のものがあれば、レンダラが注記を自動で付ける（[ADR-0006](0006-未確認データの扱い.md)）。

### ツールの名前と結果

- ドメインのツール名（`damage.expected`）は、MCP・LLM では `.` を `_` に替えた名前（`damage_expected`）にする。Claude API のツール名に `.` を使えないため。
- ツールの入力の形は、ゴールデンケースの `input` と同じにする。データを参照する入力（`gacha.probability_within` の `banner`、`echo.score` の `profile`）も受け付ける。
- 結果は JSON の 1 オブジェクト：`{"tool", "values": {フィールド: 10 進数の文字列}, "unverified_inputs": [...], "data_version"}`。
- 出典 ID（`<呼び出し ID>.<フィールド>`）はゲートウェイが振る。計算サービスは ID を知らない。

### LLM とコスト

- モデルは Claude Opus 5.5（`claude-opus-5-5`）。抽象層を挟み、テストと CI では台本どおりに返す偽の LLM を使う。
- コストの上限は日次 1 USD・月次 10 USD（設定で変更可）。上限に達したら LLM を呼ばずに終了する。
- 実際の LLM を使う評価は手元で手動で実行し、集計した結果だけをコミットする。CI は API キーを持たない。

## 理由

- プレースホルダ方式にすると、ADR-0005 の「LLM は計算しない」を、プロンプトの指示ではなく構造で保証できる。
- 境界を JSON と Protocol で固定すると、Java と Python を並行して作り、偽物に差し替えて単体で試験できる。

## 却下した案

| 案 | 却下した理由 |
|---|---|
| LLM に数値を直接書かせ、検証器が自由文から抽出して照合する | 表記ゆれ・丸め・桁区切りの判定が複雑で、誤検出と見逃しの両方が起きる |
| 出典 ID を計算サービスが振る | 1 回の質問の中で一意にする責務はゲートウェイにある。サービスを状態なしに保てる |

## 影響

- ゴールデンケースは、Java の単体試験・Python の参照実装に加えて、MCP 経由の端から端までの試験でも照合する。
- `docs/architecture.md` の M2 の節は、この ADR に合わせて更新した。

## 補足（実装で決めた細部）

- 実行トレースは 1 回の質問を 1 つのファイル（`.echolab/traces/<実行 ID>.jsonl`）に記録する。
- ツールサービスへの接続（`core/gateway/mcp_backend.py`）は、同じサービスへの呼び出しを 1 本ずつ送り、1 回の応答を 30 秒まで待つ。
  時間切れは `ToolError` として LLM に返し、質問全体は止めない。`java` が PATH に無いときは `JAVA_HOME/bin/java` で起動する。
- 拒否時のサーバ側フォールバックで料金表に無いモデルが課金された場合も、台帳には必ず記録する。金額は料金表の最高料金で見積もり、上限の判定が甘くならないようにする。
- MCP 経由の端から端までの試験（`tests/e2e/`）は、CI で jar を作ってから実行する（`test.yml` の `e2e` ジョブ）。
- 既知の制約は `docs/architecture.md` の「既知の制約」にまとめる。
