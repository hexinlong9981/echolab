# ADR-0012: 無職転生のパックとネタバレ防止

- 状態: 採用
- 日付: 2026-10-04

## 背景

3 つ目のドメインパックとして『無職転生』の設定考証を作る（M6）。鳴潮（数値の最適化）・住宅ローン（計算例）と違い、
題材は「知識と時間の推論」で、見どころは**ネタバレ防止**である。これは業務での「利用者の権限に応じて検索結果を絞る」
（権限付きの RAG）と同じ構造を持つ。利用者の判断（2026-10-04）：範囲は検索・時系列・旅程のすべて、資料は小説全巻と
アニメを対象に記憶から下書きして未確認とする、検索は構造化された決定的な照会（埋め込みは使わない）。

## 決定

### 進み具合は利用者が指定し、検索の層で必ず絞り込む

- 進み具合 `progress`（`novel:<巻>` か `anime:<期>-<話>`）は**利用者**が指定する（CLI の `--context progress=…`、評価のケースの `context`）。
- コアに汎用の `user_context`（`domain.yaml`）を加えた（別のコミット）。ゲートウェイは宣言された項目を LLM に見せるスキーマから除き、
  LLM が送ってきたらサービスのスキーマに関係なく拒み、利用者の値を入力に加える。LLM は進み具合を広げられない。
- サービスは申告した媒体の注記だけで絞り込み、媒体の間で換算しない。注記の無い項目は返さない（既定拒否）。
- 見えない項目は、存在しない項目と同じ誤りにする（存在そのものを漏らさない）。
- 正体が分かる別名（`secret_aliases`）は、明かされる巻・話から先でだけ使う。事実のタグは、その文だけで分かることに限る
  （タグや別名の経由で、まだ明かされていない関係が検索に当たるのを防ぐ）。資料の規則は試験で確かめる。

### 事実の文と数値を分ける

- コアに汎用の `texts`（数値でない説明文）を加えた（別のコミット）。事実の文は `texts` で返し、出典 ID にはならない。
- 事実の文は数字を含まない（スキーマで検査）。年・年齢・日数・巻・話は `values` で返し、回答はプレースホルダで引用する（ADR-0001）。

### 資料と権利

- 資料（事実 40・人物 18・出来事 3・場所 8・道 7）は記憶をもとに書いた下書きで、すべて `verified: false`・`source: TODO…`。
  巻・話が不確かなときは**遅い方**にする（早すぎるとネタバレになる）。確信の無いことは書かない。
- 回答には `answer_note` で「未確認の下書き資料に基づく非公式のまとめ」の旨を必ず付ける。
- 原作の本文・台詞・挿絵・アニメの画像は収録しない。自分で書いた短い要約と巻・話の番号だけ。地図は自作で、日数は目安。

## 理由

- 進み具合を LLM の判断に任せると、質問や注入で広げられてネタバレになる。ゲートウェイとサービスで強制すれば、LLM がだまされても漏れない。
- 埋め込みによる検索は費用か重い環境が要り、結果を試験で固定しにくい。構造化された照会は無料で決定的、絞り込みも確実に試験できる。
- 下書きを未確認として明示すれば、誤りを事実として示さずに仕組みを先に作れる。利用者が確かめた項目から `verified: true` にする。

## 却下した案

| 案 | 却下した理由 |
|---|---|
| 進み具合をプロンプトで伝え、LLM に守らせる | 注入や言い換えで破られる。検証できない |
| 埋め込み（ベクトル）検索 | 費用か重い環境が要る。結果が決定的でなく試験しにくい |
| 小説とアニメの進み具合を換算する | 構成が違い、換算の誤りがネタバレになる |
| 事実の文に数字を含める | 回答に写すと出典の無い数値になる（ADR-0001） |

## 影響

- 新しい場所：`domains/mushoku/`、`evals/faithfulness/mushoku.yaml`、`evals/redteam/spoilers.yaml`。`config/services.yaml` に `mushoku-lore`。
- 既知の限界：LLM が自分の知識で書いた「数字を含まないネタバレ文」は構造では止められない（プロンプトで禁じるだけ）。数字を含むものは検証器が止める。
- 試験：`tests/test_mushoku_pack.py`、`tests/core/test_user_context.py`、`tests/test_golden_reference.py`（参照実装 `tests/reference/mushoku_reference.py`）。

## 追記（2026-10-04）：資料の確認

Claude が下書きした資料 79 項目（事実 40・人物 18・出来事 3・場所 8・道 7 ほか）を、作者が原作と 1 項目ずつ照合した。
35 項目はそのまま、44 項目は訂正して、すべて `verified: true` にした（出典は「小説第 X 巻」「アニメ第 X 期第 X 話」）。
訂正の多くはアニメの話数で、ネタバレの絞り込みの境目（例：フィッツの正体が分かる話）も合わせて直した。
未確認の注記は、未確認の資料を使った回答にだけ付くように直した。今後足す資料は、確認するまで `verified: false` にする。
「数字を含まないネタバレ文」を構造で止められないという既知の限界は変わらない。
