# ADR-0002：计算服务使用 Java 21 实现

- 状态：采纳
- 日期：2026-10-03

## 背景

Agent、检索和评估方面，Python 的生态更为完善。另一方面，计算服务有着不同的要求：
“不能出错”以及“要快速运行大量试验”。

## 决定

鸣潮领域的计算服务（`services/calc-engine`）用 Java 21 实现，其余部分（`core/` 等）用 Python 实现。

## 理由

1. **用类型防止错误**：用 `record` 和 `sealed interface` 建模，若 `switch` 没有穷尽所有声骸副词条种类则无法编译。精度用 `BigDecimal` 处理。
2. **性能**：蒙特卡洛方法可以用顺序、parallel stream、虚拟线程 3 种方式实现，并用 JMH 比较。
3. **MCP 与语言无关**：即使工具用 Java 编写，Agent 一侧也无需改变。可以实际展示工具与 Agent 的分离。
4. **契约测试**：在 Java 和 Python 两边对照同一组黄金用例，保证跨语言的一致性。
5. **启动速度**：作为将来的选项，使用 GraalVM Native Image 可以加快从 Fly.io 等平台的自动停止中恢复的速度。

## 否决的方案

| 方案 | 否决的理由 |
|---|---|
| 全部使用 Python | 最简单，但会失去基于类型的穷尽性保证，以及跨语言契约测试的实证 |
| 全部使用 Java（编排也用 Spring AI） | AI・评估相关的工具比 Python 少，编排部分需要重新构建 |

## 影响

- CI 分为 Java（`java.yml`）和 Python（`test.yml`）两条流水线。
- 黄金用例的格式（`tests/schemas/golden.schema.json`）成为两种语言之间的契约。
