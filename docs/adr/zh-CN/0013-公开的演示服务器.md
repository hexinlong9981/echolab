# ADR-0013：公开的演示服务器（Hugging Face Spaces・剧本 LLM・真实计算服务）

- 状态：采用
- 日期：2026-10-04

## 背景

M5 的公开网站只有静态回放，记录是 CI 用剧本模式和**测试用计算服务**生成的（[ADR-0011](0011-网页界面与公开方针.md)）。
要向面试官证明"计算服务真的在运行"，需要一台能现场运行真实计算服务（Java 的 calc-engine・OCR・无职转生・房贷）的服务器。
用户的方针仍是**零费用**。公开真实 Claude 会产生费用，这次不涉及（用户的决定：先做"A：剧本 LLM＋真实服务"）。

## 决定

| 项目 | 决定 |
|---|---|
| 托管 | **Hugging Face Spaces**（Docker・免费 CPU，不需要信用卡） |
| 运行的内容 | `python -m servers.web_api --public`。只用真实计算服务和**剧本 LLM** 运行固定的演示。始终拒绝真实 Claude（`anthropic`），不放 API 密钥 |
| 限制 | 同时 1 个、最多排队 3 个（超过返回 503），每个来源每分钟 6 次・每天 60 次（超过返回 429），每次最长 120 秒 |
| 来自浏览器 | 只对公开回放网站的 `Origin` 返回 CORS，并响应预检（OPTIONS）。来自其他 `Origin` 的 POST 返回 403 |
| 响应 | 与静态回放同样格式的记录（不含本机绝对路径）＋耗时。执行轨迹放在每次运行的临时目录中并删除 |
| 界面 | 在演示的回放下方显示「在服务器上实际运行」。网址来自构建时的 `VITE_LIVE_API`（没有则不显示按钮） |
| 发布方式 | `.github/workflows/hf-space.yml` 只把 `deploy/hf/Dockerfile` 和运行所需的目录发送到 Space（没有 Secret `HF_TOKEN`・Variable `HF_SPACE` 时跳过） |

核心不改动（公开模式只在 `servers/web_api/public.py` 中）。

## 理由

- 即使是剧本 LLM，所有计算都由真实服务完成，能现场证明"数字来自工具"（ADR-0001）在真实的 Java・OCR 上成立。
- 不放真实 Claude，即使被第三方使用也不产生费用。次数上限和同时 1 个，是为了不让免费 CPU 被占满。
- Docker 能把 Java 21・Tesseract・Python 装进一个镜像；Hugging Face Spaces 不需要信用卡就能运行 Docker。

## 否决的方案

| 方案 | 否决理由 |
|---|---|
| Cloudflare Workers | 不能启动子进程（Java・Tesseract） |
| Render 免费方案 | 内存小，同时跑 Java 和 OCR 不够稳；也会休眠 |
| Google Cloud Run・Oracle Cloud 的免费额度 | 注册需要信用卡 |
| 公开真实 Claude | 产生费用（违反用户方针）。需要时另行决定，配口令和较小的每日上限 |
| 维持只有静态回放 | 无法证明真实服务在运行 |

## 影响

- 新位置：`servers/web_api/public.py`、`deploy/hf/`、`.dockerignore`、`.github/workflows/hf-space.yml`。
- 免费 CPU 闲置会休眠，下次调用时启动（界面显示"正在唤醒服务器"）。本机 Docker 中启动约 7 秒，每个演示 2.5〜10 秒（含 JVM 启动）。
- 要公开，需要用户准备 Hugging Face 账号、Space 和写入用令牌，并登记 `HF_TOKEN`・`HF_SPACE`・`LIVE_API_URL`（`web/README.zh-CN.md`）。
- 测试：`tests/test_web_api.py`（拒绝剧本以外的运行・CORS 与预检・次数与排队上限・不输出路径）、`web/src/liveApi.test.ts`。

## 补记（2026-10-04）：托管改为 Google Cloud Run

大约从 2026 年 7 月起，在 Hugging Face 新建 Docker（以及 Gradio）的 Space 需要付费方案（只有静态 Space 免费）。
因此托管改为 **Google Cloud Run**。按用户的决定，接受登记信用卡（只用于身份验证，在免费额度内不扣费）。

| 项目 | 决定 |
|---|---|
| 托管 | Google Cloud Run（`us-central1`）。每月免费额度：vCPU 18 万秒・内存 36 万 GiB 秒・200 万次请求・从北美向外的流量 1 GB |
| 控制费用的设置 | 最少 0・最多 1 个实例，只在处理请求时用 CPU，1 vCPU・1 GiB・每次最多 120 秒。同时最多接受 4 个请求（服务器本身仍逐个运行，次数上限不变） |
| 镜像存放 | Artifact Registry（免费 0.5 GB）。镜像压缩后约 170 MB，清理策略只保留最新的一个 |
| 部署 | `.github/workflows/cloudrun.yml`，不用密钥文件，用 Workload Identity 联合（只允许 `hexinlong9981/echolab` 的 main）。首次准备用 `deploy/cloudrun/setup.sh` |
| 监控 | 1 USD 预算告警（结算账号是日元时为 150 JPY；不扣除试用额度来计算；50%・90%・100% 时发邮件） |

- 在本机加 1 GiB 限制实测：约 6 秒可以响应，每次运行 2.5〜17 秒（要启动 Java 的演示较慢），内存峰值约 310 MiB。
- 对照免费额度：一次 Java 演示约用 15 vCPU 秒，每月不超过约 1 万次就不会产生费用。每个来源每天 60 次的上限和最多 1 个实例，使它很难超过。
- 访问来源的 IP 取 `X-Forwarded-For` 的最后一项（由 Cloud Run 前端添加），前面几项用户可以伪造。
- 否决的方案（2026-10-04 调查）：Hugging Face Spaces（Docker 已改为付费）、Render 免费版（内存 512 MB 不够）、Koyeb（新用户没有免费额度）、Fly.io・Railway（没有免费额度、必须绑卡）、Oracle Cloud 永久免费（必须绑卡，闲置的虚拟机可能被回收）、Cloudflare Containers（只有付费方案）。
