# ADR-0005：数值追踪验证器的方针（派生值由工具计算）

- 状态：采纳（在 M2 中实现）
- 日期：2026-10-03

## 背景

[ADR-0001](0001-数值仅来自工具.md) 决定了“回答中的数值若不来自工具结果则退回”，但没有规定核对的规则。
实际的回答中会出现工具并未直接输出的数值。

| 类型 | 例 | 问题 |
|---|---|---|
| 写法不同 | `0.6` → 「60%」、`6192.0` → 「約 6,200」（约 6,200） | 作为字符串不一致 |
| 派生值 | 「A は B より 12% 高い」（A 比 B 高 12%）、「差は 740」（差为 740） | LLM 在自行计算（违反 ADR-0001） |
| 引用输入 | 「攻撃力 2000 の場合」（攻击力为 2000 时） | 不是工具的输出，而是用户的输入 |

## 决定

1. **派生值也由工具计算。** 差、比、增长率、排序由用于比较的确定性工具（`compare.diff`・`compare.ratio` 等，
   领域无关，放在 `core` 一侧）计算。LLM 连四则运算也不做。
2. **数值作为“带出处的值”处理。** 为工具结果中的每个数值分配 ID（`<调用ID>.<字段>`），
   回答以引用这些 ID 的形式组织。验证器检查回答中的每个数值是否属于以下之一。
   - 工具结果的值（有出处 ID）
   - 对用户输入值的引用（明确作为输入给出的值）
   - 单位・次数等非数值词语中包含的数字（如“3 种方法”，由允许列表管理）
3. **写法的规范化。** 比较之前，先对百分数 ↔ 小数、千位分隔符、全角数字进行规范化。
   舍入只在与将工具结果按显示位数舍入后的值一致时才允许（「約」（约）视为对显示位数的声明）。
4. **传播未确认数据的标记**（[ADR-0006](0006-未确认数据的处理.md)）。引用由未确认数据计算出的值的回答，必须附有相应注记。
5. 只要有 1 个数值不属于以上任何一种，就退回。超过重试上限后，降级为不含数值的回答。

## 理由

- 若让 LLM 计算派生值，ADR-0001 的保证就会出现漏洞。比较工具可以用同样的契约测试机制（黄金用例）进行验证。
- 与从自由文本中提取数值再核对相比，以引用出处 ID 的方式组织回答，误报和漏报都更少。

## 否决的方案

| 方案 | 否决的理由 |
|---|---|
| 允许 LLM 做四则运算，由验证器重新计算并核对 | 验证器需要推测算式，会变得复杂。也与“不让 AI 计算”的主张相矛盾 |
| 完全禁止派生值 | 无法回答“哪个强、强多少 %”这类典型问题 |

## 影响

- 在 M2 中添加比较工具的黄金用例（`core` 用）（`core/golden/`）。
- 在评估（自 M2 起）中加入“数值忠实度”指标。定义为“返回给用户的回答中，不含任何无出处数值的回答所占的比例”，以 1.0 作为合格条件（`core/evals/`）。

## 补充（M2 的实现）

[ADR-0008](0008-M2的结构与契约.md) 将回答改为 LLM 不写数值的模板（数值通过占位符引用出处 ID，由渲染器填入）。
因此，决定中的第 2、3 点以如下形式实现。

- 对于工具结果的值，检查占位符中的出处 ID 是否在本次提问中签发。写法与舍入由渲染器的格式（小数位数・百分数）决定，因此不需要字符串核对。
- 写法的规范化（全角数字・千位分隔符・百分数 ↔ 小数）用于将占位符以外的数字与提问中的数值进行核对。
- 重试上限为 2 次，超过后以不含数值的固定回答结束。
