# ADR-0009：房贷领域包与"核心零改动"检查

- 状态：采用
- 日期：2026-10-04

## 背景

[ADR-0003](0003-领域包结构.md) 决定用第二个领域包（房贷，M3）证明核心不依赖任何领域，
并在 CI 中检查"添加领域包的变更对核心的改动为零"。
用 M2 时的核心承载房贷领域包时，发现以下 3 点不够用。

| 项目 | M2 的核心 | 问题 |
|---|---|---|
| Python 的工具服务 | 从 PATH 中查找 `config/services.yaml` 的 `command` | PATH 中没有 `python` 的环境（只有 `python3` 的 Linux）无法启动。即使能启动，虚拟环境之外的解释器也缺少依赖（`mcp`） |
| 评估的领域 | 评估总是用 `wuwa` 领域包运行 | 无法运行房贷的评估用例 |
| 回答的注记 | 只有未确认数据的注记 | 要在回答中必定附上"不构成金融建议"，只能在提示词里请求 |

## 决定

### 先以领域无关的方式扩展核心（单独的提交）

与添加领域包的提交分开，先对核心做了以下修改（提交 `7fb32cd`）。它们都不包含房贷的概念。

- `command` 中的 `python` 用当前运行的解释器（`sys.executable`）启动。与 `java` 使用 `JAVA_HOME` 的思路相同。
- 评估用例文件在顶层用 `domain` 指定领域包（省略时为 `wuwa`）。报告中显示领域。
- `domain.yaml` 的 `answer_note`：由 Agent 确定性地附加在通过验证的回答末尾的注记。因为在验证之后附加，所以不能包含数字（由 Schema 检查）。评估中用 `expect.answer_note` 核对。
- `domain.yaml` 的 `data_dir`、`data_version` 可以省略（不带数据的领域包）。

### 领域包的结构

| 位置 | 内容 |
|---|---|
| `domains/mortgage/domain.yaml` | 3 个工具（`mortgage.equal_payment`、`mortgage.equal_principal`、`mortgage.prepayment`）与 `answer_note` |
| `domains/mortgage/calc/` | 计算（`loan.py`，`Decimal`，有效位数 34，输出为小数 6 位 ROUND_HALF_EVEN）与 MCP 服务器（`server.py`，stdio）。结果是与 calc-engine 相同的 `ToolEnvelope` JSON |
| `domains/mortgage/golden/` | 黄金用例（每个工具至少有一个手算或解析解的用例） |
| `domains/mortgage/prompts/system.md` | 工具的分工。不写数值和一般利率 |
| `config/services.yaml` | `mortgage-calc`：`python -m domains.mortgage.calc` |

- 计算服务放在领域包内部。不像 calc-engine（Java）那样做成独立服务，而是作为"只靠领域包就能完成的最小示例"。
- 用两套独立实现核对：领域包的实现（`Decimal`，逐月推进余额）与 `tests/reference/mortgage_reference.py`（`float`，用余额公式和对数求月数）。
- 计算是简单模型（固定利率、按月还款、不舍入到日元的理论值），**不构成金融建议**。回答中通过 `answer_note` 必定注明。

### "核心零改动"的检查

CI 的 `pack-isolation` 作业（`.github/scripts/check_pack_isolation.py`）在 git 历史中检查以下两点。

1. push、pull request 新增的提交中，没有任何一个同时修改 `domains/` 与 `core/`。
2. 添加各领域包 `domain.yaml` 的提交没有修改 `core/`（与核心同时创建的第一个领域包 `wuwa` 除外）。

## 理由

- "加了领域包，顺便改了一点核心"无法证明 ADR-0003 的主张（核心不依赖领域）。
  不足之处以领域无关的功能加入核心，并与添加领域包分开，使两种变更都能被检查。
- 由 Agent 附加 `answer_note`，与 ADR-0001 的思路相同（要保证的事情用结构保证）。在提示词里请求则无法检查是否遗漏。
- 用不同方法写两套实现，可以降低两者犯同一个错误（例如期间缩短型最后一期的处理）的可能性。

## 否决的方案

| 方案 | 否决理由 |
|---|---|
| 在 `config/services.yaml` 中写 `.venv/bin/python` | 虚拟环境的位置因环境而异，CI（`setup-python`）中没有 `.venv` |
| 在提示词中请求注记 | 无法验证是否遗漏，只有用真实 LLM 评估才能发现 |
| 把房贷计算加到 calc-engine（Java） | 会修改领域包之外的代码，无法证明"只加领域包即可" |
| 对历史中的所有提交应用规则 1 | M2 的提交（同时创建了 `domain.yaml` 和 `core/`）会违反。规则适用于今后的变更 |

## 影响

- 添加领域包的步骤：添加 `domains/<名称>/` 与 `config/services.yaml` 的条目、测试（`tests/`）、评估用例（`evals/faithfulness/<名称>.yaml`）。不修改 `core/`。
- 需要修改核心时，作为领域无关的单独提交（`pack-isolation` 会拦下混在一起的提交）。
- 测试：`tests/test_mortgage_pack.py`（实现与黄金用例、启动 MCP 服务器、Agent、评估）、`tests/test_golden_reference.py`（参考实现）、`tests/test_pack_isolation.py`（检查规则）。
