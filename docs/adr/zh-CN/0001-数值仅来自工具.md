# ADR-0001：回答中出现的数值只取自确定性工具的结果

- 状态：采纳
- 日期：2026-10-03

## 背景

LLM 有时会编造看似合理的数值。在养成建议中，“只要错一个数值就会失去信任”，
因此“大体正确”是不够的。

## 决定

- 伤害、评分、概率等数值，全部由计算服务（`services/calc-engine` 等）确定性地计算。
- LLM 的职责仅限于理解问题、选择工具和说明结果。
- 回答中包含的数值，由数值追踪验证器（`core/verifier`，M2）核对“来自哪个工具结果”，无法对应则退回。
- 计算结果附带明细（各乘区的值等）返回，作为回答的出处。

## 理由

- 确定性的计算可以测试、可以重现、可以进行版本管理。
- 通过在 Java 和 Python 两边对照黄金用例，也能发现实现上的错误。

## 否决的方案

| 方案 | 否决的理由 |
|---|---|
| 让 LLM 计算，并在提示词中要求准确 | 无法保证正确性，也没有发现错误的手段 |
| 让 LLM 编写代码并执行 | 每次生成的代码都不同，无法测试和版本管理 |

## 影响

- 计算服务的测试（性质测试・契约测试）成为回答正确性的基础。
- 在 M1 中，计算服务以返回带明细结果的形式为该决定做好准备。核对由 M2 的数值追踪验证器进行。
