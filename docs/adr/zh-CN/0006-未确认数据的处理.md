# ADR-0006：未确认数据可以使用，但必须在回答中明示

- 状态：采纳
- 日期：2026-10-03

## 背景

要做到“数值可以信赖”，除了公式正确之外，输入公式的数据（倍率・概率・权重）也必须正确。
目前 `domains/wuwa/data` 中的数据全部是未确认的示例（`verified: false`），也没有规定确认的流程。

## 决定

1. **以格式强制已确认的条件。** 要设为 `verified: true`，必须具备以下 3 项（由 JSON Schema 检查）。
   - `source`：出处 URL（`https://`）
   - `checked_at`：确认日期（`YYYY-MM-DD`）
   - `game_version`：所确认的游戏版本（例 `2.3`）
   `verified: false` 时，要求 `source` 以 `TODO` 开头。
2. **未确认数据也可以用于计算。** 但工具结果中要附带 `unverified_inputs`（所用未确认数据的 ID 列表），
   数值追踪验证器（[ADR-0005](0005-数值追踪验证器.md)）对引用了这些数据却没有“基于未确认数据”注记的回答予以退回。
3. **游戏版本变化时**，将数据复制到新版本的目录（`data/v<版本>/`），在重新确认之前恢复为 `verified: false`。
   通过 `domain.yaml` 的 `data_version` 声明使用哪个版本。

## 理由

- 若采用所有数据确认后才能使用的方式，演示和开发都无法进行。只要强制添加注记，用户就能判断数值的可靠程度。
- 用模式强制已确认的条件，可以防止“没有出处的 verified: true”在评审中蒙混过关。

## 否决的方案

| 方案 | 否决的理由 |
|---|---|
| 在网关拒绝未确认数据 | 目前的数据全部未确认，将什么都无法回答 |
| 只在文档中写注意事项 | 无法传达给阅读回答的用户 |

## 影响

- 在数据的模式（`domains/*/data/*/schema/`）中添加了 `checked_at`・`game_version`，并在 `verified: true` 时设为必填。
- 在 M2 中为 calc-engine 的公开层添加 `unverified_inputs`。
