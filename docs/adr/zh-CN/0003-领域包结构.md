# ADR-0003：分为领域无关的核心与领域包

- 状态：采纳
- 日期：2026-10-03

## 背景

游戏只是题材，真正想构建的是“不能把数值弄错的 AI”的机制。
需要实际证明这一机制不依赖于特定领域。

## 决定

- `core/`（编排・网关・数值验证・评估・追踪）完全不包含领域概念。
- 各领域的知识放在 `domains/<名称>/` 中，并在 `domain.yaml` 中声明工具、数据版本、黄金用例、提示词和过滤方针。
- 网关只允许 `domain.yaml` 中声明的工具（默认拒绝）。
- 用 2 个领域包进行实证：①鸣潮（数值优化・Java）、②房贷（最小示例・Python）。顺序由 [ADR-0007](0007-优先纵向切片.md) 规定。
- 领域包采用可按相同格式添加的结构，第 3 个及以后的领域包也无需改动核心即可添加。

## 理由

- 可以在 CI 中检查添加新领域时 `core/` 的差异为零（M3，以房贷领域包实施）。
- 用性质不同的 2 个领域包（Java 的数值优化与 Python 的最小示例），可以证明核心既不依赖领域，也不依赖实现语言。

## 否决的方案

| 方案 | 否决的理由 |
|---|---|
| 每个领域单独做一个应用 | 公共部分重复，无法证明可移植性 |
| 用代码注册插件 | 声明（YAML）更便于作为网关的允许列表进行检查 |

## 影响

- `domain.yaml` 的格式成为核心与领域包之间的契约。模式（`tests/schemas/domain.schema.json`）在 M1 中添加，由 `tests/test_domain_manifest.py` 检查。
