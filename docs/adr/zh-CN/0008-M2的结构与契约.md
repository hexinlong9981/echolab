# ADR-0008：M2 的结构与组件间的契约

- 状态：采纳
- 日期：2026-10-03

## 背景

M2 用 CLI 打通“提问 → 网关 → calc-engine → 数值追踪验证器 → 带出处的回答”（[ADR-0007](0007-优先纵向切片.md)）。
由于 Java 的计算服务与 Python 的核心要并行开发，需要先确定边界的形式。

## 决定

### 整体

| 组件 | 位置 | 职责 |
|---|---|---|
| 契约 | `core/contracts.py` | 组件间传递的数据的形式 |
| 网关 | `core/gateway/` | 允许列表（`domain.yaml`，默认拒绝）・输入的模式验证・调用 ID 与出处 ID 的分配・费用上限 |
| 比较工具 | `core/compare/` | 差・比・增长率（[ADR-0005](0005-数值追踪验证器.md)）。输入为出处 ID |
| 验证器・渲染器 | `core/verifier/` | 检查回答模板，并替换占位符 |
| Agent・CLI | `core/agent/` | 与 Claude 之间的工具调用往返、退回、CLI |
| 执行追踪 | `core/trace/` | 将单次提问记录到 1 个 JSONL（`.echolab/traces/<run_id>.jsonl`） |
| 评估 | `core/evals/`・`evals/` | 数值忠实度 |
| MCP 服务器 | `services/calc-engine`（`dev.echolab.app`） | Spring Boot + Spring AI 的 MCP 服务器（stdio）。只调用 `calc` 的公开 API（[ADR-0004](0004-M1不引入Spring.md)） |

### LLM 不写数值

- LLM 的最终回答是**模板**，数值必须通过占位符 `[[c1.total]]`（带格式时为 `[[c1.total|0]]`・`[[c2.ratio|%1]]`）引用。
- 替换为数值由确定性的渲染器完成。LLM 没有抄写数字的途径，因此不会出现抄错或舍入不一致。
- 验证器检查模板中占位符以外的数字（全角数字用 NFKC 规范化）是否属于对用户提问中数值的引用，或属于允许列表（列表项编号等）。
  两者都不是则退回。
- 若引用的值中有源自未确认数据的，渲染器会自动添加注记（[ADR-0006](0006-未确认数据的处理.md)）。

### 工具的名称与结果

- 领域的工具名（`damage.expected`）在 MCP・LLM 中使用将 `.` 替换为 `_` 的名称（`damage_expected`）。原因是 Claude API 的工具名中不能使用 `.`。
- 工具输入的形式与黄金用例的 `input` 相同。也接受引用数据的输入（`gacha.probability_within` 的 `banner`、`echo.score` 的 `profile`）。
- 结果是 1 个 JSON 对象：`{"tool", "values": {字段: 十进制字符串}, "unverified_inputs": [...], "data_version"}`。
- 出处 ID（`<调用 ID>.<字段>`）由网关分配。计算服务不知道 ID。

### LLM 与费用

- 模型为 Claude Opus 5.5（`claude-opus-5-5`）。中间隔着抽象层，测试与 CI 中使用按脚本返回的假 LLM。
- 费用上限为每日 1 USD・每月 10 USD（可通过配置更改）。达到上限时不调用 LLM 直接结束。
- 使用真实 LLM 的评估在本地手动执行，只提交汇总后的结果。CI 不持有 API 密钥。

## 理由

- 采用占位符方式，可以不靠提示词的指示，而是从结构上保证 ADR-0005 的“LLM 不做计算”。
- 用 JSON 与 Protocol 固定边界，就可以并行开发 Java 与 Python，并替换为假实现进行单独测试。

## 否决的方案

| 方案 | 否决的理由 |
|---|---|
| 让 LLM 直接写数值，由验证器从自由文本中提取并核对 | 写法差异・舍入・千位分隔符的判定很复杂，误报与漏报都会发生 |
| 由计算服务分配出处 ID | 在单次提问内保证唯一是网关的职责。这样可以让服务保持无状态 |

## 影响

- 黄金用例除了 Java 的单元测试・Python 的参考实现之外，还要通过经由 MCP 的端到端测试进行对照。
- `docs/architecture.md` 中 M2 的一节已按本 ADR 更新。

## 补充（实现中确定的细节）

- 执行追踪将单次提问记录到 1 个文件（`.echolab/traces/<执行 ID>.jsonl`）。
- 工具服务的连接（`core/gateway/mcp_backend.py`）对同一服务的调用逐个发送，单次响应最多等待 30 秒。
  超时作为 `ToolError` 返回给 LLM，不会中止整个提问。`java` 不在 PATH 中时，用 `JAVA_HOME/bin/java` 启动。
- 拒绝时服务器端的回退机制即使对价格表中没有的模型计费，也一定会记入台账。金额按价格表中的最高价格估算，以免上限判定过松。
- 经由 MCP 的端到端测试（`tests/e2e/`）在 CI 中构建 jar 之后执行（`test.yml` 的 `e2e` 作业）。
- 已知限制汇总在 `docs/architecture.md` 的“已知限制”中。
