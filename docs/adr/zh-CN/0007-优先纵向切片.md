# ADR-0007：在横向扩展功能之前，先打通最小的端到端

- 状态：采纳
- 日期：2026-10-03

## 背景

EchoLab 由计算服务、Agent 编排、网关、数值追踪验证器、评估、图像读取、Web UI 等
多个要素构成。核心机制是数值追踪验证器，其有效性只有在端到端打通后才能衡量。
需要决定各要素的实现顺序。

## 决定

1. **M2 采用纵向切片。** 用 CLI 打通“提问 → 网关 → calc-engine → 数值追踪验证器 → 带出处的回答”。
   数值忠实度的评估以及费用上限（每日・每月）也纳入 M2。
2. **在 M3 中添加房贷领域包。** 以较小的成本展示“无需改动核心即可添加领域”（[ADR-0003](0003-领域包结构.md)）。
3. **目录在实现时再创建。** 计划写在 `docs/architecture.md` 的路线图中。

## 理由

- 先打通端到端，可以尽早通过评估衡量验证器的有效性。之后的功能追加也可以一边观察该指标一边推进。
- 在第一个切片中就包含费用上限，可以从一开始就安全地运行使用 LLM 的部分。
- 尽早添加第 2 个领域，可以在 CI 中持续检查核心的领域无关性。
- 仓库结构与实现一致，路线图统一集中在 `docs/architecture.md` 中。

## 否决的方案

| 方案 | 否决的理由 |
|---|---|
| 按要素横向逐个做深，最后再集成 | 要到后期才能衡量验证器的有效性，设计判断的依据会延迟 |

## 影响

- `README.md`・`README.en.md`・`docs/architecture.md` 的路线图遵循这一顺序（M1〜M5）。
- 自 M2 起衡量评估（数值忠实度），在 M4 中将评估流水线纳入 CI。
