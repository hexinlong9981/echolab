# ADR-0012：无职转生领域包与防剧透

- 状态：采用
- 日期：2026-10-04

## 背景

第三个领域包是《无职转生》的设定考证（M6）。与鸣潮（数值优化）、房贷（计算示例）不同，
它的题材是"知识与时间的推理"，看点是**防剧透**。这与业务中"按用户权限过滤检索结果"（带权限的 RAG）结构相同。
用户的决定（2026-10-04）：范围包括检索・时间线・行程全部；资料覆盖小说全卷与动画，凭记忆起草并标为未确认；检索用结构化的确定性查询（不用向量）。

## 决定

### 进度由用户指定，并在检索层强制过滤

- 进度 `progress`（`novel:<卷>` 或 `anime:<季>-<集>`）由**用户**指定（CLI 的 `--context progress=…`，评估用例的 `context`）。
- 在核心加入了通用的 `user_context`（`domain.yaml`，单独提交）。网关把声明的项目从给 LLM 看的 Schema 中去掉；
  LLM 送来时不论服务的 Schema 如何都拒绝；并把用户的值加进输入。LLM 无法扩大进度。
- 服务只按声明媒体的标注过滤，媒体之间不换算。没有标注的条目一律不返回（默认拒绝）。
- 看不到的条目与不存在的条目返回同样的错误（不泄露"存在"本身）。
- 会暴露身份的别名（`secret_aliases`）只在揭晓的卷・集之后才使用。事实的标签只限于该句本身能看出的内容
  （防止经由标签或别名检索到尚未揭晓的关系）。这些资料规则由测试检查。

### 把事实的句子与数值分开

- 在核心加入了通用的 `texts`（不是数值的说明文字，单独提交）。事实的句子用 `texts` 返回，不成为出处 ID。
- 事实的句子不含数字（由 Schema 检查）。年份・年龄・天数・卷・集用 `values` 返回，回答用占位符引用（ADR-0001）。

### 资料与权利

- 资料（事实 40・人物 18・事件 3・地点 8・道路 7）是凭记忆写的草稿，全部 `verified: false`・`source: TODO…`。
  卷・集不确定时取**较后**的一方（太早会剧透）。没把握的内容不写。
- 回答必定通过 `answer_note` 注明"基于未确认草稿资料的非官方整理"。
- 不收录原作正文・台词・插图・动画画面，只收录自己写的简短摘要与卷・集编号。地图是自制的，天数是估计。

## 理由

- 把进度交给 LLM 判断，会被提问或注入扩大而导致剧透。在网关和服务中强制执行，即使 LLM 被骗也不会泄露。
- 向量检索需要费用或沉重的环境，结果也难以用测试固定。结构化查询免费且确定，过滤也能可靠地测试。
- 把草稿明确标为未确认，就能先搭好机制而不把错误当作事实。用户核对过的条目再改为 `verified: true`。

## 否决的方案

| 方案 | 否决理由 |
|---|---|
| 在提示词中告知进度，让 LLM 遵守 | 会被注入或换个说法突破，无法验证 |
| 向量检索 | 需要费用或沉重的环境；结果不确定，难以测试 |
| 小说与动画的进度互相换算 | 结构不同，换算错误就会变成剧透 |
| 事实的句子里含数字 | 抄进回答就成了没有出处的数值（ADR-0001） |

## 影响

- 新位置：`domains/mushoku/`、`evals/faithfulness/mushoku.yaml`、`evals/redteam/spoilers.yaml`；`config/services.yaml` 中的 `mushoku-lore`。
- 已知限制：LLM 凭自己的知识写出的"不含数字的剧透句子"无法从结构上拦住（只靠提示词禁止）。含数字的会被验证器拦住。
- 测试：`tests/test_mushoku_pack.py`、`tests/core/test_user_context.py`、`tests/test_golden_reference.py`（参考实现 `tests/reference/mushoku_reference.py`）。
