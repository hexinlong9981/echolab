# ADR-0002: 計算サービスは Java 21 で実装する

- 状態: 採用
- 日付: 2026-10-03

## 背景

エージェント・検索・評価は Python のエコシステムが充実しています。一方、計算サービスには
「間違えられない」「大量の試行を速く回す」という別の要求があります。

## 決定

鳴潮ドメインの計算サービス（`services/calc-engine`）は Java 21 で実装し、それ以外（`core/` など）は Python で実装します。

## 理由

1. **型で誤りを防ぐ**：`record` と `sealed interface` でモデル化し、詞条の種類を `switch` で網羅しないとコンパイルできないようにする。精度は `BigDecimal` で扱う。
2. **性能**：モンテカルロ法を、逐次・parallel stream・仮想スレッドの 3 方式で実装し、JMH で比較できる。
3. **MCP は言語に依存しない**：ツールを Java にしても、エージェント側は変わらない。ツールとエージェントの分離を実際に示せる。
4. **契約テスト**：同じゴールデンケースを Java と Python の両方で照合し、言語をまたいだ一致を保証する。
5. **起動の速さ**：将来の選択肢として GraalVM Native Image を使えば、Fly.io などの自動停止からの復帰を速くできる。

## 却下した案

| 案 | 却下した理由 |
|---|---|
| すべて Python | 最も簡単だが、型による網羅性の保証と、言語をまたいだ契約テストの実証を失う |
| すべて Java（Spring AI で編成も） | AI・評価の道具が Python より少なく、編成部分を作り直すことになる |

## 影響

- CI は Java（`java.yml`）と Python（`test.yml`）の 2 系統になります。
- ゴールデンケースの形式（`tests/schemas/golden.schema.json`）が、両言語の間の契約になります。
