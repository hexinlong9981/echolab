# ADR-0004: M1 では Spring を導入せず、純粋な Java ライブラリとして作る

- 状態: 採用
- 日付: 2026-10-03

## 背景

計算サービスは最終的に MCP サーバ（Spring Boot + Spring AI の MCP Server）として公開します。
ただし M1 の目的は「計算が正しいこと」を固めることです。

## 決定

M1 の `calc-engine` は Spring に依存しない純粋なライブラリとして作り、MCP として公開する層は M2 で別に足します。

## 理由

1. **関心の分離**：計算ロジックをフレームワークから切り離すと、テストが速く単純になります（M1 の全テストが Spring のコンテキスト起動なしで動く）。
2. **依存の少なさ**：M1 の本番依存は YAML の読み込み（Jackson）だけで、ビルドと静的解析（Error Prone・`-Werror`）を厳しくしても維持しやすい。
3. **差し替えやすさ**：公開層を後から足す形にすると、MCP の SDK・Spring の版が変わっても計算ロジックに影響しません。
4. **Native Image**：フレームワークに依存しない部分が大きいほど、GraalVM Native Image で問題が出にくくなります。

## 却下した案

| 案 | 却下した理由 |
|---|---|
| 最初から Spring Boot アプリとして作る | M1 では使わない依存と設定が増え、計算の正しさに集中しにくい |

## 影響

- M2 で `app` 層（Spring Boot・MCP ツール定義）を追加し、`calc` の公開 API を呼ぶだけにします。
- ArchUnit で「計算パッケージがフレームワークに依存しない」規則を M2 で追加します。
