# ADR-0001: 回答に出る数値は、決定的なツールの結果からのみ取る

- 状態: 採用
- 日付: 2026-10-03

## 背景

LLM はもっともらしい数値を作り出すことがあります。育成の助言では「数値が 1 つ間違うだけで信頼を失う」ため、
「たいてい合っている」では足りません。

## 決定

- ダメージ・スコア・確率などの数値は、すべて計算サービス（`services/calc-engine` など）で決定的に計算します。
- LLM の役割は、質問の理解・ツールの選択・結果の説明に限ります。
- 回答に含まれる数値は、数値トレース検証器（`core/verifier`、M2）が「どのツール結果に由来するか」を照合し、対応しなければ差し戻します。
- 計算結果は明細（乗区ごとの値など）付きで返し、回答の出典にします。

## 理由

- 決定的な計算はテストでき、再現でき、版管理できます。
- ゴールデンケースを Java と Python の両方で照合することで、実装の誤りも検出できます。

## 却下した案

| 案 | 却下した理由 |
|---|---|
| LLM に計算させ、プロンプトで正確さを求める | 正しさを保証できない。誤りを検出する手段がない |
| LLM にコードを書かせて実行する | 毎回違うコードになり、テスト・版管理ができない |

## 影響

- 計算サービスのテスト（性質テスト・契約テスト）が、回答の正しさの土台になります。
- M1 では、計算サービスが明細付きの結果を返す形でこの決定に備えています。照合は M2 の数値トレース検証器で行います。
