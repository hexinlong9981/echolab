# ADR-0006: 未確認データは使ってよいが、回答で必ず明示する

- 状態: 採用
- 日付: 2026-10-03

## 背景

「数値を信頼できる」ためには、式が正しいことに加えて、式に与えるデータ（倍率・確率・重み）が正しいことが必要になる。
現在の `domains/wuwa/data` はすべて未確認のサンプル（`verified: false`）で、確認の手順も決めていなかった。

## 決定

1. **確認済みの条件を形式で強制する。** `verified: true` にするには、次の 3 つを必須とする（JSON Schema で検査）。
   - `source`: 出典の URL（`https://`）
   - `checked_at`: 確認した日付（`YYYY-MM-DD`）
   - `game_version`: 確認したゲームの版（例 `2.3`）
   `verified: false` のときは、`source` が `TODO` で始まることを要求する。
2. **未確認データも計算に使ってよい。** ただし、ツールの結果に `unverified_inputs`（使った未確認データの ID の一覧）を付け、
   数値トレース検証器（ADR-0005）は、これを引用する回答に「未確認のデータに基づく」旨の注記がなければ差し戻す。
3. **ゲームの版が変わったら**、データは新しい版のディレクトリ（`data/v<版>/`）に複製し、確認し直すまで `verified: false` に戻す。
   `domain.yaml` の `data_version` で、どの版を使うかを宣言する。

## 理由

- すべてのデータを確認してから使う方式では、デモも開発もできない。注記を必須にすれば、利用者は数値の確かさを判断できる。
- 確認済みの条件をスキーマで強制すれば、「出典なしの verified: true」がレビューをすり抜けない。

## 却下した案

| 案 | 却下した理由 |
|---|---|
| 未確認データはゲートウェイで拒否する | 現時点のデータがすべて未確認のため、何も答えられない |
| 文書に注意書きを書くだけにする | 回答を読む利用者には伝わらない |

## 影響

- データのスキーマ（`domains/*/data/*/schema/`）に `checked_at`・`game_version` を追加し、`verified: true` のときに必須とした。
- M2 で calc-engine の公開層に `unverified_inputs` を追加する。
