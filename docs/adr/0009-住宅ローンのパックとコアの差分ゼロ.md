# ADR-0009: 住宅ローンのパックと「コアの差分ゼロ」の検査

- 状態: 採用
- 日付: 2026-10-04

## 背景

[ADR-0003](0003-ドメインパック構成.md) は、コアがドメインに依存しないことを 2 つ目のパック（住宅ローン、M3）で示し、
「パックを足す変更でコアの差分がゼロ」であることを CI で検査すると決めた。
M2 の時点のコアを住宅ローンのパックで使おうとすると、次の 3 点がそのままでは足りなかった。

| 点 | M2 のコア | 困ること |
|---|---|---|
| Python のツールサービス | `config/services.yaml` の `command` を PATH から探す | PATH に `python` が無い環境（`python3` だけの Linux）で起動できない。起動できても仮想環境の外のインタプリタだと依存（`mcp`）が無い |
| 評価のドメイン | 評価は常に `wuwa` のパックで実行する | 住宅ローンの評価ケースを実行できない |
| 回答の注記 | 未確認データの注記だけ | 「金融上の助言ではない」旨を回答に必ず付ける手段が、プロンプトでのお願いしか無い |

## 決定

### コアを先に、ドメインに依存しない形で広げる（別のコミット）

パックを足すコミットとは別に、次の変更をコアに入れた（コミット `7fb32cd`）。どれも住宅ローンの概念を持たない。

- `command` の `python` は、いま動いているインタプリタ（`sys.executable`）で起動する。`java` の `JAVA_HOME` と同じ考え方。
- 評価のケースのファイルは、最上位の `domain` でパックを指定する（省略時 `wuwa`）。レポートにドメインを表示する。
- `domain.yaml` の `answer_note`：検証に通った回答の末尾に、Agent が決定的に付ける注記。検証の後に付けるので、数字を含めない（スキーマで検査）。評価では `expect.answer_note` で照合する。
- `domain.yaml` の `data_dir`・`data_version` を省略できる（データを持たないパック）。

### パックの構成

| 場所 | 内容 |
|---|---|
| `domains/mortgage/domain.yaml` | ツール 3 つ（`mortgage.equal_payment`・`mortgage.equal_principal`・`mortgage.prepayment`）、`answer_note` |
| `domains/mortgage/calc/` | 計算（`loan.py`、`Decimal`・有効桁 34・出力は小数 6 桁 ROUND_HALF_EVEN）と MCP サーバ（`server.py`、stdio）。結果は calc-engine と同じ `ToolEnvelope` の JSON |
| `domains/mortgage/golden/` | ゴールデンケース（各ツールに手計算か閉形式のケースを 1 つ以上） |
| `domains/mortgage/prompts/system.md` | ツールの使い分け。数値・一般的な金利は書かない |
| `config/services.yaml` | `mortgage-calc`：`python -m domains.mortgage.calc` |

- 計算サービスはパックの中に置く。calc-engine（Java）のような独立したサービスにせず、「パックだけで完結する最小例」にする。
- 照合は 2 つの独立した実装で行う：パックの実装（`Decimal`、残高を 1 回ずつ進める）と、`tests/reference/mortgage_reference.py`（`float`、残高の公式と対数で回数を求める）。
- 計算は単純なモデル（固定金利・毎月払い・円未満を丸めない理論値）で、**金融上の助言ではない**。回答には `answer_note` で必ずその旨を付ける。

### 「コアの差分ゼロ」の検査

CI の `pack-isolation` ジョブ（`.github/scripts/check_pack_isolation.py`）が git の履歴で次の 2 つを検査する。

1. push・pull request で増えたコミットのどれも、`domains/` と `core/` を同時に変えていない。
2. 各パックの `domain.yaml` を追加したコミットが `core/` を変えていない（コアと同時に作った最初のパック `wuwa` を除く）。

## 理由

- 「パックを足したらコアも少し直した」では、ADR-0003 の主張（コアはドメインに依存しない）を示せない。
  足りない点は、ドメインに依存しない機能としてコアに足し、パックの追加とは分けることで、どちらの変更も検査できる形にした。
- `answer_note` を Agent が付けるのは、ADR-0001 と同じ考え方（守らせたいことは構造で保証する）による。プロンプトで頼むと、付け忘れを検査できない。
- 2 つの実装を別の方法で書くと、同じ誤り（例：期間短縮型の最後の回の扱い）を両方が持つ可能性が下がる。

## 却下した案

| 案 | 却下した理由 |
|---|---|
| `config/services.yaml` に `.venv/bin/python` を書く | 仮想環境の場所は環境ごとに違い、CI（`setup-python`）には `.venv` が無い |
| 注記をプロンプトで頼む | 付け忘れを検証できない。実物の LLM の評価でしか分からない |
| 住宅ローンの計算を calc-engine（Java）に足す | パックの外を変えることになり、「パックだけで足せる」ことを示せない |
| 履歴の全コミットに規則 1 を当てる | M2 のコミット（`domain.yaml` と `core/` を同時に作った）が違反になる。規則は以後の変更に当てる |

## 影響

- パックを足す手順：`domains/<名前>/` と `config/services.yaml` の追加、試験（`tests/`）、評価のケース（`evals/faithfulness/<名前>.yaml`）。`core/` は変えない。
- コアを変える必要があるときは、ドメインに依存しない別のコミットにする（`pack-isolation` が混在を止める）。
- 試験：`tests/test_mortgage_pack.py`（実装とゴールデンケース、MCP サーバの起動、Agent、評価）、`tests/test_golden_reference.py`（参照実装）、`tests/test_pack_isolation.py`（検査の規則）。
