# ADR-0011: Web UI と公開の方針（費用ゼロ）

- 状態: 採用
- 日付: 2026-10-04

## 背景

M5 では、対話・実行トレースの回放・評価のダッシュボード・デモの公開を行う（[ADR-0007](0007-縦の切片を優先する.md)）。
回答には LLM（有料）・Java の計算サービス・OCR が要るので、「誰でもその場で質問できる」公開デモにするには、常に動くサーバと API の費用が要る。
利用者の方針は**費用を最優先し、できれば完全に無料**にすること。

## 決定

利用者の判断（2026-10-04）に基づく。

| 項目 | 決定 |
|---|---|
| 公開するもの | **静的な回放と評価のダッシュボードだけ**。サーバも LLM も動かさない |
| 実時間の画面 | **手元だけ**（`python -m servers.web_api`、`127.0.0.1`）。面接では画面共有で使う。実物の Claude はコアのコストの上限に従う |
| 置き場所 | **Cloudflare Pages**（無料プラン） |
| 画面の技術 | **React + TypeScript + Vite**、流れの図は React Flow |
| 公開の方法 | **GitHub Actions** で、データの書き出し・型検査・試験・ビルドが通ったら wrangler で公開。Secrets（`CLOUDFLARE_API_TOKEN`・`CLOUDFLARE_ACCOUNT_ID`）が無ければ公開だけ飛ばす |

- 回放のデータは CI が台本モード（API キー不要・試験用の計算サービス）で書き出す（`python -m servers.web_api.export`）。何度実行しても同じ内容で、手元の絶対パスは含めない。画面にも「台本モードの記録」と明示する。
- 手元の API は Python の標準ライブラリだけで作る（依存を増やさない）。ほかのサイトのページから呼ばれて費用を使われないよう、`Content-Type: application/json` を必須にし、`Origin` を確かめる。台本は決まったデモのものしか使えない。
- 画面の文言は日本語（CLI・評価と同じ）。

## 理由

- 公開デモに実物の LLM を置くと、費用の上限を設けても、第三者の利用で上限に達してデモ自体が止まる。静的な回放なら費用もリスクもない。
- このプロジェクトの見せどころ（出典の表・差し戻し・拒否）は、回放で 1 コマずつ見せる方が、実時間の回答より伝わる。
- 手元の画面があれば、面接で「その場で別の質問」に応えられる（API キーがあるとき）。
- CI でビルドしてから公開すると、公開されるデータが常にそのコミットの試験・評価と一致する。

## 却下した案

| 案 | 却下した理由 |
|---|---|
| 公開の実時間デモ（サーバ＋実物の Claude） | サーバと API の費用、第三者による費用の消費。常に無料で動くホスティングも無い |
| 公開の実時間デモ（サーバ＋台本の LLM） | 台本は質問を読まないので、自由な質問には答えられない。静的な回放と見せられるものが同じなのに、サーバが要る |
| GitHub Pages | 無料で既に使っているが、利用者の判断で当初の計画どおり Cloudflare Pages にした |
| Cloudflare 側でビルドする（リポジトリ連携） | データの書き出しに Python が要り、試験の前に公開されうる |
| 手元の API に FastAPI を使う | 依存が増える。機能は標準ライブラリで足りる |

## 影響

- 新しい場所：`web/`、`servers/web_api/`、`.github/workflows/web.yml`。
- 公開には、利用者が Cloudflare のアカウントを作り、2 つの Secrets を登録する必要がある（手順は `web/README.md`）。
- 公開の回放は台本モードの記録だけ。実物の LLM の記録を公開するかは、実物の評価を実施したときに改めて決める。
- 試験：`tests/test_web_api.py`（書き出し・API の検査）、`web/src/replay.test.ts`（回放のコマの組み立て、Vitest）。
