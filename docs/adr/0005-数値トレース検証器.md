# ADR-0005: 数値トレース検証器の方針（派生値はツールで計算する）

- 状態: 採用（実装は M2）
- 日付: 2026-10-03

## 背景

ADR-0001 は「回答中の数値はツール結果に由来しなければ差し戻す」と決めたが、照合の規則を決めていなかった。
実際の回答には、ツールが直接出していない数値が現れる。

| 種類 | 例 | 問題 |
|---|---|---|
| 表記の違い | `0.6` → 「60%」、`6192.0` → 「約 6,200」 | 文字列としては一致しない |
| 派生値 | 「A は B より 12% 高い」「差は 740」 | LLM が自分で計算している（ADR-0001 違反） |
| 入力の引用 | 「攻撃力 2000 の場合」 | ツールの出力ではなく、利用者の入力 |

## 決定

1. **派生値もツールで計算する。** 差・比・増加率・順位付けは、比較用の決定的なツール（`compare.diff`・`compare.ratio` など、
   ドメイン非依存で `core` 側に置く）で計算する。LLM は四則演算も行わない。
2. **数値は「出典つきの値」として扱う。** ツール結果の各数値に ID（`<呼び出しID>.<フィールド>`）を振り、
   回答はその ID を引用する形で組み立てる。検証器は、回答中の各数値が次のどれかに当たるかを検査する。
   - ツール結果の値（出典 ID あり）
   - 利用者の入力値の引用（入力として明示されたもの）
   - 単位・回数などの数値でない語に含まれる数字（「3 つの方法」など、許可リストで管理）
3. **表記の正規化。** 比較の前に、パーセント ↔ 小数、桁区切り、全角数字を正規化する。
   丸めは、ツール結果を表示桁数に丸めた値と一致する場合だけ許す（「約」は表示桁数の宣言とみなす）。
4. **未確認データの印を伝搬する**（ADR-0006）。未確認データから計算された値を引用する回答には、その旨の注記を必須にする。
5. どれにも当たらない数値が 1 つでもあれば差し戻す。再試行の上限を超えたら、数値を含まない回答に落とす。

## 理由

- 派生値を LLM に計算させると、ADR-0001 の保証に穴が空く。比較ツールなら同じ契約テストの仕組み（ゴールデンケース）で検証できる。
- 自由文から数値を抽出して照合するより、出典 ID の引用で組み立てる方が、誤検出・見逃しの両方が少ない。

## 却下した案

| 案 | 却下した理由 |
|---|---|
| LLM の四則演算を許し、検証器が再計算して照合する | 検証器が式を推測する必要があり複雑になる。「AI に計算させない」という主張とも矛盾する |
| 派生値を一切禁止する | 「どちらが何 % 強いか」という代表的な質問に答えられない |

## 影響

- M2 で比較ツールのゴールデンケース（`core` 用）を追加する。
- 評価（M2 から）に「数値の忠実度」（出典のない数値を含む回答の割合）を指標として入れる。
