# ADR-0003: ドメイン非依存のコアと、ドメインパックに分ける

- 状態: 採用
- 日付: 2026-10-03

## 背景

ゲームは題材であり、本当に作りたいのは「数値を間違えられない AI」の仕組みです。
仕組みが特定のドメインに依存していないことを、実際に示す必要があります。

## 決定

- `core/`（編成・ゲートウェイ・数値検証・評価・トレース）は、ドメインの概念を一切持ちません。
- ドメインごとの知識は `domains/<名前>/` に置き、`domain.yaml` でツール・データ版・ゴールデンケース・プロンプト・フィルタ方針を宣言します。
- ゲートウェイは `domain.yaml` に宣言されたツールだけを許可します（既定拒否）。
- 2 つのパックで実証します：①鳴潮（数値最適化・Java）、②住宅ローン（最小例・Python）。順序は [ADR-0007](0007-縦の切片を優先する.md) で定めます。
- パックは同じ形式で追加できる構成とし、3 つ目以降のパックもコアを変えずに足せます。

## 理由

- 新しいドメインを足しても `core/` の差分がゼロであることを、CI で検査できます（M3、住宅ローンのパックで実施）。
- 性質の異なる 2 つのパック（Java の数値最適化と Python の最小例）で、コアがドメインと実装言語の両方に依存しないことを示せます。

## 却下した案

| 案 | 却下した理由 |
|---|---|
| ドメインごとに別アプリを作る | 共通部分が重複し、移植性を示せない |
| プラグインをコードで登録する | 宣言（YAML）の方が、ゲートウェイの許可リストとして検査しやすい |

## 影響

- `domain.yaml` の形式はコアとパックの間の契約になります。スキーマ（`tests/schemas/domain.schema.json`）は M1 で追加し、`tests/test_domain_manifest.py` で検査しています。
